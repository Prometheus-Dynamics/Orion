# Changelog

All notable changes to this workspace should be documented in this file.

The format is based on Keep a Changelog and this project follows Semantic Versioning.

## [1.0.0] - 2026-04-19

- Standardized the workspace layout, docs, CI, linting, and helper scripts.
- Added repo-level testing guidance for default, Docker, perf, and soak validation surfaces.
- Added `scripts/check-file-sizes.sh`, `scripts/ci.sh`, and `scripts/repo-clean.sh`.
- Preserved the richer Orion-specific operational and performance workflow split.

### Added

- `orion-link` crate: `no_std`, allocation-free, panic-free framing for the MCU link protocol (`docs/link-protocol.md`). CRC-32C message frames (`[version][kind][seq u16 LE][payload][crc32c LE]`, `LINK_PROTOCOL_VERSION = 1`), COBS byte-stream encoding with a byte-at-a-time `StreamEncoder` and a resynchronizing `StreamDecoder<N>` with drop counters, and classic CAN / CAN FD segmentation (`Segmenter`, `Reassembler<N>`, `CanLinkIds`) with unpadded, valid CAN FD segment lengths. Optional `embedded-io`, `embedded-io-async`, and `embedded-can` adapters, and a `crc-table` feature. CI builds it for `thumbv7em-none-eabihf`, `thumbv8m.main-none-eabihf`, and `riscv32imac-unknown-none-elf`.
- `orion-link` link messages and sessions. The `alloc` feature (still `no_std`) adds postcard-encoded messages (`Hello`, `Welcome`, `Reject`, `ProviderState`, `Ack`, `Leases`, `Ping`/`Pong`; stable kind numbers with `ExecutorState`, `Workloads`, and `Status` reserved; unknown kinds ignored) and the sans-IO `DeviceSession<T, RX, TX>` over COBS streams or CAN / CAN FD with fixed const-generic buffers: `Hello` backoff, reject backoff, negotiated frame size, newest-snapshot provider publishing retransmitted until acked and re-sent on every reconnect, heartbeat pings, host-loss detection, duplicate suppression, and lease events. The `std` feature adds the sans-IO `HostSession` and the multi-device CAN `HostBus` for the upcoming node gateway (device allowlist, acks, lease piggybacking on every `Pong`, device-loss detection). A wire fingerprint fixture (`crates/link/tests/link_encoding.rs`) forces a `LINK_PROTOCOL_VERSION` bump on wire changes. `docs/link-protocol.md` now pins kind numbers, reject codes, the session lifecycle, and the retransmission and duplicate rules.
- `crates/link/examples/sim_device.rs` (simulated device and host over an in-memory serial line) and `examples/mcu-template`, a standalone chip-agnostic `no_std` firmware template (`embedded-io` UART and `embedded-can` ports, a replaceable first-fit heap, C entry points) built by CI for `thumbv7em-none-eabihf` and `riscv32imac-unknown-none-elf`. `scripts/mcu-size.sh` reports its linked footprint (about 26 KB flash and 1.2 KB RAM plus heap on Cortex-M4F).
- `link-gateway` cargo feature for `orion-node` (opt-in, Linux, also in the IPC-only build): serves the serial and SocketCAN links listed in `ORION_NODE_LINKS` (`serial:<path>?baud=...`, `can:<if>?device_base=...&host_base=...&addresses=A-B&fd=...&extended=...`, plus `allow`, `heartbeat_ms`, `missed_heartbeats`, `max_frame`) with termios and `PF_CAN` raw sockets over `libc` and tokio `AsyncFd`, and bridges every device into the node through the local IPC provider path: gateway-owned `node_id`; provider and resource ownership checks against IPC clients, other devices, and other nodes; lease sets refreshed on every desired-state commit; resources marked unavailable on device loss and restored on reconnect; devices marked lost on shutdown. `NodeApp::link_status()` reports per-link counters; the control protocol is unchanged. `ORION_NODE_LINKS` fails startup in builds without the feature. `crates/node/examples/link_device_sim.rs` simulates a device on a pseudo-terminal for trying it without hardware.
- `ORION_NODE_HTTP_ADDR=off` runs `orion-node` without the HTTP control listener for IPC-only appliances.
- `transport-http` cargo feature for `orion-node`, enabled by default. `cargo build -p orion-node --no-default-features` builds an IPC-only node without axum, hyper, reqwest, or rustls. In that build, `ORION_NODE_PEERS`, HTTP TLS settings, `ORION_NODE_HTTP_PROBE_ADDR`, and an `ORION_NODE_HTTP_ADDR` socket address fail startup with an error that names the missing feature.
- `orion-transport-http` gains a default `transport` feature. Without it, the crate exposes only the protocol layer: payloads, routes, codec, errors, and handler traits. `orion-transport-common` gates its rustls helpers behind a default `tls` feature.
- `ORION_NODE_RUNTIME_WORKER_THREADS` and `ORION_NODE_RUNTIME_MAX_BLOCKING_THREADS` size the node's Tokio runtime.
- Single-node appliance profile guidance in `docs/node-env.md`, and an `appliance_memory_soak` suite that checks memory slope and caps under provider/executor/mutation load.
- Opt-in `alloc-jemalloc` and `alloc-mimalloc` features that set the `orion-node` binary's global allocator (jemalloc wins if both are on), with allocator soak measurements in `docs/node-env.md`. The soak gains `ORION_SOAK_NODE_WORKER_THREADS` and `ORION_SOAK_NODE_BIN`.
- `ResourceEndpoint::Custom` accepts any valid URI scheme (for example `styx-frame-lease+unix://`), with `CustomEndpointScheme` for typed downstream endpoints and `Display`/`FromStr` round-tripping.
- `UnixFdLatestServer` / `UnixFdLatestClient` in `orion-transport-ipc`: a bounded latest-value channel that hands out dup'd fds (for example dmabuf frame leases) with sequence waits, max age, and max clients.
- `resource_usage` section in node observability snapshots (process RSS/PSS, state record counts, mutation history vs caps, local stream backlog, worker queue depth, registry sizes), `orionctl get memory`, and matching Prometheus families.
- `no_std` + `alloc` support for `orion-core`, `orion-data-plane`, `orion-control-plane`, `orion-auth`, `orion-runtime`, and `orion-cluster` (and the `orion` facade's model features) for microcontroller targets. Each crate has a default `std` feature; only the Prometheus metrics export and the shared-memory/unix endpoint filesystem helpers require it. Workspace dependencies on these crates and on serde, serde_json, thiserror, rkyv, and ed25519-dalek now use `default-features = false`, with std crates enabling `std` explicitly. rkyv is raised to 0.8.16 (first release that compiles `pointer_width_64` on 32-bit targets); the archived layout and `CONTROL_PROTOCOL_VERSION` are unchanged, which a new canonical-encoding fixture test checks in both std and no_std builds. CI gains a `no-std` job running `scripts/check-no-std.sh`.
- `orion_client::prelude` plus consumer views: `AssignedWorkload`, `BoundResource`, `assigned_workloads`, `resources_bound_to`, and `LocalExecutorService::watch_assigned_workloads`.
- `peer-tcp` cargo feature for `orion-node` (on by default, and usable with `--no-default-features`): peer sync with `orion+tcp://host:port` peers over plain TCP, listener `ORION_NODE_PEER_ADDR`. Frames reuse the control preamble (`[b"OC"][version][len]`), requests are the HTTP codec's signed peer requests, and responses are ed25519-signed by the responder and bound to the request they answer; no TLS (authenticity, integrity and replay protection, not confidentiality; see the threat model in `docs/peer-sync.md`). HTTP and TCP peers can be mixed. `--no-default-features --features peer-tcp` gives an IPC-only appliance build that clusters without axum, hyper, reqwest, or rustls.
- Per-object conflict resolution for desired state with a hybrid logical clock (`orion_core::HlcTimestamp`, `HybridLogicalClock`, `hlc_node_tag`; `no_std`). Every desired object carries the stamp of its last write (`DesiredClusterState::stamps`) and every delete a tombstone (`DesiredClusterState::tombstones`, all sections); peers merge per object, last writer wins (`DesiredClusterState::apply_stamped`), deterministically and independent of delivery order. Remote stamps more than `ORION_NODE_HLC_MAX_DRIFT_MS` (default 5 min) ahead are rejected and counted; tombstones are collected after `ORION_NODE_TOMBSTONE_RETENTION_MS` (default 7 days). New `desired_merge` observability section and `orion_node_desired_merge_*` / `orion_node_hlc_*` metrics.
- Each node pushes its own observed slice (node record, assigned workloads, resources and leases of its providers and executors) to its peers at the end of a sync round when it changed (at least every 30 s); receivers replace only that origin's slice.
- `docs/peer-sync.md`: merge behaviour before and after this release, sync protocol, transports, threat model, tombstones, upgrade and migration, and hooks for placement, cross-node binding and discovery.

### Changed

- The node reconcile loop is event-driven: it wakes (coalesced for up to 5ms) on desired-state commits, observed-state merges, provider/executor state published over IPC, maintenance changes, and integration registration, plus a periodic backstop (`ORION_NODE_RECONCILE_BACKSTOP_MS`, default 5000). `ORION_NODE_RECONCILE_MS` is now the minimum idle gap between passes. With the loop running, IPC provider/executor updates and applied mutations defer their reconcile to it.
- Successful reconcile passes log at `debug` and only record a recent observability event when they changed something; reconcile counters and latency still cover every pass.
- `ResourceEndpoint` and `ResourceEndpointError` are now `#[non_exhaustive]`; unknown but valid schemes parse as `Custom` instead of failing with `UnsupportedScheme`.
- Snapshot additions change the rkyv control-protocol layout, so `orionctl` and `orion-node` must be upgraded together.
- Explicit control-protocol versioning: `orion_core::CONTROL_PROTOCOL_VERSION` (now 2, for the `resource_usage` layout) is carried in a fixed 4-byte preamble on every local IPC message (unary and stream frames, including the `ClientHello`/`ClientWelcome` handshake) and in the `x-orion-control-protocol` HTTP header, and checked before any rkyv payload is decoded. Version skew now fails with `IpcTransportError`/`HttpTransportError`/`ClientError::ProtocolMismatch { local, remote }` telling operators to upgrade orionctl and orion-node together, instead of opaque rkyv decode errors. A layout fingerprint test (`crates/orion/tests/control_protocol_layout.rs`) forces a version bump on future layout changes. See `docs/protocol-compatibility.md`.
- CI workflows install the pinned 1.94.0 toolchain (matching `rust-toolchain.toml`) instead of `stable`.
- Peer sync is transport-independent (`PeerSyncTransport`) and bidirectional: one round exchanges `Hello`, compares per-object versions of the differing sections (`SyncSummaryRequest`), pushes the local winners and pulls the peer's (`SyncDiffRequest`). Before, the node with the higher revision counter overwrote whole sections of the other, equal-revision conflicts were merged by "bytewise max" of the rkyv encodings, and deletes other than workload deletes did not survive a merge. A pushed `Snapshot` is now merged per object instead of adopted wholesale, and mutation history is no longer shipped to peers. The cached "skip hello" fast paths are gone; a converged round is one `Hello`.
- `Revision` is a node-local commit sequence number; converged peers usually have different revisions and are compared by desired-state fingerprint (which now covers stamps and tombstones). `MutationBatch` gains `stamps`; unstamped batches (from `orionctl` and clients) are stamped by the node on commit. `DesiredClusterState::workload_tombstones` and `DesiredStateSummary::workload_tombstones` are replaced by `stamps`/`tombstones`, and `StateSectionCounts::workload_tombstones` (metric kind `workload_tombstones`) by `tombstones`.
- `CONTROL_PROTOCOL_VERSION` is 3 (new layout fingerprint and canonical encoding fixture). The snapshot format goes from 3 to 4: existing state directories are migrated on first start (old files kept in `legacy-format-3/`, observed state rebuilt from live reports); a directory that cannot be migrated fails startup without being overwritten.
- `ControlSurface::PeerTcp` and `ControlSource::PeerTcp` for requests from `orion+tcp` peers; peer authentication and authorization treat both peer surfaces alike (`ControlSurface::is_peer`).
- A peer's `ObservedUpdate` no longer overwrites the receiver's observed revision or applied revision.

### Fixed

- `send_unix_fd_frame_async` / `recv_unix_fd_frame_async` no longer spin at 100% CPU on idle connections; readiness is now cleared through `try_io`.
- Background loops no longer busy-spin when their `ReconcileLoopHandle` is dropped without shutdown (for example after a startup error).
- State persistence no longer fails with "cannot rewrite desired snapshot without encoded desired bytes" when a mutation races the snapshot capture; the rewrite is deferred to the next persist.
- Executor and provider subscriptions no longer drop all but the first matching event of a batched `ClientEvents` frame.
