# Flakes

A test that passed only when it was run again has a bug in it: the test's, or the code's. Each one
is written down here with how many times a rerun was what made a run green. Each is fixed by its
cause, never with a retry. One that is fixed stays on the list with its cause and fix, so the
same shape is recognised next time.

| Test | Reruns to green | Symptom | Cause | Fixed in |
| --- | --- | --- | --- | --- |
| `drills` `workloads.rs` `orion_dies_whole_and_takes_back_what_kept_running` | 1 (a gate of a commit's tree, under parallel load) | the subscriber role: `failed Connection refused`, and no `seen 300` within 10 s | The test killed Orion before the subscriber role had connected. Under load the role was still in its own connect loop (a fixed 20 ms retry that gave up after 10 s) and met only a socket with no listener. The library also had no first connect that keeps trying. | C61 (the obvious connect keeps trying), C62 (the roles use it; the test waits for both roles to be in before the kill) |
| `connect` `alive.rs` `a_node_silent_for_its_idle_time_is_gone_and_silent_for_says_so` | 1 (in 40 runs under full load) | `after 598ms`, below the 600 ms idle time | The test timed the silence from its question, but silence counts from the last frame heard (the welcome), which came earlier, and longer before under load. | C62 (it measures `silent_for` when the session is found gone) |
| `connect` `alive.rs`, a board-socket test (which one was not recorded) | 1 (the C59 gate) | `ConnectionReset` on the board socket | Two tests in one process bound the same socket path, `orion-alive-silent-<pid>`. One test's client reached the other's fake node, which accepts once. Which test lost depended on timing. Under load after C61, the same collision hung a test: the second client waited in a backlog no one accepted from. | C62 (each fake node gets a path of its own, counted, whatever its test's name) |
| `shell` `shell.rs` `with_a_login_helper_the_helper_starts_the_shell` | 1 (the D16 gate); then 1 in 60 under full load. The runs said not to reproduce it before were most likely without `--features login-helper`, which the test needs: they ran no test | `not opened on a terminal: Refused(Some(NotFound))` | The test's, not the code's. It gives credit for each piece of a shell's output; a shell that has exited is gone, so credit for it is refused `not found`, and under load that refusal came after the exit. The test took the next thing it heard as the answer to the next shell it opened, without looking at which request a refusal answered. | C65 (a shell's opening skips refusals of other requests; the test now sends credit for the exited shell itself, so the order that failed happens every run) |
| `records` `records.rs` `a_watcher_that_falls_behind_catches_up_and_misses_no_record` | 1 (the C32b gate, under parallel load); not reproduced in 15 runs under spin load | `get: Io(BrokenPipe)` after the writes | The test's. Its comment said the watcher's session keeps turning while it falls behind, but nothing turned it: no frame was taken from it during 3,072 writes. Under the gate's load the writes took about 7 s, and a frame the comm core could not hand to the session within `comm.write_ms` (5 s) dropped the session as stalled. | C32b (the session is pumped between writes; the test's board has `write_ms` 300 and the writes pause, so the order that failed happens every run: without the pump it fails 5 of 5) |
| `connect` `connect.rs` `a_tool_with_a_key_signs_its_session_on_a_link` | 1 (a gate-timing run under load ~23); not reproduced in 60 runs under spin load | `the board does not take a signed session on a link`, where the revoked key should have been refused | The code's. The board's sealed pong to the last signed session's heartbeat stayed unread in the link, and the next signed hello took it for the board's reply. Plain pings and pongs were already skipped there; sealed ones were not. | C71 (a sealed frame before the handshake ends is skipped; a test puts a sealed pong before the answer every run) |
| `comm-app` `configured.rs` `a_running_comm_core_serves_the_files_its_settings_name` | 1 (a gate-timing run under load ~40) | `sys/echo: /usr/bin/echo signal: 9 (SIGKILL)` where `made by echo` was due | The code's. The runner of a command that makes a file killed it as soon as its output ended, then waited. coreutils closes its output before it exits, and a kill in that gap was reported as the command's end. | C71 (the command is waited for until its deadline; a test command closes its output and sleeps before exiting, every run) |
| `ssh` `login.rs` `only_the_comm_cores_user_may_ask` | 1 in 4 nextest runs under load ~70 | `send failed: Broken pipe (os error 32)` where the helper's refusal was due | The code's. The login helper refuses an asker of another user before reading its question, and closes. A client that had not yet sent its question got a broken pipe and never read the refusal waiting for it. | I11 (a send that fails with a broken pipe or reset still reads the answer; a unit test closes the helper's end before the question is sent, every run) |
