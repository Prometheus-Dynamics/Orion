## Why

The fourth part of the clock row. A board gets through a whole match with no computer
attached, so the time has to come from the network it is on. Where a server is there, its
address is often known only as "the gateway" or "the NT4 server". Where none is, the boards
have only each other, and must not agree on a wrong time and call it right. And the clock was
served on every interface the address reached, where every other way in follows a list.

## Built

- **`gateway`** in `time.servers`: the default route's gateway, asked as an NTP server. It is
  read from the kernel's route table each time it is asked (`/proc/net/route`: the route to
  everywhere through a gateway with the lowest metric), so it follows the network. IPv4.
- **`nt4`** in `time.servers`: the host of `nt4.server`, asked as an NTP server at port 123.
  With no `nt4.server` it is an error at start.
- **Quiet.** A source that does not answer is passed over for the next and nothing is logged,
  as for any server. The polls back off as before. What was tried last is in `orion.time` and
  `orion/state`.
- **`time.interface`**, a list: the clock is served on those interfaces by name, a datagram
  socket and a listener kept to each at `time.serve`. Each is opened when its interface is
  there, looked at every few seconds, and opened again when the interface is made again. One
  that is not there holds up nothing and is said once. Without the setting it is as before.
- **Boards with no time.** A board that has not synchronized, and is not told to be the
  reference, already answers "unsynchronized", and a client already ignores that. A test now
  pins it. `docs/comm.md` gives the lines for an image, with no `time.serve_authority`.

## Tests

- `orion-time`:
  - `the_default_routes_gateway_is_read_from_the_kernels_table`: the lowest metric of two; none
    on a network with no way out.
  - `the_nt4_server_is_asked_as_an_ntp_server_and_a_source_that_is_not_there_is_passed_over`:
    `gateway` then `nt4`, and the second answers; held to the build's date, not to the saved
    time as a peer is.
  - `boards_with_no_time_do_not_take_each_others_and_call_it_synced`.
  - `the_gateway_and_the_nt4_server_are_sources_by_name`, and `nt4` without `nt4.server` and
    `time.interface` without `time.serve` refused.
- `orion-comm-app` `interfaces::`, in a network namespace: the clock answers on the interface
  named and not on another; the one not there is said once; made again, it answers again; the
  one that comes later answers.

Seven mutants each failed 3 of 3 runs: the highest metric taken; the address read backwards;
`nt4` passed over; `nt4` with no server let through; the datagram socket not kept to its
interface; an interface made again not noticed; and the "not there" line said every try.

**Not covered:** `gateway` answering. The test machine's gateway serves no time, so the test
shows it passed over, and the address it would ask is tested apart. It is for a board on a
network whose gateway serves NTP.
