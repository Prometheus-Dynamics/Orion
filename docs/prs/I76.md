## Why

A PC's Files and backup tab needs the files the image chooses to expose: to browse them, back
them up and restore them, with the security switch and the grants deciding who, as everywhere
else. SFTP runs as the account that logged in, so the kernel's permissions decide there, not
the grants, and with the switch off it reaches the whole file system. The image's roots keep
one security model and reach only what the image named.

## Built

- **Roots in the settings.** `files.root.<name> = <directory> rw` (or `ro`), one line each, so
  the image adds a root with one line, a read-only one over its logs among them.
  `Source::prefixed(prefix)` reads every key under a prefix and marks each read. A name is 1 to
  32 of `a-z 0-9 - _`; the directory is a whole path.
- **Confinement.** Every open, listing, removal and rename goes through `openat2` with
  `RESOLVE_BENEATH | RESOLVE_NO_MAGICLINKS` from the root's directory, opened again for each
  (`rustix`, no `unsafe`). A link that leads out is refused by the kernel. The index's walk opens
  each directory beneath the one before with no link followed (`RESOLVE_NO_SYMLINKS`).
- **Fetch.** Node logic offers `roots/` and gives each file as a program gives one (`give.rs`):
  a helper thread reads it once for its digest, then a window of 8 chunks of up to 32 KiB,
  paced by the client's `FileTaken`, read with `pread`. A file that grows while given is given
  as hashed; one that shrinks is aborted. 64 at once; a client quiet for a minute while owed
  is let go.
- **The index.** `roots/<name>/index`, in `orion_files::index`'s format, made on the helper
  thread: every file, its size as its bound, `user-data`. 65,536 files and 32 directories deep
  at most. Not sorted, which the format does not ask for (see Size).
- **Push.** Node logic takes `roots/<name>/<path>` pushes ahead of receivers and its own store,
  into one `orion_file_store::Files` per `rw` root. The store keeps its parts and its note in
  the root's own `.orion` (`FilesConfig::own`), so the rename into place is on the root's file
  system. `Files::begin_as` takes a `FileBegin` whose destination the caller has made the
  path in the root.
- **The store places beneath itself.** The helper that puts a checked file in place
  (`verify.rs`) opens the destination's directory beneath the store with `openat2`, makes each
  missing directory with `mkdirat` in one opened beneath it, and renames with `renameat`. It
  was `create_dir_all`, a `canonicalize` check, then `rename`, which a link swapped in between
  the check and the rename could take out of the store. This applies to `files.dir` too, with
  the same words ("the destination is outside the store"). A link with an absolute target that
  points back inside the store is now refused too.
- **The actions.** `files.list` (paged at 128 by name after `<after>`, with a heap of at most a
  page, so a large directory is never held whole), `files.remove`, `files.mkdir`,
  `files.rename` (`renameat2(RENAME_NOREPLACE)` unless `replace`), registered at node logic's
  attach as `files.send` is: programs on the board and operators with the grant. Text
  arguments and text output. A run on the roots is audited with its arguments.
- **`orion-test-board`.** `Options::granted`, operators trusted with some things from the
  start. The crate's tests are one binary (`tests/all.rs`) now that it has two files.
- **No new wire kinds.** Push, fetch, actions and the index are used as they are. Level 6.

## The contract, for a client

`docs/node.md`, "The image's roots": the names, the actions and what they give, the grants and
the words. In short:

- Fetch `roots/<root>/<path>`; `roots/<root>/index` for a whole root. Push to the same names.
- `files.list` (no arguments: `root rw <name>` lines; `roots/<root>/<dir> [<after>]`:
  `<kind> <size> <mtime> <name>` lines, then `more`, then `unnamed <n>`), `files.remove`,
  `files.mkdir`, `files.rename <from> <to> [replace]`.
- Grants: fetch `read`; push everything; the actions their own (`files.*`). Off: everyone.
- Words: `no such root: <name>`, `the root is read-only`, `not found`, `outside the root`,
  `there already`, `the directory is not empty`, and the rest listed in `docs/node.md`.

## A restore that breaks off

Restoring a root is pushing each file, then removing what the backup does not have. Each file
is whole, the old or the new, never a mix of the two. A restore broken off halfway leaves the
root partly restored: some files new, the rest old, extra files not yet removed, and the file
under way as a part in `.orion`, out of sight. The board does not mark the root as being
restored. The client knows how far it got and tells the user, for example "app: 140 of 312
files restored; restore again to finish". Restoring again pushes every file again, resuming the
one that was under way.

**A staged restore (proposed, not built).**

- **How it works.**
  - `files.restore.begin <root>` makes `<root>/.orion/stage/` and a marker,
    `<root>/.orion/restoring`.
  - Pushes to `stage/<root>/<path>` land in the stage, each placed as now.
  - `files.restore.commit <root>` moves each top-level entry of the root into
    `.orion/old/`, then each staged entry into the root, then removes the marker. Each move is
    one `renameat` on one file system.
  - `.orion/old` is removed afterwards, off node logic's thread.
- **If it breaks off.**
  - A restore that breaks off before the commit leaves the root as it was. A new `begin`
    clears the stage.
  - A commit that stops partway (power lost) is finished when node logic starts, because the
    marker is still there. While the marker is there, `files.list` says `root rw app
    restoring`, so the client shows the state.
- **Size.** About 200 lines and 250 lines of tests. An estimated 6 to 8 KB in `orion`.
- **A truly atomic swap.** This needs the image to make the root a link to a directory
  (`/data/app -> app.a`), which one `rename` of a new link replaces. That is the image's
  choice, and about 120 lines on top.

## Proof

- **`roots::a_root_is_fetched_pushed_listed_and_changed_and_nothing_outside_it_is_reached`**
  (`orion-test-board`, the real comm core and node logic):
  - **The setup.** A root `app` (rw) and `logs` (ro), and outside them a secret.
    Links lead out three ways: absolute, `../../`, and a directory link in `app`.
  - **What it checks.**
    - A fetch, a push into new directories, and nothing left in `.orion`.
    - Each way out is refused "outside the root", and a push through the link is refused
      "the destination is outside the store".
    - A read-only root refuses pushes and every action. `.orion` refuses a push and is not
      listed.
    - The listing of the roots and of a directory; `mkdir`, `rename` (refused "there already"
      without `replace`), `remove` (refused for a directory with something in it; a link's
      removal leaves what it leads to).
    - The index of each root.
- **`roots::a_push_broken_off_never_replaces_the_file_and_goes_on_after_node_logic_restarts`**:
  - **The setup.** A 4 MB push over a file is cut off past 1 MB. Node logic is stopped and
    started.
  - **What it checks.**
    - The old file is untouched and one part is kept.
    - The push again goes on from at least where it was, and commits.
    - Nothing is left in `.orion`.
- **`roots::fetches_at_once_from_a_slow_node_logic_past_a_full_outbox_are_paced_not_lost`**,
  I70's shape on the giving side:
  - **The setup.** `comm.outbox_bytes = 131072`. Two fetches of 4 MB at once, then four with
    node logic slowed by 2 ms for every frame it reads.
  - **What it checks.** Every fetch is whole and checked, and node logic runs.
- **`roots::with_security_on_the_grants_decide_and_a_read_only_root_refuses_everyone`**:
  - **The setup.** Security on. One operator with `read` only, one with `read` and
    `files.*`.
  - **What it checks.**
    - The reader fetches, and is refused the push and `files.list`.
    - The other lists and makes a directory, and is refused "the root is read-only" in
      `logs`.
    - A program on the board is refused the same.
- **`roots::a_fetch_goes_on_from_what_the_client_has`**: a fetch with the first 100,000
  bytes already there commits whole.
- **`keys_under_a_prefix_are_found_in_order_and_read`** (`orion-config`).
- **Mutations, 3 runs each, every run failing:**

  | Mutation | Result |
  |---|---|
  | `path::beneath` without `RESOLVE_BENEATH` | the secret is given: "roots/logs/abs was given" |
  | the store's placement without `RESOLVE_BENEATH` | the push through the link commits outside |
  | a read-only root takes pushes | `left: Committed, right: Rejected` |
  | `.orion` listed | `left: [".orion", "a", "out"]` |
  | the give's window unbounded | the client is dropped: "fetch 0 of 2: Broken pipe" |
  | the store starts each part again (no resume) | "went on from 0, after 1015808 were there" |

- **Every `orion-test-board` test passes 3 of 3**, with the flake below fixed, and so do
  `orion-file-store`'s and `orion-config`'s.
- **A flake, fixed** (`docs/flakes.md`).
  - **What failed.** `board::pushes_through_node_logic_to_a_receiver_all_commit` and
    `board::pushes_at_once_past_a_full_outbox_are_paced_not_lost` failed once each while this
    was written: `held.answered()` was one short with every push committed.
  - **The cause.** The test receiver told a commit and then counted it.
  - **The fix.** It counts first.
  - **The proof.** With 300 ms planted between the telling and the count, the old order fails
    3 of 3 (19 for 20). The new order, with the same delay after the telling, passes 3 of 3.
- **The landing gate passed.**

## Not in this

- **The staged restore.** It is proposed above, not built.
- **A tar stream of a whole root.** None for the alpha; the index and a fetch of each file
  are the whole root.
- **Names Orion does not carry.** A file whose name has a space or anything outside
  `A-Z a-z 0-9 . _ - :` and `/`, or that is over 127 bytes with `roots/<root>/`, is listed
  as `unnamed` and is left out of the index. It cannot be fetched, pushed or changed.
- **A file that grows after its index was made.** It is larger than its bound, and a fetch
  held to the bound refuses it.
- **armv7 and riscv64.** They were not measured.
