## Build

- Parse pre-authentication traffic in a child with no privileges.

## Proof

A crash in the child does not reach the server.

## Built

- `crates/comm/ssh-sandbox` (`orion-ssh-sandbox`): `SandboxedSsh`, the SSH server with a
  child process for each connection. The child (`child.rs`, started with `ssh-connection`)
  reads everything the client sends: the key exchange, the login, every request after it.
  Before it reads a byte it becomes `ssh.sandbox_user` with no groups, checks it cannot go
  back, and sets no-new-privileges.
- The child asks the keeper in the comm core over a socket (`protocol.rs`): may this key
  log in, a session, a connection from the board. `monitor.rs` answers. A session or a
  connection is answered only after the keeper itself let that connection log in; a
  connection logs in once; the keeper holds the child to the login time; anything that is
  not a question ends the child. Sessions come back as descriptors.
- `orion-ssh` is split in two for this: `Keeper` has what needs the board's rights (the
  check, starting a session as the account, connecting from the board) and takes only
  plain values; the side that speaks SSH asks through the trait `Door`. In one process the
  door calls the keeper (`Local`); with the sandbox it is the socket (`Remote`). A session
  is watched by a thread that reports its exit code on a status socket and ends it when
  that socket closes, so a session never outlives whoever carried it.
- `orion-comm-app` feature `ssh-sandbox` (on by default): `ssh.sandbox` (`true`),
  `ssh.sandbox_user` (`nobody`).

## Proved by

`cargo test -p orion-ssh-sandbox --all-features`:

- With OpenSSH's `ssh`, through a child: a command with its exit code and user, a shell on
  a terminal, 100,000 lines of output, a stranger refused, a connection from the board
  (`-W`). While a connection is open its child has `NoNewPrivs: 1`; afterwards it is gone.
- A child killed with `SIGKILL` while its connection runs a five-minute session: that
  client is cut off and the session's process is ended; a connection beside it finishes
  and prints its line; the next login works; no connection or child is left counted.
- Playing the child against the keeper: before a login a session and a connection are
  `not logged in`; a stranger's key, no key and an account that is not there are refused;
  the operator is let in once and not twice; a session's pipes and status socket come
  with the answer and carry its output and exit code 4; bytes that are not a question end
  it; a child whose client never logs in is dropped after the login time.

Every earlier SSH test still passes on the split server.

## Different from the brief

- The child reads everything, not only what comes before the login: the SSH library keeps
  one connection in one process, and reading the rest without rights as well is better.
- The child holds the board's host key, which it needs for the key exchange. Taking a
  child over lets someone pretend to be the board to a client; it does not let them in.
- A child can still open network connections of its own as the account it became: nothing
  here filters system calls. Its connections for a client go through the keeper.
- When the comm core is not root the child cannot become another account. It is still a
  process apart, without the trust store in its memory, and that is logged at the start.
  The path where it becomes `nobody` was not run here: the tests are not root.
- The keeper uses a thread for each connection and one for each session.
