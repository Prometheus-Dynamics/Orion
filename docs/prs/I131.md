# I131: Cargo's jobserver is not in a lane's key

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I130

Read `AGENTS.md` and `docs/design.md` first.

## Why

In the first `GATE_LANE_SCHEDULE` measurements, every `shared-jobs` run reused nothing in any
lane: 0 of 95 tests, 0 of 110 matrix items. Those runs could not be compared with the others.
The keys hold every `CARGO_*` variable. `shared-jobs` hands every cargo a `CARGO_MAKEFLAGS` that
names its jobserver's FIFO, and that FIFO is under a directory that is new in every gate, so
every key was new too.

## Changes

- **`CARGO_MAKEFLAGS` joins `CARGO_TARGET_DIR` in `size-key.py`'s `NOT_IN_KEY`.** It sets how many
  jobs run at once, never what is built.

## Proved by

- A new keys self-test case: a key with a jobserver in `CARGO_MAKEFLAGS` stays where it was.
  Red on d3ee6f5c: the key moved.
- The existing case for the build's environment (`RUSTFLAGS`) still moves the key.
- Mutants, 3 runs each, both red:
  - the jobserver keyed again;
  - `RUSTFLAGS` left out of the key too.
