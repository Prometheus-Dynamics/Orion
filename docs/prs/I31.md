## Fault

A program giving a file (`Files::offer`) could not stop and say why. To stop, it dropped the
gift, which sent nothing, and the client's fetch then waited for the session's silence limit
(5 s by default, longer for a client that waits while the comm core is alive). A file asked and
dropped without an answer did the same. The client could not tell that the program had stopped
from any other rejection.

## Built

- `FileState::Aborted = 5`. Only a giver sends it. An older client reads it as `Unknown(5)`; its
  fetch still ends at once as not given, since any word from the program ends a fetch.
- `Gift::abort(why)` sends `FileTaken { Aborted, why }` with what the client has. The fetch ends
  `Aborted` with "the program that offers it stopped giving it: <why>". A gift that is over
  already is left as it ended.
- A gift dropped before it is over is aborted, "it was dropped before it was given". A file
  asked and dropped without `give` or `refuse` is refused, "the program that offers it did not
  give it". A program that dies runs no drop. Its session's end still says "the program that
  offers it went".
- The comm core counts `Aborted` as over, so it frees the fetch at once. An older comm core
  passes the abort on and frees the fetch when either session ends.
- `orionctl file fetch` prints `NAME was not fetched: <those words>` and exits 1, not done.

## Proof

`crates/comm/file-offers/tests/abort.rs`, a real comm core with client and program sessions:

- A gift aborted mid-transfer (4 MiB, some of it taken): the fetch ends `Aborted` with the
  program's reason, under 1 s after the abort. That is well inside the 5 s silence limit.
- A gift dropped mid-transfer ends its fetch `Aborted` within 1 s. A file asked and dropped
  unanswered is `Rejected` with its words within 1 s.
- 257 aborted fetches, one more than the comm core has room for under way, then a whole
  fetch commits.

Each fault planted alone fails its tests:

| Fault planted | Tests that fail |
|---|---|
| The abort sends nothing | all three (the first at 5 s, when the session is lost) |
| A dropped gift says nothing | the drop test |
| An unanswered ask dropped says nothing | the drop test |
| The comm core keeps an aborted fetch | the 257 test, refused as busy |
| The fetcher calls an abort a rejection | all three |

The abort and fetch tests ran 10 of 10 green.

`fetch::a_fetch_whose_program_goes_is_rejected_to_its_client` used to end its program's session
by ending its thread, which now drops the gift first and aborts it. The program now reaches the
comm core through a relay in the test, and the relay is cut, as when a program dies. So the test
still proves what it says.
