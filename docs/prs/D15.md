# D15: A push with a known digest, a pushed file checked for change, a stepped push

**Status:** done

**Group:** D. Client

**Wave:** 18

Read `AGENTS.md` and `docs/design.md` first.

## Changes

`crates/client/files`, `crates/client/orion`, `docs/client.md`

## Build

A push read the whole file through to hash it before it sent a byte, every time, even for a
file the program had pushed before. A file edited during a push was found only by the board's
digest check, as a rejection, after every byte had been sent. And a push held the session until
it ended, so a program could not do anything else on it meanwhile.

1. `Transfer.digest`, and `Files::push_with(destination, source, Known { digest, size },
   progress)`, which does not hash.
2. `Files::push_file(destination, path, known, progress)`: the size and change time are looked
   at when the push begins and again before the commit. Changed means no commit, and an error.
3. A stepped push: `Files::start_push(destination, source, known) -> Pushing`, and
   `Pushing::step(wait) -> Step` (`Waiting`, `Progress { received, size }`, `Done(Transfer)`).

## Built

- `push.rs`: `Known`, `Step`, `Pushing` (begin, send, commit, over) and the four calls. `push` and
  `push_with` are `start_push` stepped to the end by `Pushing::finish`, so there is one push
  loop. Dropping a `Pushing` stops following the transfer; the board keeps what it has.
- `Transfer.digest`: the file's SHA-256, or the one a pull asked for.
- The facade re-exports `Known`, `Pushing` and `Step`.
- `docs/client.md`: the three calls.

## Proved by

- `orion-files` tests:
  - `a_known_digest_is_not_read_for_again_and_a_wrong_one_is_rejected`: the source is read
    twice by `push`, once by `push_with`, and a wrong `Known` ends rejected with nothing in place;
  - `two_pushes_are_stepped_together_on_one_session`: two pushes stepped in turn on one session
    both commit, each over several steps with progress that only goes forward, and a push that
    is over says so;
  - `a_file_that_changes_while_it_is_pushed_is_not_committed`.
- The resume, refusal and slow-hash tests, unchanged, through the new loop.
- Not vacuous:
  - with `Known` ignored, the first test fails on the read count;
  - with the change check off, the third test commits.

## Different from the plan

- `Step::Waiting` was added. Before the board answers the begin, there is no count to report,
  and reporting zero broke the resume test's "where it resumed" check.
