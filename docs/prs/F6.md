## Built

- `crates/gateways/nt4` (`orion-nt4`): dev's NT4.1 client and server, ported. Client:
  subscribe by name or prefix, publish, a clock estimate, reconnect with backoff, liveness.
  Server: a topic table a host edits, relay, retained and persistent topics, liveness.
  `Server::take` serves a connection upgraded elsewhere, so the server can sit behind a
  listener it shares with the comm core's own protocol.
- The WebSocket code is `orion-ws`, not a third-party crate. For that `orion-ws` gained:
  sockets that are `Send`; `WsRead::next`, a read that keeps its place when dropped half way
  (what `select!` does) and holds the message itself; `WsWrite::ping`; `accept`, an upgrade
  on a connection the caller accepted, with the server's order of subprotocols deciding;
  `connect_on`, the client's side on a connection the caller made, offering several.
- The MessagePack that NT4 uses is written out in `src/msgpack.rs`: no `rmp`, no `rmpv`.
- `interop/run.sh` and `interop/ntcore_side.py`: the interop check against ntcore.

## Proved by

- `crates/gateways/nt4/interop/run.sh` passes against `pyntcore`: an ntcore client
  publishes a double[] and a string to the server here and reads a double and a string from
  it, the relay stamps them on the server's clock, and the client here reads double,
  boolean, string[], int and raw from an ntcore server.
- `cargo test -p orion-nt4`: 33 unit tests (values, frames with the spec's bytes, control
  messages, MessagePack forms and cut-short values) and the round trips, hardening,
  liveness and allocation tests from dev, on the new WebSocket code. A relayed value costs
  at most 6 allocations across client, server and subscriber; encoding into a reused buffer
  and decoding a scalar cost none. A client reaches the server through a shared listener
  while another protocol keeps using the same port.
- `cargo test -p orion-ws --test next`: the server's order of subprotocols decides and the
  client is told; a read dropped hundreds of times in the middle of messages loses nothing,
  with a ping in the middle of a message in pieces; a ping is answered; a message longer
  than is taken ends the connection.

## Different from the brief

- The interop script is in the crate, `crates/gateways/nt4/interop/`, not in `scripts/`: it
  names the products it is tested against, and the crate is where those names may be.
- It is not in the gate: it installs `pyntcore` from the network the first time.
- `tokio-tungstenite`, `futures-util`, `rmp`, `rmpv` and `clap` are not carried over. A
  message longer than 4 MiB (`MAX_MESSAGE`) ends the connection.
- A connection that offers no NT4 subprotocol is answered `404`, as the shared listener
  answers any subprotocol nobody takes; dev answered `400`.
