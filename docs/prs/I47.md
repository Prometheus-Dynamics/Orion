## Why

Another program that uses the shared-memory crates must take them from the same device library
commit as Orion, or a process holds two copies of them. That program moves its device library
pin to `next` at `5ee2f64a`, for a stream description it needs, so Orion moves its pin there
from `c8f1b3d2`.

## Built

- **Cargo.toml.** The seven `shm-*` workspace dependencies, from the `.git` URL, at
  `5ee2f64a75561db988d519ac68395a8dd1054bb8`.
- **The lockfiles.** Only the `source` lines change: no package was added, removed or moved to
  another version. Nothing under the device library's `shm` directory changed between the two
  pins, so no byte Orion builds changes.

## Proof

- **The device library's checkers**, from its `next`, on `Cargo.lock`:

  | | its pin check (at `5ee2f64a`) | its one-source check |
  |---|---|---|
  | Before | fail: 7 of 7 crates not at the pin | pass: one copy of each of 7 |
  | After | pass: all 7 at the pin | pass |

  Both example lockfiles pass both checks too: their one `shm-*` crate is at the pin.
- **The landing gate passed** with every lane run in full.
