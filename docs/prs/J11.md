## Build

A client of this revision on a comm core of the last one (`455a956e`) failed every declaration
and subscription with `not the wire: a ring that cannot be mapped`. The shared-memory crate had
said what was wrong (`this ring is layout 1; this build reads layout 2`), and the client threw it
away. Keep the words, say which side is older, and sweep the client for other typed errors turned
into words-free ones.

## Built

- `ClientError::Layout { what, found, reads, level }`, additive (`ClientError` is
  `#[non_exhaustive]`). Its words say which side is older and what to update:
  - an older comm core (`found < reads`): "the comm core is older; update it". At layout 1 it
    adds that the comm core is built against the device library from before `ad5bf930`;
  - an older client (`found > reads`): "this client is older; rebuild it against the comm core's
    version";
  - a node that said level 0 at hello: "it is from before levels, and every ring it shares is
    layout 1".
- `ClientError::Memory { what, why }`, additive: any other shared-memory error, with the crate's
  own words.
- `orion_topics::from_ring(what, level, RingError)`: the one place a `RingError` becomes a
  `ClientError`. Used for a publisher's ring, a subscriber's ring, a subscriber's ring of its own
  (no shared memory on its address), and a buffer pool (`orion-buffers`).
- `Cx::level()`: the level the node said at hello, so a handler can say it.
- The C library returns `ORION_E_REFUSED` for `Layout`, as for `Revision`: asking again does not
  change it. `Memory` stays `ORION_E_INTERNAL`, as `Protocol` was.

### Level 0 at hello

Level 0 reliably means a layout-1 comm core: levels came with C35, and layout 2 with J8b, after
it. So the first topic error from such a core says so. Level 1 or 2 says nothing about the
layout (C36 to J8a are at level 2 and share layout 1), so nothing is guessed there: the layout in
the error is enough. Nothing is said at connect: a session that never declares a topic is not
told about memory it never maps.

### The sweep

Changed (a typed error that lost its words):

| Where | Was | Now |
| --- | --- | --- |
| `topics/src/state.rs`, publisher | `Protocol("a ring that cannot be mapped")` | `from_ring("a publisher's ring", ..)` |
| `topics/src/state.rs`, subscriber | the same | `from_ring("a subscriber's ring", ..)` |
| `topics/src/state.rs`, own mirror | the same | `from_ring("a subscriber's ring of its own", ..)` |
| `buffers/src/lib.rs`, pool offer | `Protocol("a pool that does not check")` | `from_ring("a buffer pool", ..)` |

Looked at and kept:

- Wire decodes (`connect` frame, welcome, reject, ping, body; `transport` sealed frame;
  `link_sign`; action, node, workload and destination names in `actions`, `orion`, `files`;
  `topics` declaration): the decode error is a code with no words (`malformed`), so the
  `Protocol` text, which names what did not read, says more than it did.
- `TooLarge` from `encode_body`: the only way encoding fails.
- Holds pages from the comm core (`buffers/src/adopt.rs`) already go through
  `TopicError::Ring`, which keeps the `RingError`.
- `provider/src/lib.rs`: a resource whose description does not decode is listed with no topics,
  actions or labels. That is a listing, not an error path; noted, not changed here.

## Proved by

- `connect` unit test `a_layout_says_which_side_is_older_and_what_to_update`: each branch's
  words, exactly.
- `topics` unit test `a_layout_keeps_both_layouts_and_anything_else_its_words`.
- `connect/tests/older.rs` `a_handler_is_told_the_level_the_node_said_at_hello`: on a board of
  this build a handler's `Cx::level()` is `INTERFACE_LEVEL`.
- Against the `455a956e` comm core and node on this PC (not a board), the probe declares and
  subscribes:

  ```text
  before: declare: not the wire: a ring that cannot be mapped
  after:  declare: a publisher's ring from the comm core is shared-memory layout 1, and this
          client reads layout 2: the comm core is older, built against the device library
          from before ad5bf930; update it (it said level 0 at hello: it is from before levels,
          and every ring it shares is layout 1)
  after:  subscribe orion.host: a subscriber's ring from the comm core is shared-memory
          layout 1, ... (Client(Layout { what: "a subscriber's ring", found: 1, reads: 2,
          level: 0 }))
  ```

- Mutations, 9 of 10 caught: the side, each sentence, the `ad5bf930` and level-0 conditions,
  `Cx::level`, the layout arm, the level passed, the memory words. The survivor is equivalent:
  `found > reads` as `>=`, and a layout error never has equal layouts.

## Different from the brief

- No line at connect for level 0 (see above): the first topic error carries it.
- The call sites in `state.rs` and the buffer pool are proved by the run against the old core,
  not by a test in the tree: no stub here hands a client a layout-1 ring.
