## Build

A program that holds something for a caller (a lease, a lock, a session of its own) had no way
to learn that the caller was gone, except for a run that was not detached, by its cancel. The
device library's bridge held a 60 s lease to cover for that. Agreed with the coordinator:

1. `Claim` gains an appended `session: u64`: an opaque token for the calling session, handed
   out by the action list, never reused while node logic runs, and different for two sessions
   of one identity.
2. A new kind, `ACTION_CALLER_GONE` 0x38 `{ session: u64 }`. When a session ends, for any cause,
   node logic sends it once to every program that was given a `Claim` from that session.
3. A detached run must carry a deadline, and is refused by name without one. A setting with a
   default gives the longest deadline a node takes.
4. Orion says only that a session ended. What a program holds for a caller stays its own.

## Built

- Wire: `ACTION_CALLER_GONE` 0x38; `Claim.session`, appended; `CallerGone { session }`; errors
  `NoDeadline` (18, "a detached run needs a deadline") and `DeadlineTooLong` (19, "deadline is
  longer than allowed").
- `orion-action-list`: a token for each session that asks for a run, from a counter that never
  goes back, also across `forget_sessions`; a list of which program was given a run from which
  token. `gone(session)` deals with the runs as before, then sends `CallerGone` to each program
  given a run from it, and forgets both. A program that goes is not told afterwards, and a
  program is never told of its own session. `MAX_DETACHED_MS` (an hour) and
  `set_max_detached`.
- `orion-node-app`: the setting `actions.max_detached_ms`, defaulting to an hour.
- `orion-actions`: `Request::Run` carries `session`; `Request::CallerGone { session }`.
- `orion-device-actions`: `Heard::Run` carries `session` (zero when the host does not say);
  `Heard::CallerGone { session }`.
- `orion` CLI: `action run` takes `--deadline MS`. `--detached` without it is a usage error, so
  it is not left to the board to refuse.
- Stubs and the client tests' routers say session 0, as a host that does not say.
- Vectors: `ACTION_CLAIM` gains `03`; `ACTION_CALLER_GONE` is `03`.
- Docs: `docs/node.md` (a caller's session ends; detached runs need a deadline),
  `docs/client.md`, `docs/settings.md`.

## Proved by

- `orion-action-list`, new `tests/caller_gone.rs`:
  - `a_detached_run_needs_a_deadline_no_longer_than_the_node_takes`: zero and over an hour
    refused by name with nothing reaching the program, an hour taken, a lower setting enforced,
    and a run that is not detached needs no deadline;
  - `each_program_given_a_run_from_a_session_is_told_once_when_it_ends`: two programs, one
    whose run already ended, each told once with the token their claims carried, after the
    cancels; a second `gone` tells nobody;
  - `a_program_given_nothing_from_a_session_is_not_told`;
  - `two_sessions_of_one_identity_have_tokens_of_their_own_never_reused`: including after the
    comm core's number comes round again, and after `forget_sessions`;
  - `a_detached_run_goes_on_and_its_program_is_told_its_caller_is_gone`;
  - `a_program_is_not_told_of_its_own_session`.
- The list's harness moved to `tests/common`, shared by both files. The existing 21 tests take
  the `CallerGone` frames out through `Bench::gone`, and give their detached runs an hour.
- `orion-node-app`, `a_program_hears_once_a_callers_session_ends`: through a real comm core and
  a provider process, two sessions of one program get different tokens, the provider hears the
  first one's token when it disconnects and not the second's, and detached runs with no or too
  long a deadline are refused as `NoDeadline` and `DeadlineTooLong`. The node-app suite was run
  five times, clean.
- `orion-device-actions`, `a_caller_gone_names_the_session_its_runs_came_from`; the run test
  checks `session`.
- `orion-ctl`: `--detached` without `--deadline` is a usage error.
- Not vacuous:
  - with no `CallerGone` sent, five of the six list tests fail;
  - with the token taken from the session number, the token test fails;
  - with the deadline check off, the deadline test fails;
  - with a gone program kept on the list, the own-session test fails;
  - with a program listed once per run, the told-once tests fail;
  - with the client off by one on the token, the node-app test fails.

## Different from the brief

- `CallerGone` is sent after the session's runs are cancelled, so a program hears of its runs
  first and then of the session.
- A run forwarded to another node is claimed there from the peer link's session. That node's
  program is told when the link ends, not when the first node's caller does. The first node
  still cancels a forwarded run that is not detached.
- The MCU template's C API does not pass `CallerGone` on. It runs one run at a time and holds
  nothing for a caller.
- The CLI got `--deadline`. Before this, `action run --detached` always sent a run with no
  deadline, which is now refused.
