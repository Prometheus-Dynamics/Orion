## Build

The static board files compile C (`ring`, through the SSH way in) with `zig cc`, and the size gate
holds them to numbers measured with zig 0.15.2. Another zig builds C differently, so those
numbers, and what was tested, stop applying. Check the version and refuse any other, saying what
to do.

## Built

- `scripts/size-gate.sh`: before it uses zig for a board target, `check_zig` reads `zig version`.
  Anything but `0.15.2`, including no answer, fails the gate:

  ```text
  FAIL: zig 0.14.1 is on PATH; the board files are built with zig 0.15.2 only.
        Install zig 0.15.2, or set CC_<target> to another C compiler for that target.
  ```

  It checks once per run. A target with its own `CC_<target>` is not checked.
- The three `scripts/zigcc/<triple>` C-compiler wrappers check the same, so a build by hand
  (`packaging/README.md`) is refused the same way. The `-ar` wrappers do not check: archiving
  does not depend on the compiler's version.

## Proved by

- A stand-in `zig` on `PATH` that says `0.14.1`: the armv7 wrapper and `check_zig` both refuse,
  with the words above, exit 1. With zig 0.15.2 the gate builds and measures all three board
  targets.

## Different from the brief

- The check is in the C-compiler wrappers as well as the size gate. The brief named the size
  gate or the build script. A build by hand goes through the wrappers and not the gate.
