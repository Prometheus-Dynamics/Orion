# I34: A program's own pause is never its client's silence

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I33

Read `AGENTS.md` and `docs/design.md` first.

## Changes

`crates/client/files` (`Gift::step`; the time a client's word is taken in),
`crates/comm/file-offers` (tests), `crates/client/ctl` (a test's workaround removed),
`docs/client.md`, `docs/flakes.md`, `docs/lock.md`, `TODO.md`.

## Fault

Found in I32. A gift stepped again after its program had been busy elsewhere for longer than
its session's timeout ended `TimedOut`, although its client was there and had said so. A gift
counted its client's silence from the last time one of its own steps noticed the client's
count grow. It also checked that silence before it took in anything that had come meanwhile.
So the client's words during the pause sat unread, and the program's pause read as the
client's silence.

## Built

- **What came is taken in first.** A step takes in every frame already there before it judges
  anything.
- **The client's word is stamped when it is taken in.** The gift's step or anything else that
  pumps the session may take it in. The client's silence counts from its last word.
- **The clock runs only while the client owes an answer.** If nothing was out and the step
  sends, the waiting begins then. A client that has said it has everything sent is not silent
  while it waits for more.
- The `orionctl` fetch test from I32 no longer gives its program a 30 s timeout to step around
  this. Its program has the default 5 s and pauses for 5.6 s.

## Proof

`crates/comm/file-offers/tests/paused.rs`. The program's session timeout is 300 ms and each
pause is 900 ms.

| Test | Fails before (code at I33)? | Fault that fails it alone |
|---|---|---|
| Paused with chunks out: the client takes the window during the pause and says so; the gift completes | yes, 10 of 10 | what came is not taken in first |
| Paused with nothing owed: the client's word on the whole window is taken in by the session before the pause; the gift completes | no: the old code stamped the time its step noticed the count grow | waiting does not start the clock |
| A 2 MiB gift to a client that writes slowly lasts well past 300 ms with chunks always out; it completes | no, for the same reason | the client's word is not counted |
| `orionctl`: the I32 stall test, its program at the default 5 s and paused 5.6 s | yes (`Io(TimedOut)`) | — |

- In the first test the client starts its fetch but takes nothing until the program has paused.
  Nothing the client says can reach the gift before the pause, so the old code fails every run.
  An earlier version let the client run free, and the old code passed when the program's step
  happened to take in the client's first word just before pausing.
- The pause, abort, quiet and fetch tests ran 10 of 10 green.

## Two flakes in I32's tests, found by this gate

The first landing gate of this change failed in `quiet::a_fetch_given_a_limit_gives_up_on_a_quiet_program_saying_so`,
at load ~117-190. The test set its 400 ms give-up limit when the fetch began. The limit
therefore also counted the program's own start, which builds and hashes a 4 MiB file in a debug
build, and the load stretched that past 400 ms. The fetch gave up, rightly, before any byte.
The limit is now set once the file is under way.

`orionctl`'s stall test had the same shape. `--give-up 300` counts from the start by design, and
its program then stepped a gift that was already over. The program now takes an early end as
the end.

With a 600 ms start planted in the program, the old `quiet` test failed 5 of 5 runs and the new
one 0 of 5. The old `orionctl` test failed and the new one passes. Both are in `docs/flakes.md`.
