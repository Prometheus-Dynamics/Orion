# I137: The browser tests' key holds the browser behind its launcher

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I136

Read `AGENTS.md` and `docs/design.md` first.

## Why

orion-web-tests is keyed by its binaries since I136. Its tests start the browser by its
name on PATH (`firefox`, crates/testing/web-tests/src/browser.rs), and the keys held that
name's digest. On Fedora, /usr/bin/firefox is a shell launcher that runs the browser installed
under /usr/lib64/firefox. An update to the browser leaves the launcher's bytes the same, so the
key stayed while the browser changed.

The tests use no driver: they start the browser and nothing else from outside the tree besides
`sh` and `kill`, which are keyed already.

## Changes

- **For each browser name (`BROWSERS`) whose program on PATH is a script (`#!`), the keys also
  hold what `<it> --version` says (`program_version`).** It runs once per gate process for the
  script as it stands, and is memoized by its stat like `program_digest`. Here it says
  "Mozilla Firefox 158.0.1" in 0.25 s. A browser that is not a script is held by its digest, as
  before.
- **Self-test plants for what the tests read:**
  - built output in `web/` (`web/client/dist/orion.js`, committed);
  - the browser updated behind the same launcher, then another launcher;
  - `..` handed to a path (`std::path::Path::new("..").exists()`).

## Proved by

Self-test plants (scripts/lane-reuse.py), on orion-web-tests:

- **A file in `web/` changed** (I136): its source key and its binary key move.
- **Built output in `web/` changed:** its binary key moves.
- **The browser updated behind the same launcher,** with the same PATH: its binary key moves.
- **Another launcher in its place:** its binary key moves.
- **`..` handed to a path:** it is not keyed by its binaries. Only `.contains("..")`, a test of
  a string, is exempt.

Mutations, each failing the self-test 3 runs of 3:

| Mutant | Fails on |
|---|---|
| No version for a launcher (as I136) | the browser updated behind the same launcher: the key did not move |
| Any `".."` literal exempt | `..` handed to a path: keyed, but should not be |

The version mutant is also the fail-before: I136's keys held the launcher's digest only.

Keys self-test: 19.1 CPU-s (16.4 before the browser plant), 13 s wall at load 95, nice 10.

## Not covered

- **A browser rebuilt with the same version** (a distro rebuild) behind an unchanged launcher.
  Its key stays.
- **Files under `web/` that git ignores** (node_modules, package-lock.json) are not in the key.
  The tests read none of them; they read the committed sources and `web/client/dist`.
