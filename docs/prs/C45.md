## Build

A push after a failed gate should not be possible. Make it mechanical, with a pre-push hook or a
push script that refuses unless the gate passed on that exact commit.

## Built

- **A push script, not a hook.** The hooks of a git worktree live in the shared `.git`, so a hook
  installed for this branch would also apply to every other branch and checkout of the
  repository. The script is in the repository and is the documented way to push (`AGENTS.md`).
- **The stamp.** `scripts/gate.sh` takes the tree it checks when it starts: tracked and new
  files, as `git add -A` would commit them, written through a scratch index so the real one is
  untouched. When it passes, it takes the tree again.
  - If the tree is the same, the gate stamps it: an empty file named after the tree in the
    worktree's own git directory, under `orion-gate-passed/`.
  - If anything changed while it ran, the gate fails and says so.
- **The push.** `scripts/push.sh REMOTE BRANCH` fetches the branch and lists every commit not
  yet on it. It refuses, naming each one, unless every commit's tree has a stamp. Then it
  pushes `HEAD` to the branch. A stamp is keyed by content, so a gate run before the commit
  covers the commit made from that tree.
- **Self-test.** `scripts/push.sh --self-test` runs as a gate step. In a scratch repository it
  checks three cases:
  - an unstamped commit is refused, and the remote never gets the branch;
  - a stamped commit is pushed;
  - two new commits with only the last one stamped are refused.

## Proved by

- The self-test passes, and fails if the stamp check is removed.
- This commit itself was pushed with `scripts/push.sh` after the gate stamped its tree.

## Different from the brief

- **A test fixed on the way.** `connect/tests/connect.rs`,
  `a_tool_with_a_key_signs_its_session_on_a_link`, slept eight heartbeats so that the board would
  end its last session on the link before the next one began. Under the gate's load that was not
  long enough: the next signed hello went unanswered, and the client said the board takes no
  signed session. The test board now reports how many sessions it has open, and the test waits
  until that is none, for up to 20 s.
