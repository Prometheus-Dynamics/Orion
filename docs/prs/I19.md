## Build

CI's gate job on the I18 push failed one test:

`orion-node-app` `files.rs` `a_push_that_is_interrupted_goes_on_from_where_it_was`:
`only 0 bytes were kept`, after 10.1 s, which is the test's wait for what the node kept.

The push had failed at once, with nothing sent. The test's `push` helper tries again while node
logic is not yet serving files (`Unavailable`), as on a slow machine just after it starts. Every
try used the same source. The `Failing` source lets its first pass through, which is the
sender taking the digest, and fails reads past 400 KB from then on. The second try's digest
pass was therefore failed at 400 KB, before a byte was sent. The `Lying` source in
`a_file_that_does_not_match_its_digest_is_refused` counts its passes the same way: on a second
try it would lie in the digest pass as well, and the digest would match.

Not reproduced in 50 runs on 1 and 4 cores busy with the whole test run: there node logic was
always serving files by the first push.

## Built

- The helper takes a function that makes the source, and makes it again for each try, as a
  sender that tries again reads its file again.

## Proved by

- With node logic started 300 ms late, so the first try is always refused: the old test fails
  with nothing received; the new one passes. Both tests in `files.rs` pass.
