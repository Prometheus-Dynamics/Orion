# C65: The shell test's flake fixed by its cause: a refusal is matched to its request

- **Status:** done
- **Group:** C (comm core)
- **Wave:** 19
- **Needs:** C52

## Why

`with_a_login_helper_the_helper_starts_the_shell` failed once in the D16 gate, "not opened on a
terminal", and was left open in `docs/flakes.md`. A flake is a bug, the test's or the code's.

## Found

It runs only with `--features login-helper`. Under full load, with the feature, it failed once
in 60 runs, now saying what it heard: `Refused(Some(NotFound))`.

The test reads a shell's output to its exit and gives credit for each piece, as a client must. A
shell that has exited is gone from the service, so credit for it is refused, `not found`: right,
since there is no shell to give it to. Under load the credit was sent after the shell's last
output and reached the comm core after the exit, so its refusal was the next thing the test
heard. The test took the next thing heard as the answer to the next shell it opened, and never
looked at which request a refusal answered (`Refusal.request_seq`).

The code is right; the test was wrong. The runs once said not to reproduce it most likely ran
without the feature, and so ran nothing.

## Changes

- `crates/comm/shell/tests/shell.rs`: the test client keeps the request the last refusal
  answered, and opening a shell skips refusals of other requests.
- The test sends credit for the exited shell itself before it opens the next, so the order that
  failed under load happens on every run.
- `docs/flakes.md`: the entry has its count, cause and fix, and says the earlier runs were not
  of the test.

## Proved by

- With the skip undone, the test fails 5 runs of 5: the order is now forced, not left to load.
- The whole `orion-shell` test binary with `login-helper`, 120 runs under full load: all pass
  (before: 1 in 60 failed).
