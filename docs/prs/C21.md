# C21: Orion's reader slots in an adopted table

**Status:** done

**Group:** C. Comm core

**Wave:** 18

**Needs:** C16

**Runs:** cloud

Read `AGENTS.md` and `docs/design.md` first.

## Changes

`crates/client/buffers`, `docs/client.md`

## Build

An adopted buffer topic's hold table is the program's: it has readers Orion did not place.

1. **`reader_slots` of zero is refused** by `adopt_buffers`, `TopicError::Invalid`. Under C16
   zero meant "any slot", which on an adopted table means Orion may land on a reader of the
   program's own.
2. **`poll` empties only slots it filled.** Before, each change removed whatever was in the
   slot first, so a program that put its own reader in one of Orion's slots lost it silently.
3. **A clash is said.** When a subscriber's slot is taken, the program's reader stays, that
   subscriber is never given the pool (no holds are sent to it), the other changes are still
   made, and `poll` returns `TopicError::Ring`.

## Built

As above.

## Proved by

`crates/client/buffers/tests/adopt.rs`, `orion_never_takes_a_slot_that_is_the_programs_own`:
zero slots is refused; with a reader of the program's own in Orion's slot 1, `poll` returns
`Ring`, the program's reader is still in the table, and Orion's subscriber never gets `pool()`.
With `poll` emptying the slot unconditionally, as before, the test fails: the program's reader
is removed and no error is said.
