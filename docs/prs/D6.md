## Build

## Proof

An interrupted transfer resumes.

## Built

- `orion-files`: `Files::push(destination, source, progress)` sends a file in chunks of up to
  32 KiB with at most eight in flight, commits, and returns how it ended. `Files::pull` asks
  the board to fetch a file itself and follows it.
- A push resumes without the caller keeping anything: the transfer's number comes from the
  file's digest and its destination, so beginning it again is answered with how much the board
  already has. After a broken connection: reconnect, push again.
- Both work on any address.

## Proved by

`tests/files.rs`, against a receiver written in the test: a 1.1 MB file is pushed, the session
is cut a third of the way in, the client reconnects and pushes again. The second try is told
where the board is and sends exactly the bytes that were missing, counted at the receiver. Run
on the board's socket and across the network. A pull commits with none of the file's bytes
crossing the session; a wrong digest is rejected and not put in place; a refused destination is
an error.

## For E (the receiver)

What the client expects, which the wire's comments leave open:

- `FileBegin` and every `FileChunk` are answered with `FileStatus` carrying `received`. Those
  answers are what paces the sender.
- A `FileBegin` with a known number but another size, digest or destination starts over.
