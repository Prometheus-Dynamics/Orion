# I123: The lane keys' self-test within CI's CPU bound

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I122

Read `AGENTS.md` and `docs/design.md` first.

## Why

CI went red on I121 (cd513f41, run 45979905635). In gate (main), the lane keys' self-test went
past its CPU bound: 60.5 CPU-s against 60, in 29 s wall. I121 ran each of its 33 cases as a
process of its own, all at once. Locally that cost 16 to 17 CPU-s. On CI's 4-core runner,
which costs about 2.2 times as much per process, and with 33 processes sharing 4 cores, it
went past 60.

## Changes

- **The cases run inside the self-test's own process,** not as 33 processes. Each case still
  has its own copy of the tree, and `ROOT` points at that copy while the case runs.
  - The copies are hard links. A file a case changes is written as a new file, never through
    the link, so no other copy sees the change.
  - Each process cost about 0.1 s to start and compile, and about 0.07 s to parse the
    metadata listing. That was more than the keying.
- **Four workers, forked from the self-test,** take the cases between them. One worker for all
  of them took 45 to 57 s at load 115 to 162.
- `--explain-binary` and the self-test share `explain_binary`. `--self-test-plan` is gone: the
  plan cases run in a worker's copy, and run by hand they would have changed the real tree.

## Proved by

Mutants, 3 runs each, all red:

- the seven from I121;
- the root manifest left out of the key (red: "the root manifest: the key did not move");
- a change written through the hard link (red: the plan fails, because the shared test file
  reads as changed in every copy).

## Measured

At nice 10:

| Version | Wall | CPU-s | Load |
|---|---|---|---|
| I121, a process per case, own listings | 13 to 30 s | 25 to 33 | 79 to 91 |
| I121, a process per case, shared listing | 9 to 22 s | 16 to 17 | 83 |
| One process, cases one after another | 45 to 57 s | 12.1 to 12.6 | 115 to 162 |
| This change: 4 forked workers | 8.5 to 9.3 s | 11.1 to 11.5 | 83 to 91 |
