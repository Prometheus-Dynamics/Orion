# C18: The caller in a claim

**Status:** done

**Group:** C. Comm core

**Wave:** 18

**Runs:** cloud

Read `AGENTS.md` and `docs/design.md` first.

## Changes

`crates/core/msg-actions`, `crates/core/check`, `crates/node/reply`, `crates/node/action-list`,
`crates/client/actions`, `crates/client/executor`, `crates/testing/stubs`

## Build

A program handed a run is told who asked for it. `Claim` gains `caller` (appended after `;`, so a
host that does not send it is read as empty), named as the audit log names a caller:
`local:<uid>`, `operator:<key>`, `peer:<node>`, `device:<name>` or `anonymous`.
`Request::Run` carries it to the program.

## Proof

A provider in another process is handed a run from a program on the board and answers with the
`caller` it was given: `local:<uid>` of the test's user.

## Built

- `Asked::principal()` in the `reply` crate names the caller from what the comm core passed node
  logic; the action list puts it in each `Claim`.
- `impl Display for Principal` in `orion-check` names a principal the same way, for what builds a
  claim from a session (the stand-in routers).
- The recorded `ACTION_CLAIM` vector gained its trailing field; the bytes before it are
  unchanged.

## Proved by

`an_action_from_another_process_runs_and_is_refused_by_its_policy` (orion-node-app), and the
node-app suite 60 runs in a row with the executor fix below (the first 40, before it, failed
once, on that race).

## Different from the brief

- There was no brief: written with the PR, from the plan given to the consumers.
- A run forwarded from another node names that node (`peer:<node>`), not the person who asked
  there: the forwarding node is who asked this one.
- The node-app loop turned up a race in the client's executor loop, fixed here: a workload that
  started and ended well before the executor next looked at its inventory was never in one, so
  nothing was reported and node logic left it `Starting` for good (1 run in 40 of
  `a_workload_that_fails_is_started_again_and_one_that_must_not_is_left`). What was started
  since the last look and is not in the inventory is now reported gone. The executor test has
  the case, and fails without the fix.
