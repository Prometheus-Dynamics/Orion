## Why

The programs that use both Orion and the device library are moving to the device library's
`next` at `a6251ecf`. Orion moves its pins there so that all of them land on one pair of revs.

## Built

- **Cargo.toml.** The seven `shm-*` workspace dependencies come from the `.git` URL, at
  `a6251ecfb815752880f399e4e137634d022d4a2d`. `7b4fdb25` is an ancestor of that rev.
- **The lockfiles.** Only the `source` lines change. No package is added, removed or moved to
  another version.
- **No byte Orion builds changes.**
  - Nothing under the device library's `shm` directory differs between `7b4fdb25` and
    `a6251ecf`.
  - The seven crates' path dependencies all stay inside `shm`.
  - The workspace `Cargo.toml` is byte for byte the same at both revs.
- **Nothing else Orion takes from the device library changes.** Orion takes only these seven
  crates; the device library's pin check counts 7 of its crates in Orion's lock and no other.
  The device library's contracts that changed between the two revs are none of Orion's. Orion's
  interface level stays 6.

## Proof

- **The device library's checkers**, from `a6251ecf`, on `Cargo.lock`:

  | | its pin check (at `a6251ecf`) | its one-source check |
  |---|---|---|
  | Before | fail: 7 of 7 crates not at the pin | pass: one copy of each of 7 |
  | After | pass: all 7 at the pin | pass |

  Both example lockfiles also pass both checks.
- **The sources.** `git diff --stat 7b4fdb25 a6251ecf -- shm/ Cargo.toml` is empty.
- **`cargo metadata --locked`** resolves the new lock.
- **The landing gate passed.**
