# I96: A note for porting a program from dev to next

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I94

Read `AGENTS.md` and `docs/design.md` first.

## Changes

`docs/from-dev.md` (new), `docs/README.md`, `docs/lock.md`, `TODO.md`.

## Why

Programs built against the `dev` branch are being ported to `next`. Each one needs the same
answers: what became of the control-plane client, the records with typed config, status
entries, streams and the NT4 crate, and what the program does instead.

## Built

`docs/from-dev.md`: group by group, each thing a `dev` program used and what it is on `next`,
marked as there, as the program's own to do, or as a gap. It covers crates, features and
sockets; registering; resources; reading and writing state; workloads and their config;
actions; status entries and streams; a device library's devices; the board's vital signs;
other boards; NT4 and capture times; and security for a program on the board. The gaps are
listed together at the end: seven.

It names no program. It was written from `next`'s code and docs and from a read-only survey
of one `dev` program's calls.

## Not checked

Nothing in it was run against a ported program. Three things it says it did not check: the
command line's verbs one by one, the security rules line by line, and the relay of TCP to
another board. A port will find what it got wrong; corrections go into the note.
