## Why

A client that pushes to a receiver doing long device work at the commit has to set
`Reply::Alive` or `Within` (I67). Its test needs a commit answered later than twelve timeouts,
while the board goes on answering the client. The stand-in receivers answer `FileCommit` as
they handle it and can't hold the answer back. A receiver that held it by blocking would stop
its pings too, which is a different failure.

## Built

- **`TestBoard::hold_commits(prefix, hold) -> HeldCommits`.** A thread connects to the board's
  socket and becomes the receiver for `prefix` through the real `Files::sink`. It retries while
  node logic is starting.
  - It answers `Begin` and each `Chunk` at once.
  - At `Commit` it checks the digest and queues the answer (`Committed`, or `Rejected` with
    why) for `hold` later.
  - It goes on calling `Sink::next` every 20 ms meanwhile, so its session stays pumped and the
    comm core and node logic keep answering the pushing client.
  - Dropping it stops the thread. `answered()` counts the commits it has answered.
- **The crate stays test support.** `orion-test-board` is `publish = false` and no shipped
  build depends on it. It now asks for `orion`'s `files` feature.

## Proof

`a_commit_answered_after_twelve_timeouts_ends_committed_under_alive_and_timed_out_otherwise`
(`tests/board.rs`):

- **The setup.** Two pushes of a 50 kB file run at once, from two clients with
  `Options::timeout` 400 ms, to a receiver that holds commits `12 × 400 ms + 1.5 s`.
  - Until every byte is there, each client waits under `Reply::Within(20 s)`, so a slow moment
    while sending is not what ends it.
  - After that, one client switches to `Reply::Timeout` and the other to
    `Reply::Alive { ceiling: 30 s }`.
- **What it checks.** The first ends with a timed-out `ClientError::Io`; the second ends
  `Committed`, no sooner than the hold.
- **It passes 3 of 3**, in about 6.4 s each.
- **Mutations, 3 runs each, every run failing:**

  | Mutation | Result |
  |---|---|
  | The receiver ignores `hold` | The `Timeout` push ends `Committed` |
  | `Pushing::step` bounds the commit by twelve timeouts under `Alive` too | The `Alive` push times out at 4.8 s |

- **The landing gate passed.**
