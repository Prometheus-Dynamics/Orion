## Built

- `crates/comm/ssh-sftp` (`orion-ssh-sftp`): the sftp subsystem as a helper process, on
  `russh-sftp` 3.0.1. Protocol version 3 with OpenSSH's `posix-rename`, `fsync` and
  `hardlink` extensions: open, read, write, close, stat, set attributes, list, make and
  remove directories, remove, rename, links, real path. `orion_ssh_sftp::main` is the whole
  program, for a binary to call when started with `ssh-sftp`.
- `orion-ssh`: subsystems. `SshConfig::subsystems` names a program for each; a client that
  asks for one gets it in place of a shell, started by the session helper after it has
  become the user. So the sftp process is the user, and the kernel decides what it may do.
- `orion-comm-app` feature `ssh-sftp`: the comm core's own program, started with
  `ssh-sftp`, is the `sftp` subsystem.

## Proved by

`cargo test -p orion-ssh-sftp`, with OpenSSH 10.2's `sftp` and `scp` as the clients:

- `sftp`: a 3 MiB file up and down whole, a file down, a directory made, a file renamed,
  a mode changed, a link made and read through, a listing with sizes, a file and a
  directory removed. The files are the user's. A file that is not there, a file the user
  may not read and a directory the user may not write to are each refused and said.
- `scp`: a 5 MiB file up and back, the same bytes; a directory with what is in it, with
  `-p` keeping a file's mode and time; a file that is not there makes nothing.
- A board without the subsystem refuses `sftp`.

If OpenSSH is not installed the tests print that and pass.

## Different from the brief

- `orion-ssh` gained subsystems in general, not sftp alone: the SSH server does not know
  what sftp is.
- `orion-ssh-sftp` depends on `orion-ssh` only for `orion-sftp-helper`, a binary that is
  both helpers, which the tests start.
- A name that is not UTF-8 is left out of listings: the protocol library carries names as
  text.
