# I114: One nice level for all heavy work

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I113

Read `AGENTS.md` and `docs/design.md` first.

## Why

On a machine the projects share, work at nice 19 gets a sliver of a processor beside builds
at nice 10: their weights are 15 and 110. Levels across the projects were mixed, from 0 to 19,
so no one's minute could be measured or kept. All heavy work now runs at nice 10 (2026-11-24).

The gate itself ran some lanes a level lower than the rest. Its unit started at 10, and inside
it the feature matrix and the device size builds ran at `nice -n 10` more: 19. That was so the
size gate's links got the processors first (I21), on a machine Orion had to itself.

## Changes

- **`scripts/work-env.sh`** holds the one level, `GATE_NICE=10`, and `at_gate_nice`, which puts
  a shell there: absolutely (`renice --priority`), not relative to where it started. A shell
  started above it fails, saying so, rather than run lower and measure wrong: a process may not
  lower its own level.
- **`scripts/gate.sh`, `scripts/run-gate.sh` and `scripts/ab-target.sh`** use it. Nothing inside
  the gate sets a level of its own. `run-gate.sh` and `ab-target.sh` record the level beside the
  load.

## Proved by

- **`at_gate_nice`**: started at nice 0, it ran at 10; started at 15, it failed, naming both
  levels.
- **The gate**, every lane run in full (the gate's script changed); see Measured.
