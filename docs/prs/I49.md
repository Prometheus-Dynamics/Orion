## Fault

Two rules, checked against the gate after a finding in another repository (a filtered step
matched nothing, ran nothing and was recorded as passed):

- **A selection that matches nothing must fail.** It passed here.
  - `feature-matrix.sh` lists its builds through a process substitution, which hides the
    listing's status. A failed listing, or a crate name that matches no crate with features,
    gave no builds: `feature matrix: 0 builds, 0 failed`, exit 0.
  - `lane-reuse.py plan` with no items printed `0 of 0 reused`, and `status` then said `passed`
    and recorded a full run.
- **A change to what measures must measure everything again.** The lanes' keys held every such
  file. The size gate's key did not hold `size-gate.sh`, which chooses what is built and how
  (profiles, flags, toolchains). A change there could reuse a measurement made the old way.
  Its limits were never at risk: each run judges against today's.

## Built

- **`feature-matrix.sh`** fails when it selects no build, naming the crates asked for.
- **`lane-reuse.py`**: `plan` fails for a lane with no item, and `status` for a state with no row.
  Neither records a pass. A lane left out on purpose is `--drop LANE:WHY`, said as `not-run(WHY)`.
- **`size-key.py`** keys `scripts/size-gate.sh` in every build's key. The size gate's self-test,
  which the gate runs, plants it and checks that every build's key changes.

## Proof

- **Nothing selected, through the gate.** With the matrix's selection planted to match nothing,
  `scripts/gate.sh --part matrix` failed: `feature matrix: no build selected: nothing was
  checked`, then `FAILED: feature matrix`. The same plant on the old script passed with `0 builds,
  0 failed`. `lane-reuse.py plan matrix STATE` with no items fails, saying the lane selected
  nothing.
- **What measures, every key.** Each file planted in turn, the keys of the 108 matrix builds, the
  10 other-system checks and the device size compared before and after:

  | Planted | Matrix | Other systems | Devices |
  |---|---|---|---|
  | `gate.sh` (the lane map) | 108 | 10 | 1 |
  | `lane-reuse.py` | 108 | 10 | 1 |
  | `size-key.py` | 108 | 10 | 1 |
  | `feature-matrix.sh` (the matrix's definition) | 108 | 0 | 0 |
  | `same-features.py` | 0 | 10 | 0 |
  | `device-size.sh` (its budgets) | 0 | 0 | 1 |
  | `examples/stm32g4-device/size-baseline.txt` | 0 | 0 | 1 |
  | `rust-toolchain.toml`, root `Cargo.toml` | 108 | 10 | 1 |

  The tree put back gave the same keys.
- **The size gate's script.** The size gate's self-test passes with the new plant. With
  `size-gate.sh` taken back out of the key, it failed: `scripts/size-gate.sh left the key of c as
  it was` (and of `a` and `v`).
- **The landing gate passed** with every lane run in full: these scripts are in every lane's key.
