## Build

A program told to stop a run could not tell a caller's request from its caller dying, the
deadline passing, or node logic going away. A program that holds something for a caller treats
these differently.

1. `Cancel` gains an appended reason: 0 not said, 1 asked, 2 caller gone, 3 deadline,
   4 stopping. A body without it reads as 0.
2. Node logic sets it. What a caller says is not kept, so a caller cannot claim a deadline.
3. A run carried to another node keeps the carrying node's reason there.

## Built

- `CancelReason`, an open enum, appended to `Cancel`.
- Action list:
  - a caller's `Cancel` goes on as `Asked`, unless it comes from a peer that says why;
  - `gone` sends `CallerGone`;
  - `tick` sends `Deadline`;
  - new `stopping` cancels every run with `Stopping`, ends each for its caller as cancelled
    ("node logic is stopping"), and keeps nothing for starters.
- Action forward: a caller's cancel is `Asked`. A caller gone, or every caller forgotten when the
  comm core goes, is `CallerGone`. The link carries the reason to the other node.
- Node logic: `serve` takes the stop future. When asked to stop while connected, it cancels
  every run with `Stopping` before it lets go of the session. Before, the session was dropped
  under the runs.
- `orion-actions`: `Request::Cancel` carries `reason`. `Run::cancel` sends `Asked`.
- `orion-device-actions`: `Heard::Cancel` carries the reason as its byte, 0 when absent.
- Test stub router: `Asked` and `CallerGone`.
- `examples/mcu-template`: its cancel match takes the new field.
- Docs: client.md (the reasons) and comm.md (who sets them).

## Proved by

- `orion-action-list` tests:
  - a caller's own reason is replaced by `Asked`;
  - `CallerGone` on `gone`, `Deadline` on `tick`;
  - `another_nodes_reason_for_a_run_it_carried_is_passed_on` (a peer's `CallerGone` is kept,
    and a peer's unsaid reason becomes `Asked`);
  - `node_logic_stopping_cancels_every_run_and_says_why` (detached runs too).
- `orion-node-app` forward test: a cancelled run on the other node hears `Asked`. A caller that
  goes with a run under way there makes its program hear `CallerGone`.
- `orion-node-app` actions test: node logic stopping with a run under way ends it for the caller
  as cancelled, "node logic is stopping". The test's node logic is now stopped as a signal would
  stop it, not dropped.
- `orion-device-actions`: a cancel's reason reaches the device as 3.
- Wire vector `ACTION_CANCEL` is now `0702`.
- Not vacuous:
  - forwarded caller-gone sent as `Asked`: the forward test fails;
  - a peer's reason not kept: the forward test and the unit test fail;
  - node logic not cancelling on stop: the actions test fails.

## Different from the plan

- Forwarded runs are not cancelled with `Stopping` when node logic stops. The link to the other
  node closes with it, and that node sends `CallerGone`, which is what its program needs.
