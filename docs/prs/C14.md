## Build

- Uptime, memory, CPU and temperature, published on change or on demand.
- Every component's state as a topic. This replaces metrics export.

## Proof

Nothing is sampled while nobody watches.

## Built

- `orion-self-status`: `SelfStatus::start(comm, broker, source, interval)` declares `orion.host`
  (uptime, memory total and available, processor share, hottest temperature) and `orion.comm`
  (sessions, the server's counters, topics, ring bytes). `status.part(name)` gives a `Part` whose
  `report(&Status)` publishes `orion.state.<name>`, so a link's or a dial's backoff state is a
  topic. `ProcSource` reads `/proc` and `/sys`; `HostSource` lets a test or another board stand in.
- The sampler task is woken through a `TopicWatch` and sleeps on nothing but that while neither
  topic has a subscriber. The first subscriber gets a reading at once; then one per interval; only
  fields that changed are published.
- The broker gained topics the comm core publishes itself (`Topics::declare_internal`,
  `LocalPublisher`, `Writing`, which the proxy now uses too). A client can't declare over one or
  open it to write, and it is not removed when its last subscriber leaves.

## Proved by

`crates/comm/self-status/tests/status.rs`: 600 s of paused time with nobody subscribed and a
connected client watching something else: 0 readings. Then 1 at once on subscribe, 1 per
interval, 0 after the last subscriber leaves or vanishes, lanes counted to show only changed
fields were written. `orion.comm` is read without touching the host. A part's state is there for a
late subscriber and an unchanged report writes nothing.

## Not carried from dev

The host-facts document (model, serial, addresses) is not here: the hello document (C8) carries
facts other programs publish as `hello.<fact>` topics, and Orion invents none. Metrics export is
gone, as designed.
