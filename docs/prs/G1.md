## Built

- `crates/comm/ssh` (`orion-ssh`): an SSH server on `russh` 0.65.1 with `ring` (no
  aws-lc, no OpenSSL, no C). One family of key exchange, two ciphers, public keys only.
- Logins go through the check: the client's ed25519 key is looked up in the trust store,
  and `Check::decide` is asked `What::Login` under `Admits::OPERATOR`. An operator trusted
  with everything gets in; with security off anyone does, with a key or none. The session
  code is only reachable with the `Checked<Login>` the check made.
- A shell as the user: each session runs in a helper process (`helper.rs`, binary
  `orion-ssh-helper`, or the comm core's own binary started with `ssh-session`) that takes
  the terminal, becomes the account with all its groups, checks that it has and that there
  is no way back, and becomes the shell. Commands, a login shell on a terminal, window
  changes, input, output and errors apart, exit codes and signals.
- The host key is made on the first start; a broken one is moved aside and replaced; one
  that cannot be kept is used for the run.
- Limits before a login: `ssh.max_unauthenticated` connections, each with `ssh.login_ms`.
- `orion-comm-app` feature `ssh`: settings `ssh.listen`, `ssh.host_key`, `ssh.helper`,
  `ssh.max_connections`, `ssh.max_unauthenticated`, `ssh.login_ms`.

## Proved by

`cargo test -p orion-ssh`, with OpenSSH 10.2's `ssh` as the client:

- An operator trusted with everything logs in with its key and runs commands as the user:
  output, errors apart, exit code 7, the user's id, name, home and shell, 100,000 bytes of
  input, 200,000 lines of output in order, a command ended by a signal reported as 143.
- A key nobody enrolled, an operator that may only read, and no key are each refused with
  `Permission denied`; so are an account that is not there and one the server cannot become.
- `ssh -tt`: a login shell on a terminal (`$TERM`, a `/dev/pts` name, `test -t 0`, a name
  that starts with a dash), exit code 3; a command on a terminal.
- With security off a stranger's key and no key at all both get in.
- The host key is kept across a restart (a client with strict checking gets in), a file
  that is not a key is moved aside and replaced, and a key that cannot be written still
  leaves the way in open.
- Three connections that say nothing fill the places before a login and the next is turned
  away; each is closed within the login time; one that is logged in stays past it.

`cargo test -p orion-comm-app --all-features`: with `ssh.listen` set the comm core says
`SSH-2.0-`, has made its host key in the state directory, and closes the port when stopped.

If OpenSSH is not installed the tests print that and pass.

## Different from the brief

- No `authorized_keys` and no passwords, which dev's note had: the design gives logins to
  the one check, and the trust store is where a board says who may do what.
- The helper process is not in the brief. Becoming another user has to happen in the
  process that will be them, between its start and the shell's; a helper does that with no
  `unsafe` in the comm core.
- The path where the comm core is root and the session becomes another account was not
  run: the tests run as an ordinary user, who can only be let in as themselves. It is
  written and checked in the helper; G6's board run is where it is run as root.
- The server runs on the comm core's thread, as the design says, with the question of a
  big copy delaying a topic left to be measured on the test board.
