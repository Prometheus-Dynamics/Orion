## Built

- `web/client/src/orion.ts`: one file, no dependencies. `Orion.connect(url, name)` opens a
  WebSocket with the subprotocol `orion.v1` and says hello. `subscribe(topic, onsample)` gives
  a `Subscription` (declaration, status, close). `declare({...})` gives a `Publisher`
  (`publish`, `subscribers`, the subscribers' `request`). `run(action, onprogress)` gives the
  `Result`, or throws `Refused` with the board's code. It carries its own frame, CRC-32C and
  postcard codec, and keeps the session alive with pings.
- `web/client/dist/`: the build (`orion.js`, `orion.d.ts`) is checked in, so a page uses it
  with one `import` and no build step. `build.sh` rebuilds it and notes the source's digest.
- `orion-stubs`: the stand-in board also listens for WebSocket (`Board::websocket()`).
- `crates/testing/web-tests`: the proof.

## Proved by

`cargo test -p orion-web-tests`:

- A headless browser loads a page that uses the client against a comm core. It reads a topic
  a Rust program publishes (declaration, status, samples in order with their times), declares
  a topic and publishes three samples a Rust subscriber reads (times, values, the depend
  flag, and the subscriber's request reaching the page), runs an action a Rust program does
  (progress and output), and is refused code 8 for an action that is not there.
- `dist/` is the build of the source beside it (digest check), imports nothing, and is under
  32 KiB.

If no browser is installed the browser test prints that and passes.
