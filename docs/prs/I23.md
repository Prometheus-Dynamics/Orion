## Build

`a_resource_is_said_again_only_once_its_actions_are_back` failed once, in a gate part run alone
while other repositories' gates ran beside it (load ~78):

```
listen: Os { code: 98, kind: AddrInUse, message: "Address already in use" }
the board starts: RecvError
```

The test stops its board and starts it again on the same port. The board had listened on port 0,
so its port came from the kernel's ephemeral range (32768-60999 here). While the board was down,
the kernel could hand that port to any socket on the machine, an outgoing connection's own end
among them. `SO_REUSEADDR` does not help when another socket holds the port. Every test that
starts a board again on its port had the same gap.

## Built

- With no port named, a board listens on a port below the ephemeral range (from 16384 up to the
  range's low end, read from `/proc/sys/net/ipv4/ip_local_port_range`). The kernel never hands
  those ports out by itself, so only a socket that names the port can take it. It starts at a
  point taken from the clock and the process, walks every port in the span, and binds the
  carrier itself, moving to the next port on `EADDRINUSE`. There is no gap between choosing a
  port and listening on it.
- A board named a port listens there as before.

## Proof

`orion-stubs` `port.rs` `a_boards_port_is_never_one_the_kernel_hands_out_by_itself` starts
three boards, checks that each port is below the ephemeral range, and starts each again on its
port.

| Stub | Test |
| --- | --- |
| Port 0, as before | `FAILED`: `port-one listens on 40825, in the ephemeral range from 32768` |
| This change | `1 passed` |

The `facade` tests then passed three times out of three with this change (7 of 7 each).
