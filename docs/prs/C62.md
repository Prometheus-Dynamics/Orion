# C62: Roles started before Orion wait for it, and two flakes fixed by their cause

- **Status:** done
- **Group:** C (client)
- **Wave:** 19
- **Needs:** C61

## Why

Two tests passed only when they were run again, so each had a bug, and `docs/flakes.md` now lists
them:

- **The drills' `orion_dies_whole_and_takes_back_what_kept_running`.** It killed Orion before
  its subscriber role had connected. The role's own connect loop gave up after 10 s of a socket
  with no listener. C61 removed the reason for that loop.
- **`alive.rs`'s `a_node_silent_for_its_idle_time_is_gone_and_silent_for_says_so`.** It timed
  silence from the wrong moment.

## Changes

- **The drills' roles connect with the library's connect**, which keeps trying. Their loop of
  their own, which gave up after 10 s, is gone.
- **New drill `roles_started_before_orion_wait_for_it_and_flow_when_it_comes`:**
  - The publisher and subscriber roles start first, and nothing else runs for 12 s, longer than
    the old loop's limit.
  - Neither may have failed or ended.
  - Then Orion starts, and 200 values must reach the subscriber.
- **`orion_dies_whole_and_takes_back_what_kept_running`** waits for the publisher's first
  publish and the subscriber's first value before it kills Orion. The values it counts while
  Orion is away can only flow between roles that are both in.
- **`alive.rs`** measures `silent_for()` when the session is found gone. Silence counts from the
  last frame heard (the welcome), not from the question that came after it. The bound is the idle
  time to the idle time plus 2 s, far below the 30 s ceiling, so it is still the idle rule that
  ended the session.
- **`alive.rs` shared one socket path between two tests**, `orion-alive-silent-<pid>`
  (`a_comm_core_silent_on_the_boards_own_socket…` and the idle-time test). They run side by side
  in one process, so each could take the other's client.
  - That was the `ConnectionReset` seen once in the C59 gate.
  - Since C61, under load, it hung: the second client waits in a backlog that the other test's
    fake node, which accepts once, never takes from.
  - Each fake node now gets a path of its own, with a counter.
  - Every test file was scanned for the same mistake (the same literal name given to a helper
    that names a socket or directory). This was the only one.
- **`docs/flakes.md`:** each rerun-to-green with its count, cause and fix. None is open.

## Proved by

- **The new drill.** With the roles' old loop put back, it fails: a role reports
  `failed No such file or directory`.
- **On a machine with every CPU the tests use held busy:**
  - `orion_dies_whole_and_takes_back_what_kept_running` passed 20 times in 20;
  - `alive.rs` failed 1 time in 40 before the fix, and hung in one later run on the shared
    path. With both fixed, it passed every run of 80.
