## Build

- `<node>/<topic>` carried into a local copy of the ring, only while someone asked.
- Frame times aligned using time sync.

## Proof

Two comm cores: the subscriber code is identical to same-board.

## Built

- `crates/comm/topic-peers` (`orion-topic-peers`): `TopicPeers::start` and `with_clock`,
  `Resolve`, `Reach`, `Table` and `PeerNode` for where nodes are, `LinkStats`. A link is this
  comm core as a client of the other, over `orion-tcp`.
- `orion-broker`: a topic may belong to another node (`Topic::node`); a subscription to one
  is taken when something carries them, and waits; `Topics::declare_mirror` and
  `mirror_lost` are how what carries it gives it a ring and says its publisher is gone;
  `TopicWatch::waiting` tells of a subscription that waits.
- `orion-comm-app`: feature `topic-peers`, on by default, and the setting `peer.nodes`.

It rests on F2: the other node sends samples to this one with its outbound part.

## Proved by

`tests/across.rs`: two comm cores, each with a socket and a network port, and the real client.

- **The subscriber code is identical.** One program on the board that has the topic
  subscribes to `tank.level`, one on the other board to `right/tank.level`. The same reading
  function gives both the same 200 samples, values and times, and the same latest value.
- **Only while someone asks.** The publisher counts two subscribers; a second program on the
  far board does not make it three; when one far program leaves it is still two; when both
  have left it is one.
- **Before the topic, and through a restart.** A far subscriber asks before anyone has
  declared the topic and waits; the topic is declared and it is live. The other node is
  stopped, comm core and all: the subscriber is told the publisher is gone and can still
  read the latest value. The node comes back on its port and its publisher declares again:
  the subscriber, having done nothing, is live and reads what is published next.
- **Frame times.** With this board's clock five seconds ahead of the other's, a frame stamped
  on the other board arrives carrying this board's time for the same moment, to within
  20 ms.
- A node nobody knows the place of leaves its subscriber waiting, and the board goes on.

Unit tests of the clock comparison: clocks that agree are left alone, five seconds either way
is measured exactly, the time the other node held the request is not counted, and nonsense
does not overflow.

## Different from dev

Dev's remote sessions were the client's: a program connected to the other node itself and had
separate code for remote topics. Here the program's comm core does it and the program cannot
tell.

## Limits

- A topic of shared buffers does not cross: a buffer number means nothing on another board
  (the design says video off the board is an ordinary bytes topic).
- A node is found only through `peer.nodes`. What discovery finds is not used yet.
