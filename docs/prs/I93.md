# I93: orion-recovery's size for a board is checked before a release, not on every change

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I92

Read `AGENTS.md` and `docs/design.md` first.

## Changes

`scripts/size-gate.sh`, `docs/lock.md`, `TODO.md`.

## Why

No image carries the separate `orion-recovery` binary. Its limit for a board had 4,488 bytes
left, and most of its code is shared with `orion`: the next change to that code would have
needed a raise, with a table, for a file nothing ships. I79 already raised it once.

Recovery mode itself, the comm core opening the recovery way in when it cannot start, is part
of `orion` and is not touched by this.

## Built

- `orion-recovery` for a board (aarch64) is built and held to its limit by
  `scripts/size-gate.sh --release`, as the armv7 and riscv64 files are, and not on every
  change. The table of boards has a column for it.
- **What still runs on every change:** `orion-recovery` for this machine, built and held to
  its limit; the comm core's tests built as the recovery binary builds it; and the binary's
  own tests. `orion` for a board is checked on every change as before.

This takes one check off every change. It was decided, not slipped: the limit is looked at
again when an image is to carry the file, with what could come out of it (`docs/prs/I92.md`).

## Tests

`scripts/size-gate.sh --self-test` passes. The gate's size lane says `orion-recovery for a
board (aarch64-unknown-linux-musl): before a release only`.
