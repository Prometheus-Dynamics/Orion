# I135: Every string of a source is read as the compiler reads it

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I134

Read `AGENTS.md` and `docs/design.md` first.

## Why

`reaches_outside` (scripts/lane-reuse.py) finds the strings of a package's sources with one
regex over the whole file. That pairs quotes in order, so a raw string with a quote inside it
pairs every later quote of the file with the wrong one. For example, the page in
`crates/testing/web-tests/tests/client.rs` is `r#"<meta charset="utf-8">..."#`.

After such a string, a path outside the crates goes unseen. The package then counts as reading
nothing outside the crates: its keys leave out what it reads, and it can be keyed by its
binaries.

No package's result changes today: every file gives the same paths both ways. But a package
that declares its outside reads (next, I136) would make this live. orion-web-tests reaches
outside only through client.rs, its literals in `web/`, and the raw page above.

## Changes

- **`string_literals` reads the strings of a Rust source as the compiler does:**
  - plain, byte and C strings, with their escapes;
  - raw strings with any number of `#`;
  - never a char literal (`'"'`) or a lifetime.
- **In a comment, every quoted run still counts, as before.** A path in a doctest or a comment
  is seen.
- **`reaches_outside` uses it.**

## Proved by

- **Fail-before.** A planted `r#"one " quote"#` followed by `std::fs::read("../../../scripts/gate.sh")`
  in orion-ctl's tests was keyed by its binaries:
  `orion-ctl names a path outside the crates after a raw string with a quote in it, and was keyed by its binaries`.
- **Pass-after.** Not keyed so.
- **The self-test checks `string_literals` directly** on a char literal of a quote, a lifetime, a
  raw string with `"#` inside, a byte string with an escaped quote, a doctest path in `///`, and
  a path in `/* */`.
- **Mutation.** `reaches_outside` put back on the regex fails the self-test, 3 runs of 3.
- **Nothing else moves.** Every one of the 95 packages has the same `reaches_outside` and
  `binary_keyable` as before. Every file gives the same set of paths outside the crates by the
  regex and by `string_literals`.
