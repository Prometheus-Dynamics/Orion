# I121: Tests and fuzz keyed by what their binaries run

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I120

Read `AGENTS.md` and `docs/design.md` first.

## Why

The one-minute rule (2026-11-24). A change to a core crate's source ran every test that builds
on it, even when the change was a comment, and that was about 250 CPU-s of a core change's 650 to
700. A test binary built from a changed source is often the same in everything it runs. Only its
debug info, symbol table and build-id change. A key of what the loader maps tells those cases
apart.

## Changes

- **`scripts/elf-alloc-key.py FILE...`** keys an ELF file by its allocated sections (SHF_ALLOC).
  For each section it takes the name, address, flags, type, size and bytes. A NOBITS section is
  taken by its size, and `.note.gnu.build-id` is left out. The ELF type and entry point are in
  the key too. A file it cannot read whole as ELF (truncated, malformed, or not ELF at all) is
  keyed by all of its content, `file-` and its SHA-256. That key is never narrower than the file.
  `--self-test` builds a small C program and checks that:
  - adding a non-allocated section keeps the key;
  - the same section made allocated moves it;
  - changing one byte of `.rodata` moves it;
  - truncated, empty, non-ELF and section-table-past-the-end files are keyed by their whole
    content.

  The gate runs that self-test, once per version of the script.
- **The tests step builds first, then keys** (`scripts/lane-reuse.py binary-plan`). Rows the
  source keys did not reuse are built with `cargo test --no-run`. Each package is then keyed by
  its executables' alloc keys, together with:
  - the non-Rust files of every package it builds, Cargo.lock entries included;
  - the files its tests say they read;
  - the programs it runs;
  - the test environment.

  A package that passed before on that key is not run. A package is never keyed this way if it
  reaches outside the crates, or if any of its sources mentions `CARGO_MANIFEST_DIR`, since it
  may read files at run time that the key does not hold. Both records are written after a pass:
  the source key and the binary key.
- **Fuzz the same way** (`binary-plan-item`). After its build, `scripts/fuzz-short.sh` keys the
  run by its targets' alloc keys, its seconds and the corpus files under `testing/fuzz`.
- **`scripts/alloc-key-probe.sh [--fuzz] TARGET OUT`** measures which binaries a change moves,
  by the whole-file hash and by the alloc key. It covers five changes to `orion-types`.
- The lane keys' self-test now also covers the binary key:
  - a Rust source of the crate, or of a crate it builds, keeps the key;
  - another binary with the same name moves it;
  - a manifest it builds, or the nextest settings, move it;
  - a note keeps it;
  - a crate that reaches outside is not keyed by its binaries, and neither is one with a planted
    `CARGO_MANIFEST_DIR`.
- **`binary-plan` end to end** (`--self-test-plan`, run by the self-test in its own copy). It
  uses planted cargo artifacts, planted test state, and records in the copy's own git directory,
  and checks what runs again:
  - nothing passed before: both keyed packages run;
  - the same binaries, passed before: nothing runs;
  - a fixture of `orion-device-probe`, which nothing else builds: only it runs;
  - only the code of a binary its tests run: it runs;
  - a value of the environment the tests read: everything runs;
  - on CI: everything runs;
  - the five packages that mention `CARGO_MANIFEST_DIR` stay on the source key, and a sixth,
    planted in `orion-ctl`, is refused binary keying;
  - a test binary that is not ELF is keyed by all its bytes, and one byte changed runs it again.
- **The self-test runs every case in a copy of its own, all at once.** One after another, with
  the cases above, it took 41 s at load 73 and starved in the gate at load 90.
  - All at once, it took 13 to 30 s wall and 25 to 33 CPU-s (load 79 to 91), and starved in the
    gate again when the load rose from 81 to 106: 30 CPU-s in 75 s.
  - The cause was cargo's package-cache lock. Thirty `cargo metadata` runs at once wait on it
    one after another: 23 s wall at load 95.
  - So the self-test now lists once, and every case that leaves the manifests, lockfile and
    toolchain file alone reads that listing (`LANE_REUSE_METADATA`, self-test only). A case
    that changes one of those lists its own tree. A key holds the manifests' bytes either way.
  - Now: 9 to 22 s wall and 16 to 17 CPU-s, at load 83 and nice 10.

  Its bound stays 25:12: a 75 s backstop and a 60 CPU-s floor.

## Proved by

Mutants, 3 runs each, all red:

- `elf-alloc-key.py`:
  - non-allocated sections taken in (red: "a section not allocated, added, moved the key");
  - section bytes left out (red: ".rodata changed left the key as it was");
  - the fallback a constant `file-`, and the fallback hashing only the first 64 bytes (both red:
    "a truncated file was not keyed by its whole content").
- `lane-reuse.py`:
  - the `CARGO_MANIFEST_DIR` check removed (red: the planted case was keyed);
  - the binaries' keys left out of the key (red: "another binary of the same name: the key did
    not move");
  - only the first binary of a package keyed (red: "only the code of a binary
    orion-device-probe's tests run: reused, not run");
  - the fixtures of what it builds left out (red: "a fixture of orion-device-probe ...: reused,
    not run");
  - the environment the tests read left out (red: both packages reused);
  - CI not run in full (red: both reused).
- `elf-alloc-key.py` with its fallback a constant also turns the plan red ("that binary, one
  byte changed: reused, not run").

  Before the planted case existed, the first of these two survived. All five crates that mention
  `CARGO_MANIFEST_DIR` today also reach outside, so on today's tree that check never decides
  anything, and the planted case is what tests it.

## Measured

`scripts/alloc-key-probe.sh` against the committed tree: 143 test binaries, nice 10, load 60 to
100. "Moved" counts binaries whose key changed.

| Change to orion-types | File hash moved | Alloc key moved |
|---|---|---|
| A comment appended to lib.rs | 0 | 0 |
| A comment put first in error.rs | 117 | 1 |
| An error message changed | 61 | 61 |
| The escape's hex digits in lower case | 37 | 37 |
| An unused `pub fn` appended | 35 | 29 |

- **The comment at the top** moves only orion-types' own tests. Their panic messages carry line
  numbers.
- **The unused `pub fn`** moves `.text`, `.rodata`, `.rela.dyn`, `.eh_frame` and `.eh_frame_hdr`
  in all 29 binaries, and every section in 13 of them. So `.eh_frame` gets no exclusion of its
  own.
- **The fuzz targets (12):**
  - comment appended: 0 and 0;
  - comment at the top: 12 by file hash, 0 by alloc key;
  - error message: 0 and 0;
  - hex digits: 10 and 10.

The build itself still runs. That is 102 to 110 CPU-s and 27 to 35 s for the tests' binaries
after an appended comment, and 18 to 26 CPU-s for fuzz.

## Open

- **A fixture in a crate that others build reruns them too.** The binary key takes the non-Rust
  files of every crate a test builds. Narrowing that to the package's own files is sound only if
  the reach and `CARGO_MANIFEST_DIR` checks also cover each dependency's library. On today's
  tree that leaves 7 of 68 keyable packages: the heuristic flags path-check strings like
  `a/../b` in `orion-types` and a `.parent()` in `orion-identity`. So the rule stays
  conservative.

- **Doctests run as they did,** by the source key. A doctest is built and run in one step, so
  there is no binary to key ahead of the run.
- **The build is the remaining cost.** The check and test builds of a core change cost about 470
  to 520 CPU-s, near 120 s at load 100. The early-cutoff probe comes next.
