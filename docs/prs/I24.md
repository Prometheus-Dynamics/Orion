## Build

The size gate's nine builds are half the CPU-seconds of a gate after a change to a core crate:
664 of 1,378. Each ends in a fat-LTO link on one thread, which is three quarters of the build:
60 of 82 CPU-s for `orion` for this machine. In a warm worktree cargo builds only the binaries
whose dependencies changed. It decides by file times and by the worktree's path, though, so it
builds all nine again in two cases where the bytes cannot have changed:

- a fresh worktree, even one seeded from another worktree's target directory: its size lane
  took 254 s;
- a file whose time changed and whose content did not: a proof that undoes a change it
  planted, or a checkout. A gate on a change to documents only rebuilt the whole size lane
  (122 s).

The same builds made in two worktree paths are byte for byte the same. That held for
`orion`, `orion-recovery`, `liborion_c.so` and `orion` for aarch64, 4 of 4. So a measurement
can be keyed on content and reused across worktrees.

## Built

- `scripts/size-key.py` gives each build a key: a hash of all that can change its bytes.
  - Every file, by content, in each workspace crate in the package's dependency closure:
    normal and build dependencies, every platform, tracked and new files.
  - `Cargo.lock`, the root `Cargo.toml` with its profiles, `rust-toolchain.toml`, and every
    cargo config file cargo reads, both here and above.
  - `CARGO_HOME`, `rustc -vV` and `cargo -V`.
  - The package and the target.
  - For this machine, `cc --version`. For a board, zig's version and the wrapper scripts.
  - The environment variables builds and build scripts read. `CARGO_TARGET_DIR` is left out,
    and the worktree's path is written as `<root>`.
  - The key script itself.

  `--explain` lists each input.
- `scripts/size-gate.sh` keeps one record per key in `<target>/size-gate/store`: size,
  SHA-256, whether the file is static, when it was measured, and from where.
  - A build whose key has a record is not built again. The recorded size is held to today's
    limit, and the line says so:
    `orion for this machine: 6310568 bytes (limit 6590000), reused from key 8dc074801d5f (sha256 a7fca44fe3cf, measured 2026-11-18T23:05:08Z)`.
  - A seeded target directory carries the records.
- Everything is built and measured, ignoring the keys, in three cases:
  - at least once a day;
  - with `--measure`;
  - with `SIZE_GATE_MEASURE=1`, which CI sets on every run.

  A full measurement checks each result against its key's record and fails if they differ,
  since then the key missed an input. It also builds `liborion_c.so` a second time from a copy
  of the source at another path, and the two must be byte for byte the same.
- `scripts/size-gate.sh --self-test`, with no builds, runs on a copy of the source at another
  path. The gate runs it when it measures, and whenever `size-gate.sh` or `size-key.py` has
  changed since it last passed.
  - The copy has the same keys as the worktree.
  - A planted change to each input changes the keys it should, and only those. The inputs
    are: a core crate, a node crate, a manifest, the C library, `Cargo.lock`, `Cargo.toml`,
    `.cargo/config.toml`, `rust-toolchain.toml`, a zig wrapper, the key script, a new file in
    a crate, `RUSTFLAGS`, a profile set from the environment, a board's C compiler and the
    toolchain.
  - Changes to `docs/lock.md`, `TODO.md` and `CARGO_TARGET_DIR` change no key.
  - A reuse says its key. A reuse over its limit fails, and so does a reused board file that
    is not static. Other bytes or another size under the same key fail.

## Proof

Mutations of the self-test:

| Mutation | Self-test |
| --- | --- |
| `Cargo.lock` left out of the key | `FAILED: Cargo.lock left the key of r as it was` (and o, c, a, v) |
| A record never checked against a new measurement | `FAILED: other bytes under the same key passed` |
| Build dependencies left out of the closure | passed. No crate here has build dependencies, so the mutation changes nothing today. |
