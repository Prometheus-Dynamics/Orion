## Fault

Found as a flake in a landing gate under load (about 106): `ctl` `fetch.rs`
`file_fetch_says_a_stall_waits_it_out_and_gives_up_only_when_asked` gave its program
`Done { taken: false, detail: "the client went" }` where the client's own reason, `gave up: …`,
was due.

The client said why it stopped (`FileTaken { Rejected, "gave up: …" }`) and exited. The program
was still sending chunks. The comm core's write to the client found it gone (a broken pipe), and
ended the session: its reader stopped, and every frame not yet read was refused, since a session
that is ending handles nothing more. So the client's last word, already in the socket, was
dropped. The program's next chunk then met a session that was ending, and the file service told
the program "the client went". Which came first, the write's failure or the reader reaching the
last word, was down to timing.

## Built

- **A write that finds the program gone** (a broken pipe or a reset) no longer ends the session
  at once. The session is marked gone and its reader is stopped. Before the session is closed,
  the reader handles what is already there from the program, up to 1,024 frames, none waited
  for. Why the session went is kept as before: `WriteFailed`, with the frame and the error.
- **A frame for a gone session** is taken and goes nowhere, as a socket takes a frame a moment
  before its peer closes. So no service acts on the session being gone before its last word is
  handled. The session's end still tells every service, as before.
- Any other write failure, a stalled write and a full outbox end the session as before.

## Proof

`crates/comm/server/tests/drops.rs`, on the in-memory carrier with the order made the same
every run (the comm core's write is woken before the reader reaches the last word):

- `what_a_program_said_before_it_closed_is_handled_though_a_write_to_it_failed_first`, 8 rounds:
  each session's last `GET` is handled, and each session is still kept as dropped, `WriteFailed`
  on a `Pong`, `BrokenPipe`. With a broken pipe sent back to ending the session at once, it fails
  at round 0, 3 runs of 3.
- `a_frame_for_a_program_that_closed_is_taken_until_what_it_said_last_is_handled`: another
  session's frame for the gone one is taken, the gone one's last word is handled, and the services
  are told it closed. With a frame for a gone session refused, it fails, `[false]`, 3 runs of 3.

The `ctl`, file-offers and comm-app tests pass.
