## Fault

CI's size part was red on I26 and I27 with `liborion_c.so built at another path has other
bytes`. The bytes never differed. CI sets no `CARGO_TARGET_DIR`, so the size gate's target
directory was the relative path `target`. The path check builds from a copy of the source
(`cd "$copy/src"`) with `CARGO_TARGET_DIR="$copy/target"`, which cargo read against the copy's
directory. The build went to a nested `target/` inside the copy, and the `cmp` back in the
worktree read a file that was never made: exit 2, reported as other bytes. On this machine the
target directory is always absolute, so the gate passed here.

Reproduced in a clone with CI's layout: `cmp` exits 2 with
`target/size-gate/path-check/target/service/liborion_c.so` missing. The file the copy did
build, under `path-check/src/target/...`, is byte for byte the original.

## Built

- The size gate makes its target directory absolute before anything uses it.
- A path check with a file missing says that, naming both paths, instead of "other bytes".
- When the two builds do differ, `scripts/elf-diff.py` reports where: the sizes, how many bytes
  differ, in which ELF sections, and the strings each has alone.

## Proof

In a clone with CI's layout (no `CARGO_TARGET_DIR`, so the target directory is `target` inside
the checkout), measuring everything:

- the fixed size gate: `liborion_c.so from a copy at another path: the same bytes`, exit 0;
- the old one, in the same clone: `liborion_c.so built at another path has other bytes`,
  exit 1, as on CI.

`elf-diff.py` on a copy of `liborion_c.so` with one string and one byte changed: 7 bytes,
6 in `.rodata` and 1 in `.dynsym`, and the changed string in each.
