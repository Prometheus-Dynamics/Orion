# I129: A test that starts its own binary again is not a read outside the crates

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I128

Read `AGENTS.md` and `docs/design.md` first.

## Why

The check for reads outside the crates flags every `current_exe`, since a binary's own path can
find the target or files beside it. Several packages' tests use it only to start their own
binary again, as a second process: `orion-actions`, `orion-buffers` and `orion-broker`. That
child is the same bytes the binary key already holds.

## Changes

- **`Command::new(std::env::current_exe().expect("..."))` is left out of the check.** This is
  the binary started again, as it is, with nothing else done to its path.
- **Every other use is judged as before:**
  - its own path handed to another program, as in `.arg(current_exe…)` under a wrapper;
  - a file found beside it, as in `with_file_name` or `parent`.

## Proved by

- A planted case: `orion-ctl` starting its own binary again stays keyed by its binaries. Red on
  14727bca: it was not keyed.
- Two planted cases that must stay broad, and do:
  - its own path handed to another program (`Command::new("unshare").arg(...)`);
  - a file found beside its binary (`with_file_name`).
- Mutants, 3 runs each, both red:
  - every `current_exe` left out;
  - the `.arg(...)` form left out too.
- 74 of the 95 packages are now keyed by their binaries, from 71.
