# I143: shipped binaries hold no Cargo home path, and the size key drops it

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I142

Read `AGENTS.md` and `docs/design.md` first.

## Why

A dependency's sources are under the Cargo home (`registry/src`, `git/checkouts`), and their
absolute paths end up in what the dependency compiles to: panic messages, `file!()`. Measured at
I139, `orion` held 365 such strings, `orion-recovery` 219 and `liborion_c.so` 18.

So the same crates in another home (another user's, a copy, the gate's own) built other bytes.
The size key therefore had to hold where the home was, and a key measured with one home did not
hold with another.

## Changes

- **`scripts/shipped-remap.sh [TRIPLE]`** prints one cargo argument:
  `--config=target.TRIPLE.rustflags=["--remap-path-prefix=<CARGO_HOME>=/cargo-home"]`, plus the
  home's real path when it differs.
  - A `--config` entry adds to the flags `.cargo/config.toml` gives that target (checked:
    aarch64 musl keeps `--cfg chacha20_force_neon`). RUSTFLAGS would replace them.
  - cargo's `trim-paths` is not stable in 1.99.0.
- **The size gate builds every shipped binary with it** (service-profile `orion`, `orion-recovery`,
  `liborion_c.so`). packaging/README.md's build commands give it too.
- **The size gate's full measurement (CI) checks two homes.** It already built `liborion_c.so`
  again from a copy of the source at another path and compared the bytes with `cmp`. That build
  now also uses a copy of the Cargo home at another path, offline, and must give the same bytes.
- **The size key no longer holds where CARGO_HOME is.**
  - It still holds every cargo config file, the home's own by its place in the home.
  - The size gate's self-test gains a case: the same home at another path, through a symlink,
    must change no key.

## Proved by

- **Fail-before:** `orion-capi`, release profile, built at once with the gate's home and with a
  reflink copy at another path, each in a target directory of its own. Without the remap, the
  two `liborion_c.so` differ (from byte 41), with 7 home-path strings.
- **Pass-after:** the same with the remap: the same bytes, no home path left, and 7 `/cargo-home`
  strings in its place.
- **Size key:** the self-test passes. Mutant with the home put back in the key: 3 of 3 red ("the
  Cargo home at another path changed the key of r", and of o).
- **CI on the commit:** the size part runs the full measurement, so the two-home `cmp` on the
  service-profile `liborion_c.so`.

## Not covered

- Only `liborion_c.so` is built twice. The other shipped binaries take the same flag from the
  same script.
- The rustup toolchain's own paths are not remapped; the standard library's are `/rustc/<hash>`
  already.
