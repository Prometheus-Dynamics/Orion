## Built

- `testing/board-runs/I7.md`: every row of "Proof on hardware", run on the test board or pointed at the
  run that showed it (B9, F8, G6, I6).
- `orion-drill throttle`: a slow link with small buffers, run on the board in front of its
  WebSocket, so that a page watching from far away is a slow reader to the board and not to
  an SSH tunnel.
- `video_from_a_board_plays_over_a_throttled_link` in `crates/testing/web-tests`: the video
  page against a board, given by `ORION_WEB_BOARD`; ignored unless run by hand.

## Proved by

`testing/board-runs/I7.md`. On the test board: Orion at 0.3% of a core while values (1 kHz) and
frames (100 a second) flowed between programs; each part killed while running, as the
design's table says, with no gap and no torn frame through it all; the video page over a slow
link, sent less than was published and playing on, with the board's own subscriber missing
nothing; the SystemCore's own NT4 client library reading from and writing to Orion's NT4 server.

## Different from the brief

- Not every row: **Recovery** is shown in a root holding only the comm core (G6), not in a
  booted initramfs, which needs an image built with `orion-recovery`. **MCU** has its size
  gate; the real device board is H8's run.
- Graph to graph ran with drill programs, not graphs: the graph bridge was dropped (I2).
- Live values in a browser are shown on the bench (the web client test), not against the board;
  the board run is video.
- The design's table said requests for records answer "restarting" while node logic is away;
  they are refused `unavailable`, and the table now says so.
