## Why

A provider's record write is a `Put`. Since I70 it can be refused `busy`, and the board's one
known provider makes these calls. Both calls took their handle by value and returned a bare
`ClientError`:

- A `publish` turned away lost the description, so the program had to build it again.
- A `withdraw` turned away had already withdrawn the topics, and left the record written,
  with no handle left to finish it.

## Built

- **`Describing::publish`** now returns `Result<Resource, Unpublished>`.
  - `Unpublished` carries `error` and `describing` (boxed), with everything declared for the
    resource. `describing.publish(..)` again publishes it.
- **`Resource::withdraw`** now returns `Result<(), Unwithdrawn>`.
  - `Unwithdrawn` carries `error` and `resource` (boxed).
  - Each topic is struck from the resource once it is withdrawn, so a second call only does
    what is left.
  - A topic this session no longer publishes counts as withdrawn (`Topics::withdraw` returns
    `false` for it).
- **The errors still work with `?`.** Both types turn into `ClientError` and `orion::Error`
  with `From`. The three node-app tests that chained `publish` into a `ClientError` result
  now say `.map_err(ClientError::from)`.
- **`docs/client.md`**, "When the board is busy", says what to call again.

## Proof

Both tests run on a test board with `comm.outbox_bytes = 70000`. Node logic is slowed with
I70's `slow` hook, and a filler sends puts until node logic's outbox is full. The resource's
2 kB label makes its record larger than the room that is left.

- **`a_publish_turned_away_as_busy_gives_its_description_back_to_publish_again`:**
  - **What it checks.** The publish is refused and `is_busy()` is true. Once node logic has
    caught up, the description it gave back publishes. The resource is found `Ready`, with its
    label.
  - **It passes 3 of 3.**
  - **Mutation:** the description comes back without its labels. All 3 runs failed: the
    label is missing.
- **`a_withdraw_turned_away_as_busy_is_finished_by_withdrawing_again`:**
  - **The setup.** The resource has a topic, and is published.
  - **What it checks.** The withdraw is refused busy. Once node logic has caught up, the
    resource it gave back withdraws, and the resource is no longer found.
  - **It passes 3 of 3.**
  - **Mutation:** the record write's error is swallowed. All 3 runs failed: the withdraw
    returned `Ok`.
- **The landing gate passed.**
