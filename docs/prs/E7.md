# E7: Files before start

**Status:** done

**Group:** E. Node logic

**Wave:** 11

**Needs:** E5, E13

**Runs:** cloud

Read `AGENTS.md` and `docs/design.md` first.

## Creates

`crates/node/workload-files` was not made: there was nothing to put in it. The rule is three
small pieces in the crates that have what it needs, listed under Built.

## Read on dev

- `crates/client/src/graph.rs`

## Build

- A workload starts only when every file it needs is on the board.

## Proof

A missing file holds Pending and reports why.

## Built

- `orion-workloads`: `Tracker::hold(name, why)` and `held`. A held workload is `Pending` with
  the reason instead of being started; let go, it starts at once.
- `orion-file-store`: `has(destination, digest)` and `commits()`, from a note of what the
  store put in place (`.placed`), kept across restarts.
- `orion-executors`: the `Board` trait and `Workloads::review`, which holds every workload
  with a file that is not on the board and lets go the rest. A put is held before it is
  given to the tracker.
- `orion-node-app` reviews when a file has been put in place and every second besides.
- Client: `Workloads::put_needing(workload, files)`.

## Proved by

- `crates/node/node-app/tests/workloads.rs`, with the sample executor: a workload that needs
  `models/detector.bin` with a given digest is `Pending`, "waiting for file
  models/detector.bin", with its executor connected, and its command is not started. Another
  file pushed to that name changes nothing. The right file is pushed: the workload is
  `Running` without being put again, started once. After node logic restarts the file is
  still known and the run is adopted.
- `crates/node/executors/tests/executors.rs`: two files, one missing and one wrong, then
  both right; what it says at each step; a file that goes away while it runs.
- `crates/node/workloads/tests/stopping.rs`: held before put, the reason changing, let go;
  a hold on what runs.
- `crates/node/file-store/tests/store.rs`: `has` by digest, after reopening, after another
  file is put there, after the file is deleted.

## Limits

Only files the node's own store put in place count. A file handed to a receiver (E15), or
copied to the board by hand, is not known to be the file a workload names.
