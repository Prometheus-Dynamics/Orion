## Build

A flasher image's SSH is to be open on the USB gadget's network and nowhere else, whatever
address the image gives that network. An address in the example would depend on a number the
image's own configuration sets.

1. **`ssh.interface`**: SSH listens only on that network interface (`SO_BINDTODEVICE`, through
   tokio's `TcpSocket::bind_device`; no `unsafe`), on `ssh.listen`'s port, 22 if unset. Either
   key turns SSH on.
2. **An interface that is not there yet is waited for.** A gadget's network comes up after the
   comm core, since the comm core is handed the gadget's endpoints. Failing the start would put
   the comm core in recovery, without its USB link; instead SSH tries every second and opens
   when the interface comes. Both the plain and the sandboxed server.
3. **Recovery keeps to it.** Settings that were read and name an interface keep every address
   recovery tries to that interface. Settings that could not be read name none, and then
   security is on.
4. **The flasher example** sets `ssh.interface = usb0` and `ssh.listen = 0.0.0.0:22`. Its
   comments and the README say what security off means there: whoever reaches the board is root,
   which is safe only while the cable is the only way in, never on a shared network.

## Proved by

- `crates/comm/ssh/tests/interface.rs`: `ssh.interface` alone turns SSH on at port 22; a
  listener on `lo` takes connections; a server on an interface that is not there starts, says
  it is waiting, and is open nowhere, not on its address alone.
- `crates/comm/recovery/tests/recovery.rs`, `on_one_interface_recovery_is_open_there_and_nowhere_else`.
- `crates/bins/orion-recovery/tests/binary.rs`: the flasher example, with `lo` standing for the
  gadget's interface, is read whole, starts, and lets SSH in.
- By hand, in a network namespace of its own (`unshare -rn`): `orion-recovery` with
  `ssh.interface = dummy0` started as a comm core, not in recovery, and was closed on port 2222;
  `dummy0` was added and brought up three seconds later, and within a second SSH took a
  connection on its address and still none on `lo`.
