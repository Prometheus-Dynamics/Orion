# I25: A crate's integration tests are one binary

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I24

Read `AGENTS.md` and `docs/design.md` first.

## Changes

The 27 crates with two or more integration-test files: `Cargo.toml` and a new `tests/all.rs`
each. Also:
- the five test files that run their own binary again;
- the seven files whose counting allocator moves into `all.rs`;
- the test files whose shared helper module (`common`, `support`) is now declared once;
- `.config/nextest.toml`, `scripts/check-test-filters.py` (new), `scripts/gate.sh`, `AGENTS.md`,
  `docs/lock.md` and `TODO.md`.

## Build

Each integration-test file was a binary of its own, and after a change to a core crate every
one of them linked most of the workspace again. That was 235 test binaries. In `orion-node-app`
(12 files), a change to its own source linked 13 executables, for 14-29 CPU-s of building.

## Built

- **One binary per crate.** Each crate with two or more files in `tests/` sets
  `autotests = false` and has one test target, `all` (`tests/all.rs`), which names each file as
  a module by `#[path]`.
  - A test that needed features (`required-features` on its own `[[test]]`) has the same
    features as a `cfg` on its module.
  - Its tests are named `<file>::<test>`.
  - Crates with one test file are as they were.
- **Fixed for a shared binary:**
  - The tests that run their binary again on one test name it with `module_path!()`
    (`own_test`), so the name is right whether the file is alone or shares a binary.
  - A binary has one global allocator, so the counting allocator (it counts per thread) is set
    once in `all.rs`.
  - A helper module several files used (`mod common;`) is declared once in `all.rs`, and the
    files `use crate::common`.
  - Where every test file of a crate is built only on Linux (or only with some features), what
    moved into `all.rs` carries the same `cfg`. The first gate on this change failed clippy for
    the client on Windows: `orion-connect`'s `mod common` and counting allocator, moved out of
    files that are `#![cfg(target_os = "linux")]`, were built there.
- **Filters renamed.** `.config/nextest.toml` filters name the tests by their new names.
- **New gate checks** (`scripts/check-test-filters.py`):
  - every `test(...)`, `package(...)`, `binary(...)` and `binary_id(...)` in a nextest filter
    matches a test, checked against the list nextest gives for the binaries the tests just ran;
  - every `tests/*.rs` in a crate without autotests is built by something.

  The script's self-test plants a filter naming a missing test and a test file left out of
  `all.rs`, and both must fail.
- `AGENTS.md` says that tests in one crate share a binary, so under plain `cargo test` a test
  may not rely on being alone in its process.

## Proof

- **The same tests.** `cargo nextest list --workspace --all-features`, before and after,
  compared by list with each merged test's old name mapped to `<file>::<test>` in binary `all`:
  881 tests before and after, the same in every crate, and every name accounted for. Binaries
  went from 235 to 171.
- **The helpers start.** The four merged crates whose tests run their binary again pass
  (74 tests, with `orion-ssh-sandbox`). With `own_test` changed back to the bare name, 8 of
  them fail: the helper process never starts (`the provider never got ready`, and timeouts).
  `orion-ssh-sandbox` keeps a binary of its own, and its test ran its helper inside a user
  namespace (2.4 s, no skip).
- **The filters.** `check-test-filters.py` on the old filters against the new list fails the
  six renamed tests. On the new filters it passes. With its "matches no test" line removed,
  its self-test fails. A planted `tests/planted.rs` in `orion-node-app` fails
  `--files`: `built by nothing: name it in tests/all.rs`.
- **Cost.** The test build after a change to `orion-check`, interleaved, at load 100-130 (other
  repositories' gates beside it):

  | Round | One binary per file (CPU-s) | One per crate (CPU-s) |
  | --- | --- | --- |
  | 1 | 155 | 102 |
  | 2 | 167 | 184 |
  | 3 | 295 | 135 |
  | median | 167 | 135 |

  In `orion-node-app` alone: 13 executables linked became 2, and 14-29 CPU-s of building
  became 2-5.
