## Built

- `orion` (`crates/client/orion`): one handle, `Orion`, over one session. `connect`, `declare`,
  `subscribe`, `declare_buffers`, `subscribe_buffers`, `records`, `run`, `attach`,
  `register_action`, `files`, `workloads`, `executor`, `provider`, `resources`, `pump`.
  Everything a program needs is re-exported, so it depends on this crate alone.
- Each part is a cargo feature: `topics`, `records`, `actions` (the default), `buffers`,
  `files`, `workloads`, `executor`, `provider`, `tokio`; `full` is all of them. Every
  combination tried builds without warnings.
- `Orion::reconnect` connects again and says everything again. For that, `Topics`, `Records`
  and `Actions` gained `restore`: a topic is declared with its ring handed back, so the comm
  core takes back the same memory; a subscriber keeps the reader it has on that ring; a watch
  is asked for from its newest stamp; actions are registered again. Buffer topics offer their
  pool again when they next look at the session.
- `Workloads` (feature `workloads`): `put`, `remove`, `status`, `wait`. There was no client
  crate for saying what should run, and the example's executor had nothing to start without it.
- One macro: `fields![rpm: Float "rpm", spinning: Bool]`.

## Proved by

- `examples/roles.rs` uses the `orion` crate alone for three programs: a provider speaking for
  a fan, an executor running scripts, and a client that finds the fan, reads it, drives it, asks
  for a workload and watches it run and go. `tests/facade.rs` runs it and checks its six lines.
- `a_comm_core_that_restarts_stops_nothing_that_was_flowing`: with the comm core stopped, four
  values still go from publisher to subscriber through the ring. After it starts again with no
  memory, both reconnect; the value published in between is read, later ones wake the subscriber
  through its doorbell as before, the subscriber count is 1 again, and a record watch made
  before the restart is pushed a change made after it.

## Different from the brief

- The package is named `orion`, not `orion-orion`. It is the one crate a program names, and
  `use orion::Orion` is the point of it.
- Dev's proc macros (typed runtime and resource descriptors, derive for executors and
  providers) are not carried. They generated dev's typed records, which are gone, and would
  bring `syn` into every client build. One declarative macro earned its place.
- The design's sketch has every call returning `ClientError`. Topic calls can also fail on a
  sample that does not fit or a ring that cannot be mapped, so the facade has its own `Error`
  with both, and `is_lost` on it.
