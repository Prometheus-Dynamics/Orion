# I60: A hello too large for a link is refused, saying its size and the limit

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I59

Read `AGENTS.md` and `docs/design.md` first.

## Changes

`crates/comm/server` (`carrier.rs`, `server.rs`, `sessions.rs`, `mem.rs`), the other carriers'
`Connection` (`unix`, `tcp`, `ws`, `link-can`, `link-serial`, `comm-app`'s `carriers.rs`),
`crates/comm/hello/src/lib.rs`. Tests: `crates/comm/link-usb/tests/usb.rs` and
`crates/comm/comm-app/tests/signed_link.rs`, with the `topics` feature added to `comm-app`'s
`orion` dev-dependency. Docs: `docs/comm.md`, `docs/lock.md`, `TODO.md`.

## Why

A serial or USB link's frames are at most 8192 bytes, what the far end's decoder takes. With I59,
a hello can be far larger. There were two faults:

- **The comm core believed the far end.** A session's `max_frame` was whatever its hello said,
  up to the comm core's own 64 KiB, so a far end that said more than the link carries was sent
  frames that never arrived. It heard nothing and waited.
- **The refusal did not say why.** Orion's own client says the link's size in its hello, so a
  hello too large for it was refused. But the refusal was `buffer_too_small` with its stock
  words, `buffer is too small`, and gave neither the size nor the limit.

## Built

- **A carrier says the largest frame it takes.** `Connection::max_frame`, like `local`, has no
  default.
  - A stream link (serial, USB) says 8192, or 8160 on a signed session: 32 fewer, for the seal.
  - Every other carrier says `None`, as before.
  - A session's `max_frame` starts at that limit, and the hello's figure is clamped to it, so
    the welcome tells the far end.
- **Sending over the limit was already refused.** A frame larger than a session's `max_frame`
  was already refused `buffer_too_small`, so with the clamp an answer too large for a link is
  refused, not lost.
- **The hello says its size.** It is now encoded into a buffer that holds the largest document,
  and a frame larger than the caller's `max_frame` is refused `buffer_too_small` with `the hello
  is <n> bytes, over the <limit> bytes a frame to this session may be`.
- **Interface level 6, no wire change.** `Welcome.max_frame` and `buffer_too_small` were already
  there, and the refusal's words are free text.

## Proof

- **`usb.rs`,
  `a_device_that_says_it_takes_more_than_the_link_carries_is_sent_no_more_than_the_link_carries`.**
  A device that says 64 KiB is welcomed with 8192, and its session's `max_frame` is 8192.
- **`signed_link.rs`, `a_hello_too_large_for_the_link_is_refused_saying_its_size_and_the_limit`.**
  This runs a comm core with `links.usb = usb0`.
  - A small hello comes on both the plain and the signed session.
  - A program then publishes ten 1000-byte facts.
  - The plain session's hello is refused with its size (over 10,000) and the limit 8192. The
    signed session's is refused with its size and 8160.
- **Before:** at `586dff3b`, the second test fails 3 of 3 with `BufferTooSmall: buffer is too
  small`.
- **Mutants**, each run 3 times, fail every time:
  - the hello's refusal removed fails the second test;
  - the stream link with no limit fails the first.
- **Not proved by a mutant:** the 32 bytes taken off on a signed session. Orion's client says
  8160 itself, so only a far end of another make would show it.
- **The landing gate passed.**
