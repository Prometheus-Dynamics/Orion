# C61: The obvious connect keeps trying until it is answered

- **Status:** done
- **Group:** C (client)
- **Wave:** 19
- **Needs:** C59

## Why

`Session::connect`, `Orion::connect`, `orion_connect` and the browser's `Orion.connect` each made
one try. A program that started before the comm core, or while it restarted, met nobody there and
got an error back, so every program wrote its own loop around connect. The drills' roles had one:
a fixed 20 ms retry that gave up after 10 s, and it gave up for good once in a gate run. A way in
never gives up, and a program should not have to know to ask for that. Nobody answering is not an
answer. A refusal is.

## Changes

- **`Options::patience`**, a `Patience`: `Forever` (the default), `Within(d)` or `Once`.
  - `Session::connect` (`patience.rs`, so `lib.rs` stays under 800 lines) keeps trying, at the
    pace of `reconnect` (the access path: every 250 ms, never backed off). It stops when it is
    welcomed or refused, or when the patience is spent. Each try waits up to `Options::timeout`
    for the welcome.
  - `Session::connect_once` is the named one-shot.
  - `Session::connect_watching(.., keep_trying)` tells the caller each failure (`Status`) and
    stops when told. The same three are on `Orion`.
- **`ClientError::may_retry`** says what is tried again:
  - `Io` and `Lost`;
  - `Rejected(Busy)`: no room now;
  - `Rejected(NoSession)`: no session for this one.

  Everything else is an answer and returns at once. `reconnect` and `reconnect_over_with` use the
  same rule, so a `Busy` comm core no longer ends a reconnect.
- **Over a link**, the patience is how long a hello is said again on the same halves (C59's capped
  backoff). With `Forever` that is for as long as it takes. A signed link's handshake is tried
  again in the same way. `reconnect_over_with` gives each try one window (`Once`) and opens new
  halves after it.
- **C:** `orion_connect` keeps trying, and `timeout_ms` bounds one try. `orion_connect_once` is the
  one try. The header and the surface list are updated.
- **Browser:** `Orion.connect(url, name, keepTrying?)` keeps trying every `CONNECT_AGAIN_MS`
  (250). A refusal is `TurnedAway` and ends it. `Busy` and `NoSession` are tried again.
  `Orion.connectOnce` is the one try. `dist/` is rebuilt.
- **A device** already says hello until a host answers, and again after a refusal. That is
  unchanged.
- **Callers that keep their own pacing, or that answer for a request, now say so by name:**
  - node logic's loop (async, ready to stop and save between tries) uses `connect_once`;
  - the peer dialer (a node that is away is `Unavailable` to the waiting caller) uses
    `Patience::Once`;
  - `orion-ctl` (a person is waiting) uses `Within(timeout)`;
  - the sample executor uses `connect_watching` with its `keep_going`.
- **Tests that meant one try now say `connect_once`.**
- **`docs/client.md`:** a section on starting before the comm core, with the list of what is a
  refusal.

## Proved by

`crates/client/connect/tests/patience.rs`:

- `a_program_started_before_the_comm_core_is_welcomed_when_it_comes`: the connect is still
  trying 1.5 s in, with 200 ms tries. The board then starts, and the program is welcomed.
- `a_refusal_ends_the_trying_at_once`: a role not offered returns in under 500 ms.
- `a_bounded_wait_and_a_single_try_end_when_they_say`: `Within(700 ms)` ends between 0.4 s and
  1.5 s, and `connect_once` ends in under 200 ms.
- `the_trying_is_told_how_it_goes_and_may_be_stopped`: `keep_trying` sees failures 1, 2 and 3,
  then stops the trying.
- `over_a_link_a_hello_is_said_again_past_one_timeout_until_it_is_welcomed`: three hellos are
  lost (1.75 s) against a 300 ms timeout, and the session is welcomed.
- `over_a_link_one_try_ends_with_its_timeout`: the same link with `Once` fails.

`error.rs` `only_a_way_in_that_broke_or_had_no_room_is_tried_again` lists both sides of the rule.

The browser test: `connectOnce` to nothing fails, and `connect` to nothing is told failures
1|2|3 and then stopped.

Mutations, each killed:

- `Busy`/`NoSession` made final: the unit test fails.
- Nobody answering made final: three patience tests fail.
- The default `Options` patience made `Once`: three tests fail.
- A link's `Forever` made one timeout: the link test fails.
- The browser's connect made one try: the page reports no failures counted.
