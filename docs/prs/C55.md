# C55: A socket path too long is said, and never tried again

- **Status:** done
- **Group:** C (comm and client)
- **Wave:** 18
- **Needs:** C54

## Changes

A Unix socket's path is at most 107 bytes: `sun_path` is 108 with its NUL. Before C55, a longer path broke in four places:
- the client got `ClientError::Io`, which `is_lost`, so it tried again for ever;
- the comm core's bind failed without naming the path or the limit;
- node logic retried for ever;
- the test stub panicked in its own thread, where the caller never saw it.

Now each place checks the length before any system call:

- `orion-connect`:
  - `ClientError::PathTooLong { path, len }`, which is not lost;
  - `SOCKET_PATH_MAX` and `socket_path(path)`;
  - `Transport::local` checks before `connect`, so `Session::reconnect` and `Orion::reconnect` return it at once.
- `orion-capi`: `PathTooLong` is `ORION_E_ARGUMENT`, and the header says so.
- `orion-unix`: `fits(path)` and `SOCKET_PATH_MAX`. `UnixCarrier::bind` refuses with `InvalidInput`, naming the path, its length and the limit, and leaves nothing at the path.
- `orion-node-app`: `Node::load` refuses with `socket: ...`, so node logic never reaches its connect-again loop.
- `orion-stubs`:
  - `Board::try_start_with` gives the error back before a thread starts;
  - the other starts panic with the words in the caller's thread;
  - `Board::start(name)` uses a short directory, `orion-<hash of name>-<pid>`, and writes the name to a `name` file inside it.
- Docs: `docs/client.md`, `docs/comm.md`, `orion.h`.

## Proved by

- `orion-connect` `tests/path.rs`:
  - 107 bytes fit and 108 don't;
  - `connect` gives `PathTooLong` that is not lost, and its words name the path, 108 and 107;
  - a 107-byte path to nothing is still a lost connection, so it is tried again.
- `orion-capi` `tests/path.rs`: `ORION_E_ARGUMENT`, with the words in `orion_last_error`.
- `orion-unix`: the bind refuses 108 bytes with words and makes nothing; 107 binds.
- `orion-node-app`: `Node::load` refuses a 120-byte socket.
- `orion-stubs`: `try_start_with` refuses before starting; `Board::start` with a 200-byte name gets a socket path that fits.
- Mutations, each failing its test:
  - the client check removed;
  - the C mapping removed;
  - the bind check removed;
  - the node-logic check removed;
  - the stub check removed.

## Different from the brief

The connect-again loop is proved by its condition, not run. `PathTooLong` is not `is_lost`, and `Session::reconnect` stops on any error that isn't. A session can't have a too-long address and also have connected once, so the loop can't be entered with one. Node logic's own loop is now never reached with such a path.
