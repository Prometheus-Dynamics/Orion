# C32a: The security switch is the board's record, and trust follows it

**Status:** done

**Group:** C. Comm core

**Wave:** 18

**Needs:** C41

Read `AGENTS.md` and `docs/design.md` first.

## Changes

`crates/core/config` (new `security_view.rs`), `crates/comm/keys`, `crates/comm/comm-app`,
`crates/core/msg-records`, `crates/node/resources`, `crates/node/node-app`, their tests,
`crates/comm/time/tests/time.rs`, `docs/settings.md`, `docs/comm.md`, `docs/node.md`,
`docs/getting-started.md`, `docs/lock.md`, `packaging/`, `TODO.md`.

## Build

- One reader of `/etc/board/security`, failing secure, and every part's trust follows it. It is
  the only source: no file means off, and a damaged one means on, with words naming the file and
  what is wrong.
- Remove `security` from `orion.conf`. A file that still has it is warned about once, loudly,
  and the line never takes effect.
- With security on, a lease's holder is the writer's principal, set from the session. The
  client's text becomes a label for people.
- At most 32 operators pending, nobody evicted, and re-asks allowed.
- Hello and time stay readable by keys the board does not know, with a test.
- A flash seeds one operator key.
- Later, in C32b, when the device library's record layout lands: precondition/1, the signed
  turn-off and the `orion node security on|off` writer.

## Built

- **The reader** (`orion_config::SecurityView`, `crates/core/config/src/security_view.rs`).
  - The record is two lines: `on` or `off`, then `generation <n>`.
  - No file means off. A file that cannot be read, or says anything else, means on, with
    `fault` saying what is wrong.
  - The path is the constant `SECURITY_VIEW`, `/etc/board/security`. A comment says it becomes
    the device library's record crate's constant once that crate is a dependency.
  - Tests read another path through `Config::from_source_with_view` and
    `CommSettings::from_source_with_view` (`#[doc(hidden)]`). There is no setting for the path.
- **Trust follows it.** `Config::security` is now the record's switch. The comm core, its
  recovery and node logic all take it from there: the check, the trust store, SSH, peer
  dialing and lease binding. Each service logs the record when it starts: `info` when it was
  read, `warn` when it is damaged.
- **The key is retired.** `Source::retire` marks a key no longer read. A `security` line in the
  file, or `ORION_SECURITY`, gives one warning with the ruled words (see below), and is ignored
  even by a part that reads the key anyway. `Warning` gains `retired` and is
  `#[non_exhaustive]`.
- **Lease holders.** `Resources::bind_holders` is on when security is on.
  - `Resources::as_written` rewrites each lease of a write before it is checked: the holder
    becomes the caller's principal (`local:<uid>`, `operator:<key>`), and the text the writer
    sent goes in the new appended field `LeaseRecord.label`.
  - A lease that already names the writer's principal is stored as written.
  - Busy and denied words, the contest and freeing all go by the principal, so another
    session of the same caller may free it.
- **Pending cap.** `MAX_PENDING` is 32.
  - With 32 pending, a new key that asks without proof gets `KeysError::Waiting`. The service
    refuses it `busy`, with words saying to ask again once one of them is approved or refused.
  - A key already pending may ask again.
  - A proof still enrolls, and root's approval is not counted. Nothing is evicted.
- **Flash seed.** The file is `operator.seed` in `keys.dir`: one line of 64 hex digits, with
  `#` lines allowed.
  - `Keys::open` enrolls the key with read and everything, saves the trust store, removes the
    file and logs it. The file is taken once, so it is not a standing grant.
  - A seed that is empty, more than one line or not a key stops the open with
    `KeysError::Seed`, naming the file and the fault. The file is left there, and the comm core
    goes to recovery, which says why.
  - `KeysError` is `#[non_exhaustive]`.
- **Hello and time.** Both were already readable without a grant. Hello's test already asked
  with an unknown operator key. Time's test now does too, with security on.
- **The packaging examples.** The examples and the flasher's file no longer carry `security`. The
  flasher is open because its image has no record.
- **Docs.**
  - `settings.md` has "The security switch".
  - `comm.md` has the cap, the seed and recovery's switch.
  - `node.md` has bound holders.
  - `lock.md` loses the known limit "a lease holder is not yet bound to a principal (C32)" and
    lists C32a under "Since the lock revision", with its breaks marked:
    - the removed key, with migration "write `/etc/board/security`";
    - `LeaseRecord` literals needing `label`;
    - `KeysError` and `Warning` now `#[non_exhaustive]`.

## Proved by

- **orion-config.**
  - `security_in_the_config_file_is_ignored_and_said_so_loudly`: from the file and from the
    environment, one warning with the exact words, and the switch stays off.
  - `the_switch_is_the_boards_record`.
  - The reader's unit tests: absent, on, off, empty, an unknown word, no generation, a bad
    generation, extra lines, unreadable.
- **orion-keys.**
  - `at_most_so_many_wait_and_none_waiting_is_dropped_for_another`: 32 wait and the 33rd is
    refused with words. All 32 are kept, and one of them re-asks. A proof still enrolls, and
    room returns once root approves one.
  - `a_flash_seeds_one_operator_who_may_do_everything_once`: the seed is enrolled with
    everything, the file is gone, and the operator is still there after a reopen. Three damaged
    seeds each stop the open with the file named and are left byte for byte.
  - `an_operator_asking_when_too_many_wait_is_told_busy` (through the server).
- **Node logic.**
  - `with_security_on_a_lease_is_held_by_its_writers_principal_whatever_it_says`: a claim
    saying `workload:recorder` is stored as `local:<uid>` with that label. Writing one's own
    principal keeps the record as written, and another session of the same caller frees it.
  - The security-off contest test still holds free-text holders.
- **orion-time.** An unknown operator key gets the time with security on.
- **The comm core.** The tests that needed security on now write a record and read it through
  `from_source_with_view`. With the record saying `off`, `signed_link` and `recovery` fail, so
  they depend on it. The broken-settings case of `recovery` now breaks `comm.max_sessions`,
  because `security = sometimes` no longer breaks anything.
- **Mutations.** `/mnt/nvme-wd/scratch/c32-mut.py` made 19 mutations, and all were caught.
  They covered:
  - the reader: absent means off, damaged means on, the generation is required;
  - the retired key, the switch coming from the record, and the record reaching the comm core;
  - the cap, re-asks and the busy refusal;
  - the seed: taken once, everything granted, one line, enrolled;
  - lease binding: off, from the switch, never with security off, the label, one's own
    principal as written, and stored as bound.
- **Runs.** The node-app suite ran 6 times, all passing. Workspace clippy with
  `-D warnings` is clean. The gate passed.

## Different from the brief

- **The warning's words.** The ruled text names the device library's control tool by its
  product name. `scripts/check-boundaries.sh` fails any product name in code, so the words say
  "the device library's control tool" there. Everything else is as ruled: "security is no
  longer set in orion.conf; it is ignored; the switch is /etc/board/security (the device
  library's control tool / orion node security on|off)".
- **A broken `orion.conf` still means security on in recovery.** The record would also be
  readable then. Recovery keeps its fail-secure rule: settings that could not be read are not
  believed, so security is on, as before.
- **A forwarded lease write is bound to the forwarding node.** It arrives over a peer session,
  so with security on its holder is `peer:<node>`, not the operator behind it. This is the same
  class as `Run.on_behalf`.
- **A test fixed on the way.** The contest test in `node-app/tests/leases.rs` measured "taken
  no sooner than the quiet time" from after a second session connected. Under load that connect
  took 180 ms, and the bound failed at 1.32 s against 1.5 s. It now measures from just before
  the holder's last word is sent, which is when the comm core's quiet clock can start at the
  earliest.
