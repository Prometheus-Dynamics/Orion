## Build

In a gate, nextest ran 878 tests on 26 threads in 30 s. Together they took 296 s of test time,
so 26 threads need about 11 s. The two slowest, 22 s and 16.5 s, finished last, as tests 877
and 878: they had started late.

The second, `orion-node-app` `sink.rs`
`a_large_file_passes_to_its_receiver_with_memory_bounded_by_the_chunk`, moves 96 MiB through
every hop and hashes it on each side. It took 14-35 s, depending on load. A profile of it alone:
about 45% in `sha2` built without optimization (its SIMD intrinsics not inlined), and about 20%
in the test's own byte generator.

## Built

- **The longest tests start first.** `.config/nextest.toml` gives the two slowest priority 100
  and the next six priority 50. Priority changes only when a test starts, not what it checks.
  The same 878 tests run.
- **`sha2` is built with `opt-level = 3`** in the `dev` profile, which tests use. Debug
  assertions and overflow checks stay the profile's.

## Proved by

Interleaved, the same built tests, run old then new three times:

| | old | new |
| --- | --- | --- |
| the `sink` test alone | 16.4, 21.7, 13.7 s | 7.3, 7.4, 3.4 s |
| `cargo nextest run`, every test | 31.0, 37.1, 30.4 s | 23.7, 20.8, 20.1 s |

With priorities alone, before `sha2` was optimized, two runs of three got faster (33.6 → 20.7 s,
34.1 → 25.8 s). In the third the `sink` test took 35 s even when it started first. Both changes
are needed.

Every run passed: 878 tests, 2 skipped.
