## Fault

The two places I16 parked, with the same cause as I16 and I23. Neither has been seen failing.

- **The drills' `free_port`** found a port by binding port 0 and letting it go. It then wrote
  that port into the board's settings for the comm core to listen on later, as `ssh.listen` and
  `peer.listen`.
- **`forward.rs`'s `-L` port** was found the same way, and handed to `ssh` to listen on.

A port let go can be handed to any other socket before its program listens there. The program
then fails to start, or a test reaches someone else's listener.

## Built

- **The port is held until the program listens there.** It is held by a socket bound to it and
  not listening, with `SO_REUSEADDR`, which the kernel gives to no bind to port 0 (shown in
  I16). The comm core's listeners and `ssh`'s forwards also bind with `SO_REUSEADDR`, so the
  hold does not stop them.
  - The drills' `held_port` keeps both of a board's ports for as long as the `Board` lives.
  - `forward.rs` keeps the `-L` port until the test ends.

## Proof

- **Passing as they are:**
  - the drills that use the ports (`node_logic`'s SSH banner, `contained`'s peer port) and the
    rest of `orion-drills` and `orion-ssh`;
  - `forward.rs` with `--features forward`, 2 of 2.
- **The hold is in place when the program binds.** With the hold made without `SO_REUSEADDR`,
  the program cannot listen there, so the tests that use the port fail:
  - the drills, 2 tests fail 3 of 3;
  - `forward.rs`'s `-L` test fails 3 of 3.
- **No fail-before.** The race needs another socket to be handed the port inside the gap, which
  no test can force. I16 showed the property the fix rests on: a held port was never given to
  3,000 binds to port 0, and a port let go was taken at once.
- **The landing gate passed.**
