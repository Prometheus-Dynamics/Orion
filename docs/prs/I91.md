## Why

Three small things.

1. **A setting the build does not read was a warning in a log nobody reads at start.** An
   image came within one build of shipping settings the pinned Orion ignored.
2. **One refusal for a held resource had no words.** A client now waits out a bare `busy` and
   treats a worded one as held. A lease that could not be read was refused bare, so it would
   be waited out.
3. **cargo decides what is fresh by file times.** In a target directory another worktree built
   in, a crate can be taken as fresh for this worktree's older, different sources, and a gate
   then passes or fails on code that is not in the tree. Orion's gate did not check whose a
   target directory was, and `scripts/seed-target.sh` copies one for a new worktree.

## Built

- **Settings nothing reads**, a key of the file or a variable of the environment alike:
  - a line in `orion/state`, running and in recovery: `settings not read: a, b`, each as it
    was written;
  - the hello fact `settings_unread`, the same list, reserved as Orion's other facts are, and
    `Node::settings_unread` in the client;
  - an error in each service's log, where it was a warning.
  The start is not stopped. An error at start for a variable was weighed and not built: it
  would turn a typo into a board that does nothing, and a slot rolled back to an older build
  must come up with a newer file. The image's own check at build time is the guard; this is
  what a person sees on a board.
- **A lease that cannot be read**, or is not there while the resource is held: refused `Busy`
  with `<resource> is held: its lease cannot be read`.
- **`scripts/target-owner.sh`**, run by the gate before anything is built. A target directory
  records the worktree it belongs to (`.orion-worktree`).
  - One that belongs to another worktree is refused, saying whose.
  - One that `scripts/seed-target.sh` copied says it was seeded. The gate takes it over, and
    first gives every tracked file of this worktree the time now, so nothing in the copy is
    newer than the sources it is used for and cargo builds this worktree's own.
  - A new one, or one from before this record, is taken as this worktree's.
- `docs/prs/I84.md`: its opening line said two commits; it was one.

## What a value that does not parse does

Unchanged, and now written in `docs/settings.md`. The comm core's settings fail, and it comes
up in recovery, with the recovery way in open and its hello saying `recovery` and why. Node
logic logs `the settings cannot be read: ...` and ends; the service manager starts it again,
and the comm core stays up.
