`crates/device/actions`, `examples/mcu-template` (the C API, its header, its README and its
tests), `web/client` (`src/orion.ts` and `dist/`), `crates/testing/web-tests/tests/client.rs`,

## Build

`Finished.code` (C44) in the C library, the web client and the MCU library: readers where
`Finished` is exposed, and setters where those libraries finish calls.

## Built

- **The MCU library** (`orion-device-actions`). `Actions::finish_with_code(link, call,
  (outcome, code), output, detail)` sends the code as the appended field. `finish` sends the
  result as before, with no code after `detail`, so a firmware that never gives a code costs
  not one byte more, and the host reads zero.
- **The MCU template's C API.** `orion_finish_code(call, outcome, code, output, len, detail)`,
  in the header and the README. `orion_finish` and it share one body. Without a code, it is
  `finish`, so the result has its old shape.
- **The web client.** `Result` gains `code`, read when the board sent one and zero when it did
  not (a board from before C44). `dist/` is rebuilt by `build.sh`.
- **The C library.** It has topics and no actions (`orion.h`): nothing to read or set, so
  nothing changed. `docs/lock.md` says so.
- **Docs.** `docs/client.md` names the setter on a microcontroller and the reader in a page.
  `docs/lock.md` lists C47 under "Since the lock revision" as additive.

## Proved by

- **orion-device-actions** (`tests/actions.rs`): a plain `finish` is exactly call, outcome,
  output and detail, with nothing after (`[41, 1, 2, 7, 8, 0]`), and reads as code 0.
  `finish_with_code` with `(Failed, 300)` decodes to code 300, with its output and detail.
- **The MCU template** (`tests/ffi.rs`): `orion_finish_code(44, FAILED, 300, ..)` reaches the
  host as code 300, beside two runs finished without one (code 0). `tests/c/header.c` calls
  `orion_finish_code`, so the header's declaration compiles under each configuration.
- **The web client** (`web-tests`, `the_web_client_subscribes_publishes_and_runs_actions_in_a_browser`,
  in a real browser): the action finishes with code 7 and the page reports `code=7`.
- **Mutations.** `/mnt/nvme-wd/scratch/c47-mut.py` made 4, and all were caught: the device
  library not writing the code, `finish` appending a zero code, the C API dropping the code,
  and the web client not reading it.
- **Runs.** The gate passed.

## Different from the brief

- **No setter for the C library.** It cannot finish a call: it has no actions.
- **`ORION_MCU_API_MINOR` stays 0.** `orion_finish_code` is an addition, but versions move only
  at a release. A firmware built against this header and linked against an older library fails
  to link, rather than misbehaving.
