## Build

- Chunked, resumable, digest-checked, from any connection.
- Hashing on a helper thread started on demand.

## Proof

Interrupt and resume. A bad digest is refused.

## Built

`crates/node/file-store` (`orion-file-store`): `Files` with `open`, `request`, `poll`, `gone`,
`path`. `orion-relay` routes the three kinds and `orion-node-app` answers them, with settings
`files.dir` and `files.max_size`. The rules are in `docs/node.md`, "Files a node receives".

## Proved by

- `crates/node/node-app/tests/files.rs`, through the `orion` client against a real comm core:
  - A push of 1.2 MB whose source fails after 400 KiB. Nothing is at the destination. Node
    logic is then killed and started again. A second push from a new session goes on from
    exactly the bytes that were on disk (several hundred KiB), not from zero, ends `Committed`, the file is byte for byte the
    source, and nothing is left in `.incoming`.
  - A source whose bytes are not the ones its digest was taken of ends `Rejected`, "the digest
    does not match". The file that was at the destination before is untouched and the bad
    part is gone.
- `crates/node/file-store/tests/store.rs`, 11 tests: order and gaps, going on in a store that
  was closed and opened, the same number for another file, an early commit, a wrong digest,
  too many bytes, too large a file, destinations that leave the store, the limit on
  transfers, and a committer that went away while the helper worked.

## Different from dev

Dev kept blobs by digest in a content store, with local and remote variants and a table of
what each node had. Here a file has a destination and goes there; the digest is what it is
checked against, not where it lives.
