## Build

What a worker waits on, past the gate:

- **The inner loop.** After a change, the only check was the whole gate.
- **Disk.** The gate's debug target directory had grown to 80 GB. Cargo never removes builds of
  earlier revisions, or of dependencies since moved on: 388 builds of `orion-comm-app` alone.

Also measured, and not changed:

- **The core-crate case.** The size gate's builds, grouped by target so that crates with the same
  features build once, cut the size gate's CPU by about 15%. Its time was longer, because the
  links then run one after another. Each run was after a change to `orion-check`, interleaved
  (s):

  | Size gate | Wall | CPU (user) |

  | One lane per build, run 1 | 197 | 748 |
  | One lane per build, run 2 | 133 | 734 |

  | Grouped by target, run 2 | 148 | 611 |

  Lanes stay as they are.

## Built

- **`scripts/check-changed.sh [CRATE...]`.** It takes the crates named, or with none, those
  owning a file changed against `HEAD` (`git status`). It adds every workspace crate that depends
  on them, through normal, build and dev dependencies. Then it runs, for those crates, the
  gate's own commands with `-p` for each:
  - `cargo fmt --check`;
  - clippy with `--all-targets --all-features -D warnings`;
  - the tests under nextest, then the doctests of the crates that have a library (without
    nextest, `cargo test`);
  - the feature matrix, beside the rest.

  A changed path outside every crate (a manifest, a script, the docs) is listed as one only the
  whole gate checks. It stamps nothing: only the gate does.
- **`scripts/prune-target.sh [--delete]`.** It asks cargo for the gate's debug builds again, with
  JSON messages: clippy, the tests, the doctests and the check compiled out. Each is up to date,
  so this costs seconds, and it names every artifact it would use.
  - A binary or an example is named by its copy without a hash, a hard link: the hashed file is
    found by its inode.
  - A C library has no hashed file: the newest fingerprint of its package recording that target
    is kept.
  - Everything else under `debug/deps`, `build`, `.fingerprint` and `examples` goes, and
    incremental caches untouched for a day.
  - Without `--delete` it says what would go, and how much.

## Proved by

- **Scoped check against the gate, interleaved, after the same change to `orion-action-list`
  (31 crates depend on it) (s).**

  | Run | Gate | Scoped |
  | --- | --- | --- |
  | 1 | 203 | 86 |
  | 2 | 87 | 40 |

- **It fails where the gate would.** By mutation, each restored after:
  - **Clippy:** an unused variable in `orion-action-list`, found from `git status`. It exits 1.
  - **Tests:** a wrong error kind in a test in `orion-stubs`, a crate that depends on
    `orion-action-list`, with only `orion-action-list` named. It exits 100, `FAIL ...
    orion-stubs tests::a_socket_path_too_long_is_said_before_the_board_starts`.
  - **Feature matrix:** a `compile_error!` under `costs` alone in `orion-measure`. It exits 1,
    `FAILED: cargo check -p orion-measure --no-default-features --features costs`.
- **Prune, on this machine's target directory.**
  - It removed 73.7 GB; `debug` went from 80 GB to 14 GB.
  - The first version also removed 52 entries still in use: binaries and examples, named
    without their hash. With the hard-link and fingerprint rules, a prune right after it removed
    nothing.
  - Building `orion-action-list` and `orion-ssh` alone (other feature sets) made 190 entries the
    gate does not use. The prune removed them, and the gate's clippy, test, doctest and
    compiled-out builds then compiled nothing.
