## Why

The workspace skeleton's gate guidance, checked against I27:
- **Per step, the same:** the bounds (three times the slowest green run, a minute at least,
  TERM to the step's processes, KILL five seconds later).
- **Stricter here:** a step that leaves a process running already fails.
- **Three things missing:**
  - a TMPDIR of its own for each step, with a check for leftovers;
  - a scale for every bound, for a slower machine;
  - a refusal of a step written without its number. Bash arithmetic turned a missing or
    misspelt number into 0, and so a 60 s bound nobody chose.

Gates here are timed as they are landed: as systemd user units, the same environment as the
lander's. Neither sets a `CARGO_*` or `RUST*` variable; only `PATH` differs from a shell.

## Built

- **Each step has its own TMPDIR.**
  - `bounded.py` makes an empty directory with a short name (`$TMPDIR/gXXXXXXXX`; a socket under
    it must fit in 107 bytes) and runs the step with `TMPDIR` set to it.
  - When the step ends, anything there fails it with 125, each entry named (the first 50, then
    a count). The directory is then removed, pass or fail.
- **A step without a bound does not run.** `bounded` in `gate.sh` takes only a whole number
  of seconds; anything else exits 2, naming the step.
- **`GATE_STEP_BOUND_SCALE`**, a whole number, 1 if unset, multiplies every bound. Anything else
  exits 2.
- **The skeleton's words for a bound passed:** `<step>: TIMED OUT after N s (bound N s)`.

## Proof

- **A leftover fails its step, named.** node-app's `tests/node.rs` was put back as it was
  before I35, and its tests were run under `bounded.py`:

  | Run | Result |
  |---|---|
  | Planted | the 6 tests passed; the step failed 125, naming `orion-node-audit-…`, `orion-node-comm-restart-…`, `orion-node-kill-…`, `orion-node-pages-…`, `orion-node-stop-…` |
  | Restored | exit 0 |

- **The bounds self-test has a sixth case.** A step must get an empty TMPDIR, apart from
  `bounded.py`'s own, and a file it leaves there must be named with 125. The old `bounded.py`
  passes the step's status through (0), so the case fails against it.
- **Refusal and scale.** A new gate step, "steps without a bound refuse", runs `bounded` with
  `x`, an empty number and 0, and with scales of 1.5 and 0: each must exit 2. A scale of 2 must
  run. Against I35's `bounded`, it fails at once: "a bound of 'x': exit 0, not 2".
- **The landing gate passed** with every step in a TMPDIR of its own, nothing left in any.
