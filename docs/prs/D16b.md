# D16b: The index of a prefix, a fetch held to its bound, and `orion file fetch`

- **Status:** done
- **Group:** D (files)
- **Wave:** 19
- **Needs:** D16

## Why

A client collecting files from a board must say how much it will fetch, and warn of what may hold
a user's data, before it fetches anything, whichever program offers them. So every prefix has an
index in one format, which Orion owns and knows nothing behind. A file larger than its index says
is not taken. And a person at the bench fetches with the tool, as they push.

## Changes

- **`orion_files::index`.** `Index { total, entries }`, each `Entry { name, max_bytes, user_data
  }`: `write` gives the text, `parse` reads it or says which line is wrong and why (another format
  or version, no `total`, a name that is not one, a number that is not, a word other than
  `user-data`/`no-user-data`, a name twice), and `bound(name)`. The format is in
  `docs/client.md`.
- **A fetch held to a bound.** `Fetching::within(bound)`: a file said to be larger is rejected
  on both sides ("the file is N bytes, more than its bound of B"), and nothing of it is written.
  `Fetching::finish(progress)` steps one to its end; `Files::fetch` is that.
- **`orion file fetch NAME PATH [--bound BYTES]`** fetches into PATH, going on from what PATH
  holds already. **`orion file offers`** lists each prefix and who offers it, and the clashes.
  The file verbs moved to their own module of the tool.
- **The stub board offers files** as the comm core does, so a consumer's tests can offer and
  fetch.

## Size

`orion file fetch` brings the fetching side of the client into `orion`. The board's `orion`
(aarch64) is 5,250,168 bytes, 12,616 more than D16 left it. D16 cut what it could before (its
fetch tables as lists, not trees, and the fetch handler heard only once used, together about
11 KB); what is left is the fetch itself, in the tool (about 7.6 KiB) beside the push (about
8 KiB). The limit goes from 5,240,000 to 5,270,000: what was measured and the usual margin.

## Proved by

- `orion-files` unit tests: an index written reads back as it was, with its bounds; each kind of
  text that is not an index is refused with its line and why.
- `orion-file-offers` test `a_fetch_held_to_a_bound_does_not_take_a_larger_file`: 5,000 bytes
  against a bound of 4,000 is rejected on both sides with nothing written; 4,000 at its bound
  is taken.
- `orion-ctl` test `file_offers_and_fetch`: `file offers` says nothing is offered, then names the
  program; `file fetch` into a file holding the first 50,000 bytes asks only for the rest and
  ends with the whole file; with `--bound 1000` it is not fetched, exit 1, saying why.
- Not vacuous:
  - with the bound not checked, the bound test and the tool's test fail;
  - with the tool fetching from zero whatever the file holds, the tool's test fails (it was
    asked from 0, not 50,000).
