**Status:** done

**Group:** C. Comm core

**Wave:** 18

**Needs:** J9

Read `AGENTS.md` and `docs/design.md` first.

## Build

`peer.listen` failing to bind (an address the board does not have yet, an interface not up yet,
a port another program still holds) failed the comm core's start, and a failed start is
recovery. A way in that cannot open is not a comm core that cannot start. Now it tries again
with a capped backoff and the rest of the comm core runs. Only the comm core itself failing
means recovery. It also gains `peer.interface`, as `ssh.interface` is for SSH.

## Built

- `orion_tcp::Listen { addr, interface }` and `TcpCarrier::listen(&Listen, options)`. With an
  interface the socket is kept to it (`SO_BINDTODEVICE`), and a connection on any other is not
  taken. An interface that is not there is `ENODEV`.
- `TcpCarrier::listen_retrying(&Listen, options, Retry)`. It tries until the socket opens:
  - waits 5 s, then 10 s, and 10 s from then on (`Retry::default()`);
  - logs one warning with the address (and interface) and the error;
  - logs one info line when it opens.
- The comm core tries `peer.listen` once at start. If that works, nothing changes. If not, the
  start goes on: the retrying listener is a task of the comm core, and it is served when it
  opens. `peer_addr()`, which discovery announces, is the address as given meanwhile.
- `peer.interface`: needs `peer.listen`. The name must be 1 to 15 bytes, with no `/` and no
  space, as the kernel takes it.
- `TcpCarrier::bind` is unchanged for other callers (tests, the stubs).

## Proved by

- `tcp/tests/listen.rs`:
  - a taken address is refused at once by `listen`; `listen_retrying` keeps trying past several
    waits and opens on that address once it is free;
  - kept to `lo`, a connection over loopback is taken;
  - kept to another interface that is up, a connection over loopback is not taken (skipped on a
    machine with no other interface up);
  - an interface that is not there is `ENODEV`.
- `comm-app/tests/comm.rs`:
  - a comm core whose `peer.listen` is taken by another starts, serves its socket and announces
    the address. Once the other goes, a hello over the network is welcomed;
  - one kept to an interface that is not there starts, serves its socket, and has not opened.
- `comm-app/tests/recovery.rs`: the start that fails after the board's socket is served, and
  ends in recovery with nothing of it left serving, is now a taken `ws.listen`. It was a taken
  `peer.listen`, which no longer fails the start.
- `settings.rs`: `peer.interface` read, and refused without `peer.listen`, too long, or with a
  `/`.
- 9 mutations, 9 caught (`c39-mut.py`).

## Different from the brief

- Only the network way in (`peer.listen`) tries again. The WebSocket, SSH (`ssh.listen`) and NT4
  listeners still fail the start, and so mean recovery, when their address cannot be listened
  on. They are the same class. Each has its own start (the WebSocket listener is shared with
  NT4, and SSH has a sandboxed start), so moving them is a change of its own. It is on the
  PARKED list. `ssh.interface` already waits for its interface.
- The backoff doubles from 5 s to a 10 s cap. Two steps.
- The size gate's limit for `orion` on this machine is set again: 6,534,400 bytes measured, and
  a tenth more (7,190,000). It was 6,530,000, set at I6 from 5,936,216. The binary grew by a
  tenth across waves 15 to 18, and this change took it 4 KB past the limit. The board files
  (static musl) are all still under theirs.
