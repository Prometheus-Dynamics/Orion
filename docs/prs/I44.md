## Fault

The gate ran the comm core's tests only with `--all-features`, and no shipped binary builds it
that way. `comm.rs` assumed every link and the status topics were built in:

- With the default features, two tests failed. The start test configured serial, USB and CAN
  links the build does not have. The bad-identifiers test expected a CAN refusal.
- With the recovery binary's features, the start test hung for good. That build has a serial
  link (through `link-usb`) but not `self-status`, so `orion.state.link.uart0` never opens.
  `watch` waited on it with no limit: one run sat 10 hours on 44 CPU-s.

## Built

- **comm.rs.** The start test configures, and looks for in the summary, only the links its build
  has. It checks a link's retry state only when the build also has `self-status`, which
  publishes `orion.state.*`. The vital signs and the CAN refusal are checked only where built.
- **A link this build does not have is warned about** (`a_link_not_built_in_is_warned_about`).
  For serial, USB, CAN and sealed links it asserts the settings warn exactly when the link is not
  built in. So every build checks the links it leaves out.
- **`watch` gives up after 10 s**, naming the topic, so a topic that never opens fails a test
  instead of hanging it.
- **The gate's new step, "the shipped builds' tests"** (bound 300 s), runs after the
  `--all-features` tests. It does not replace them. For `orion-bin` and `orion-recovery-bin` it
  runs the comm core's tests with the features that binary builds it with, then that binary's own
  tests alone. `scripts/shipped-features.py` reads those features from the binaries' manifests
  (`cargo metadata`), so a change to a manifest changes what the gate runs.

## Proof

- **The comm core's tests under each set**, after:

  | Set | Tests |
  |---|---|
  | The recovery binary's | 16 passed (hung before) |
  | Default | 21 passed (2 failed before) |
  | The orion binary's | 22 passed |
  | `--all-features` | 22 passed |

- **The hang now fails.** With `watch`'s limit in, putting the serial retry check back under
  `link-serial` alone failed the recovery set's start test 3 of 3, each in 10 s, with
  "orion.state.link.uart0 never opened".
- **The new step** took 144 s wall, 133 CPU-s, on a warm target.
- **The landing gate passed** with every lane run in full.
