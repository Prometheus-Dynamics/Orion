## Why

A file on a board may have any name. Orion carried only `A-Z a-z 0-9 . _ - : /` in at most 127
bytes, so a file with a space, a name in Cyrillic or Chinese, or a few directories down could be
listed only as `unnamed`, and not fetched, pushed or changed.

## Built

- **Names carried escaped** (`orion_types::Escaped`, `orion_types::unescape`, no allocation,
  `no_std`). Letters, digits, `. _ - : /` and text outside ASCII as they are; `%XX` in uppercase
  hex for an ASCII byte outside that set, `%`, a control (C1 included) and a byte that is not
  UTF-8. Nothing else is escaped, so a name has one form, and `FileName` takes only it: the
  bytes it stands for, escaped again, must give it back. A name escaped where it need not be,
  or in lowercase hex, is `InvalidName`.
- **`FileName` at most 255 bytes**, was 127, the limit on the escaped name. The other name
  types do not change.
- **The board turns a name into bytes in one place for each side:** `file-roots`' `path::raw`
  for every open, unlink, mkdir and rename, and the store's `place` for where a push lands.
  `walk::read` gives each entry's bytes, and the listing and the index escape them.
- **`files.list`:** the fourth field is the escaped name; when that is not how it shows, the
  rest of the line is what it shows as (lossy UTF-8, controls as U+FFFD). An entry whose name,
  with its directory's, is over 255 bytes escaped is listed, its line beginning `long`, so a
  client can say why it cannot be reached; `unnamed` is no longer given. A page is at most 128
  entries and at most 16 KB of lines: a page of long names is shorter, fits a client's 64 KB
  frame, and bounds what node logic holds for it.
- **Names held at their own length on the board**: a transfer being received (the store's
  `Meta`), a file being sent to a receiver (`send.rs`'s `Run`), and the files a workload needs
  keep the name as `Box<str>`, made once when the transfer, run or workload starts and freed
  when it ends; a frame is built with an inline `FileName` from it, with no allocation, when
  the transfer begins or begins again. Nothing on the way of a chunk allocates for a name.
  `orion_executors::Board::has` takes the name as text.
- `docs/node.md` (names, the listing) and `docs/client.md` (names carried escaped, and a path
  too long: listed as `long`, reached or renamed over SSH or SFTP).

## Memory

| Held | Before (`FileName`, 127) | `FileName` at 255, inline | Landed |
| --- | ---: | ---: | ---: |
| each transfer being received (64 at most) | 128 B | 256 B | 16 B + the name |
| each file being sent to a receiver (64 at most) | 128 B | 256 B | 16 B + the name |
| each file a workload needs | 128 B | 256 B | 16 B + the name |
| a `FileName` on the stack, while a frame is made or read | 128 B | 256 B | 256 B |
| a listing page | up to 128 names of 127 B and their lines | — | at most 16 KB of lines and their names |

With every table full of 255-byte names, the tables hold what 255 inline would: 64 × 271 B each.
With the usual names of 20 to 60 bytes, they hold less than before.

## Size

The first gate went red at the size lane: aarch64 `orion-recovery` was 2,761,360 bytes, over its
2,760,000 limit (+1,592 over I78). Recovery decodes file names from the wire (file offers), so it
checks the one form as every program does.

| Crate (`.text`, cargo bloat) | Change |
| --- | ---: |
| `orion_types` | +1,023 (`FileName::new`, the check of the one form, inlined: +824) |
| `orion_ssh` | +614 (code moved from `orion_broker`: `Source::get`) |
| `orion_file_offers` | +307 (a 256-byte `FileName` copied) |
| `num_bigint` | +307 |
| `orion_broker` | −512 |
| `ring` | −307 |

Not cut: a second, hand-written check of the one form for recovery (a few hundred bytes, and a
rule written twice). The limit is raised once from 2,760,000 to 2,770,000. That figure is a
ratchet set at measurements, not a physical bound; it is replaced by the space recovery has in
the flasher's initramfs, less a margin, once that is known, and until then each raise needs a
table like this. No row planned after this one adds to recovery (it has no time sync, mDNS or
NT4). The board's `orion` is 5,491,200 (+1,848, under 5,510,000); `liborion_c.so` does not
change.

## Tests

- `orion-types` (`escape::tests`): names escaped only where they must be (a space, `%`,
  controls, C1, bytes that are not UTF-8; Cyrillic and Chinese as they are); only the one form
  is a `FileName` (lowercase hex, an escape of a letter or of `é`, a `%` with no digits, `..`
  escaped, refused); the 255-byte limit on the escaped form; and the round-trip property: 50,000
  names of random bytes, weighted to the ones that need thought, each escaped, read back to the
  same bytes, its own form, and another spelling of it not.
- `orion-test-board` (`roots::`):
  `any_name_on_the_board_is_listed_fetched_pushed_and_changed_by_its_escaped_form` (a space,
  Cyrillic, `%`, a byte that is not UTF-8 and a 200-byte name of controls, listed with what each
  shows as and the last `long`; fetched; a spelling that is not its form refused; a directory
  made, a file pushed and one renamed and removed by escaped names, the bytes on disk checked;
  a 254-byte name of `é` pushed and fetched), and
  `a_page_of_long_names_is_cut_by_its_bytes_and_goes_on_after` (40 long names, paged at 16 KB,
  every one seen once, in order).
