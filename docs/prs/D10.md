## Built

- `orion-capi` (`crates/client/capi`), library `orion_c`: fifteen functions over the `orion`
  crate. Connect, reconnect, pump and close; declare, publish, count subscribers; subscribe,
  wait, next, latest; a version check and the last error in words. `include/orion.h` is the
  header and the reference.
- Static and shared: `liborion_c.a` and `liborion_c.so`, whose SONAME is `liborion_c.so.1`, so
  the loader refuses a library of another major before any call.
- Every call returns a status; nothing allocates memory the caller frees except the handles;
  no thread is started; a panic never crosses into C.

## Proved by

`tests/c_program.rs` compiles `tests/c/pubsub.c` with `-Wall -Wextra -Werror` and runs it
against a comm core, once linked to the archive and once to the shared library by its
versioned name. The C program declares a topic from one session, subscribes from another,
publishes a hundred values and a text field, and reads them back in order with their times; it
also checks a refused second publisher, an oversized sample, a buffer too small, a missing
socket, a bad address, a null handle and another major. The test also checks that the shared
library exports exactly the header's functions and that the header's numbers are the
library's.

## Different from dev

- Dev's surface was the link client and the latest-value client over the old protocol, with
  generation-counted handles and types shared with another repository's ABI header. This is a
  new, smaller surface over the one client, with its own types and plain pointers for handles:
  a freed handle must not be used again, as the header says.
- The header is written by hand and checked against the library by the test. cbindgen and the
  symbol-list script are not carried.
- Topics only. Records, actions and the rest are not on the C surface yet; they are additions,
  so they raise the minor.
