## Build

- Runs with nothing else on the board.

## Proof

The comm core starts alone and serves hello and topics.

## Built

- `orion-comm-app`: `CommSettings::from_source` reads every part's settings from the one file
  and the environment; `CommCore::start` puts the parts together; `run` is the whole program:
  start, tell systemd ready, say alive, stop on `SIGTERM` or `SIGINT`.
- Always there: the server, the board's socket, the broker, the keys service and hello. Each
  other part is a cargo feature: `tcp`, `time`, `self-status`, `proxy`, `buffers`, `systemd`
  (the default set), and `discovery`, `mdns`, `link-serial`, `link-sealed`, `link-can`,
  `link-usb` (`full` is all of them). Every combination tried builds without warnings.
- systemd: `READY=1` with a line saying what is served, once every way in is up; `WATCHDOG=1`
  every half of `WATCHDOG_USEC`, sent from the comm core's own thread, so a comm core that no
  longer turns stops saying it is alive; `STOPPING=1` at the end. No libsystemd.
- A link's state is the topic `orion.state.link.<name>` when status topics are built in.

## Proved by

`tests/comm.rs`: a comm core started with no node logic and no other program answers a signed
hello on the board's socket, carries a topic between two programs, serves `orion.host` and
`orion.comm`, shows a serial link and a CAN bus with nothing on them as retrying, and answers on
the network. A service manager's socket hears ready once, alive repeatedly, and stopping last.
A second comm core on the same socket, a taken network address and a bus that cannot work are
each refused by name, and the first keeps serving.

## Different from the brief

- The crate is `crates/comm/comm-app`, not `crates/comm/app`: a crate is named
  `orion-<directory>`, and node logic's `crates/node/app` (E3) would have been `orion-app` too.
  `docs/design.md` and the E3 brief now say `comm-app` and `node-app`.
- Dev's watchdog watched the reconcile loop. The comm core has none: it is one thread, and
  being able to send the message is the proof that the thread turns.
- No packaged unit yet. The binary with the `comm` mode is I1, and the unit belongs with it.
- Discovery tells the log when an enrolled peer comes or goes. Keeping a connection to it is the
  outbound side, which is group F.
