# C49: A session dropped for its writes says whether they stalled or failed, and on what

**Status:** done

**Group:** C. Comm core

**Wave:** 18

**Needs:** C48

Read `AGENTS.md` and `docs/design.md` first.

## Changes

`crates/comm/server` (`sessions.rs`, `driver.rs`, `tests/drops.rs`), `docs/comm.md`,
`docs/lock.md`, `TODO.md`.

## Build

The C48 board run dropped one command-line session: "it did not take a frame within 5000 ms".
Reproduce it with logs kept, on the bench first: under load, and with a reader blocked on its
output. Explain it. Either fix it, or show it was the right call, for a client that really did
not read for 5 s. If the bench cannot reproduce it, it goes into the next board run.

## Built

- **The bench could not reproduce it.** Each run kept the comm core's log:
  - 200 short commands run to the end;
  - 100 cut off by `| head -1` (each got a broken pipe);
  - 50 holding publishers killed with `SIGKILL`;
  - three readers whose output was blocked (`| sleep 15`): a topic watch, `node show`, and a
    publisher with 300 KB of input;
  - C48's whole board script three times, on two cores with a CPU hog on one of them.

  Not one session was dropped for its writes.
- **What the words did not say.** The writer ended a session with "it did not take a frame
  within N ms" for any write that did not succeed, a failed one as well as a stalled one. So
  the board's line could have been either. It also did not say which frame or how much was
  queued.
- **Now the two are told apart.**
  - A write past `comm.write_ms` is `Dropped::WriteStalled { kind, waiting, limit_ms }`: "it
    did not take a frame of kind 0x05 within 5000 ms, with N bytes waiting behind it: is its
    program still reading?"
  - A write that fails is `Dropped::WriteFailed { kind, error }`: "its connection failed while
    it was sent a frame of kind 0x05: broken pipe".
- The next board run uses this build, and keeps its logs (`testing/board-runs/C48-run.sh`), so
  the line will say which it was.

## Proved by

- `crates/comm/server/tests/drops.rs`,
  `a_session_whose_writes_stall_or_fail_is_dropped_saying_which_and_on_what`:
  - a session that sends 4,000 requests and reads none is dropped as `WriteStalled` on a
    `PONG`, with bytes waiting, and the words say so (its outbox has room, so it is the
    write that waits, not the outbox that fills);
  - a session whose reading end is gone while it still asks is dropped as `WriteFailed` on a
    `PONG` with `BrokenPipe`, with the exact words.
- **Mutations.** `/mnt/nvme-wd/scratch/c49-mut.py` made 4, and all were caught: a failure called
  a stall, the waiting bytes not counted, the frame's kind not taken, and a failed write
  ignored.
- **Runs.** The gate passed.

## Different from the brief

- **Not explained yet.** The bench did not reproduce it, so the cause is not known. This PR
  makes the next occurrence say which case it is and on what frame. The item stays open until
  the next board run, with this build, says so.
