## Build

Today a state directory that cannot be written is found by the first thing that writes to it:
the identity, the trust store, the saved time, the host key, each with its own message, some
after the comm core is up. And a board updated by slot whose state partition is not mounted
makes its state directory on the root file system, starts as a new node, and loses it all at
the next update.

1. **Made and tried.** Before anything else, the comm core makes `state.dir` and `keys.dir` (with
   their parents) and writes, syncs and removes a file in each. A directory that cannot be made
   or written stops the start with the setting, the directory and the cause, and the board goes
   to recovery with that as its reason.
2. **`state.require_mount`** (default `false`): a directory that is, or would be when made, on
   the root file system is refused before anything is made. Checked on the nearest part of the
   path that is there, by its device against `/`'s.
3. **Recovery writes nothing there either.** With `state.require_mount` on and the host key's
   directory on the root file system, recovery keeps its SSH host key in
   `/run/orion-recovery/`, for the boot (or, if that cannot be written, for the run).
4. Docs: the setting, what is tried, and "Boards updated by slot" in `operating.md`.

## Built

As above. The packaged units keep `StateDirectory=`; a slot-updated image adds
`RequiresMountsFor=` in a drop-in, as `operating.md` says.

## Proved by

- `crates/comm/comm-app/src/state_dirs.rs`: missing directories are made and left empty, and
  made again when there; a directory that cannot be made is named with its setting; one that
  cannot be written to is refused (not as root); with a mount required, a root file system is
  refused before anything is made, and a root on another file system (`/proc`) is not.
- `crates/comm/comm-app/tests/recovery.rs`, `each_broken_state_ends_in_recovery_and_still_lets_you_in`:
  a state directory that is a file and one that cannot be written to end in recovery with
  "cannot be made" and "cannot be written to" as the reason; with `state.require_mount` on and
  the test's directory on the root file system, recovery says `state.require_mount`, nothing is
  made there (not even recovery's host key), and the repairer still gets in. That last case runs
  only where the temporary directory is on the root file system: run with `TMPDIR=/var/tmp`
  where `/tmp` is its own mount. It failed before item 3: recovery made the directory for its
  host key.

## Different from the brief

The test's root is a parameter of `prepare` (a btrfs subvolume and a tmpfs report their own
devices, so the unit tests compare against a directory they choose and against `/proc`).
`StartError` and its helper moved to `error.rs` to keep `lib.rs` under 800 lines.
