## Built

- `crates/bridges/daedalus` (package `orion-daedalus`): a `cdylib` plugin with three nodes on
  backend `orion.cpu`:
  - `orion.topic.read` (`topic` → `value: f64`). `topic` is `name` or `name:field`.
  - `orion.topic.write` (`topic`, `value` → `published: u64`). It declares the topic, one float
    field, the first time.
  - `orion.frame.read` (`topic` → `frame: bytes`). It hands the newest frame over: the bytes
    are the subscriber's mapping of the publisher's pool. The `Held` frame is boxed as the
    handover's data, and the plugin's `release` drops it on whatever thread Daedalus lets go
    on.
- Each step thread keeps one connection, with its subscribers and publishers by topic, made
  on first use at `ORION_ADDRESS` or the default socket. A step that fails drops the
  connection, so the next one connects again.
- It is outside the workspace (root `exclude = ["crates/bridges"]`) and pins Daedalus `next`
  at 9d8ed136, since the daemon checks a plugin's step layout at load. `check.sh` installs
  `daedalusd` from the same commit, then runs fmt, clippy and the tests. `gate.sh` runs every
  `crates/bridges/*/check.sh`.
- The boundary check lets `crates/bridges/` use `unsafe`: the plugin interface is raw cells.

## Proved by

- `tests/daemon.rs`: a comm core, then `daedalusd` with the plugin in its plugin directory.
  One graph reads field 1 of `imu` (42.5), writes three numbers to `echo` (the subscriber reads
  5.0, and `published` counts 1, 2, 3), and takes a 4,096-byte frame from `camera` with the
  bytes the publisher filled.
- `tests/handover.rs`: the frame node run without a host. The cell it fills is a handover, and
  its pointer falls in the `memfd:orion-ring` mapping of the pool: the frame was not copied.

## Different from the brief

- **Topics are fed, not set.** At this Daedalus commit a plugin's step gets cells only for
  ports with an edge: a graph's constants never reach it. The `held` host input policy is
  accepted and not applied by the runner. So the topic name comes on an edge each time, and
  is what makes a reader run. When Daedalus passes constants to plugin steps, the same ports
  take them.
- **"A resident the owner's adapter can turn into its own type"** is the Daedalus handover:
  next has no resident type. The frame is a `bytes` value whose bytes are the shared buffer,
  and an owner's own node reads them in place.
- No adapter for a specific frame type ships here; that is the owner's.
