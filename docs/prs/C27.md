## Build

A tool reached a board's shell only over SSH: on the network, with an SSH client. A board on a
USB cable, or a tool already holding a session, had no way to a shell without a second
protocol and a second login.

1. **Shell kinds** in their own range, `0x80` to `0x87`: open, opened, data, credit, resize,
   end of input, exit, close.
2. **The check decides** `What::Shell(account)`: root and programs on the board (their own
   account only unless root), operators granted `login` or `shell:ACCOUNT`.
3. **The SSH helper starts it**, so becoming the account is never done in the comm core.
4. **Credit both ways**, so a shell never fills the session.
5. **In recovery too**, on the socket and USB links recovery serves.
6. **`Orion::shell`** in the client, feature `shell`.

## Built

As above.

- `crates/comm/shell` (`orion-shell`): `ShellService`. Opening is checked as
  `What::Shell(account)` with the caller's uid given to `Keeper::admit`, the session path of
  the SSH keeper (`Proof::Session`): a local caller that is not root gets its own account
  only. What is asked of a shell already open is checked by session and number, so one
  session cannot touch another's. At most 8 shells a session; output in chunks of 16 KiB,
  sent only as far as the caller's window (64 KiB, at most 1 MiB); the board's input window
  is 64 KiB and input past it is `Malformed` and ends the shell. `ShellExit` follows the last
  output (waited for up to two seconds), 255 if there was no code. A session that ends ends
  its shells.
- `ShellOff`: a board with `shell = off`, or built without the feature, answers an open with
  `Unsupported`. A server ignores kinds it does not know, so without it the caller would wait
  out its timeout.
- `Comm::downgrade` / `WeakComm`: the service's tasks send without keeping the comm core up.
- Settings: `shell = on|off` (on). With SSH off, the shell still has a helper: `ssh.helper` or
  the program itself.
- Recovery serves the shell beside the hello document, with recovery's own helper; from a
  record of the last good start, recovery's helper too, not the recorded one.
- Client: `Shell::{next, write, end_input, resize}`, `Event::{Output, Errors, Exit}`,
  `Terminal`; dropping a `Shell` closes it.

## Proved by

- `crates/comm/shell/tests/shell.rs` (run 30 times in a row, no failure):
  - a command's output, errors and exit code;
  - credit: a shell printing more than the window waits until credit is given, and a `Ping`
    on the same session is answered while it waits;
  - input under credit, end of input, and input past the window ending the shell with
    `Malformed`;
  - a terminal with its size, and a resize the shell sees;
  - refusals: another account for a non-root caller, an operator without the grant, another
    session's shell; close; a session ending ends its shells.
- `crates/comm/comm-app/tests/shell.rs`, `a_tool_gets_a_shell_on_the_board_and_in_recovery`:
  through the real comm core and the client, `cat` with errors and exit 4, a terminal that
  answers its size and a resize, `shell = off` refused as `Unsupported` without waiting, and
  in recovery from the record a shell that says it is in recovery.
- `crates/comm/keys/tests/store.rs`: `login` grants a shell as any account, `shell:svc-*` only
  as those accounts and not a login.
- `crates/testing/wire-vectors`: the eight bodies.
