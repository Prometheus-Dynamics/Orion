## Fault

The size part of CI has been red since I24. `scripts/size-key.py` listed the workspace with
`cargo metadata --locked --offline`. A fresh CI runner has not fetched the dependencies yet, so
that listing failed. The script then read cargo's error as JSON and crashed. The size gate kept
going, because a failure inside a process substitution does not stop the script, and died on
an unset variable (`keys[$name]: unbound variable`) instead of naming the cause. On this
machine every dependency is fetched, so the gate passed here.

Reproduced with an empty `CARGO_HOME`: the same `JSONDecodeError`.

## Built

- `size-key.py` lists the workspace without `--offline`, as the build after it would. A failed
  listing stops it with cargo's own error; no key is made from it.
- `size-gate.sh` takes the keys whole before reading them, so a key script that fails stops
  the gate at that line. A build left without a key stops it too, naming the build.

## Proof

- With an empty `CARGO_HOME`, the fixed script fetches what the lockfile names and gives the
  key.
- Planted failure (empty `CARGO_HOME`, `CARGO_NET_OFFLINE=true`): the fixed size gate exits 1
  with cargo's error. Before the fix it exited on `keys[$name]: unbound variable`.
