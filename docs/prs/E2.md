## Build

- Postcard snapshots under the wire's append-only rules.
- Atomic replace. A corrupt state file never stops start-up.

## Proof

Crash at every write step and recover.

## Built

- `orion-persist` (`crates/node/persist`): `Persist::save(records)` and `Persist::load()`. One
  snapshot file, `records.v1.snap`, with the one before it kept as `.prev`.
- A save writes the new snapshot beside the old, syncs it, renames the old to `.prev`, renames
  the new into place and syncs the directory. A save that fails loses only itself.
- `load` never fails. A snapshot that is cut short, fails its CRC-32C or is not a snapshot is
  renamed to `…unreadable-N` and the one before is used; if neither can be read the answer is
  nothing, and what was wrong is returned for the log.
- The file is a header, then each record as a wire `RecordEntry` with its length in front, then
  a checksum. A newer build's extra fields at the end of a record are passed over. Another
  format version is another file name, neither read nor touched.

## Proved by

`tests/crash.rs`, on a model disk that keeps only what was synced:

- Power goes after each of the steps of a save, and for each the disk is found in six ways:
  unsynced renames kept or lost, unsynced contents lost, half there or whole. In every one the
  node loads a whole snapshot, the old or the new; a save that returned success is always what
  is found; and the next save and start are as any other. Removing the sync from `save` fails
  the test.
- An empty file, a truncated one, one flipped bit, a text file, zeros and a changed format
  field each fall back to the snapshot before, are moved aside, and do not trip the next start.
  With both bad the node starts with nothing.
- On the real disk, a store of 301 records and a tombstone comes back identical from another
  `Persist`, and only the two snapshot files are left in the directory.

## Different from dev

Dev kept desired, observed and applied state in separate rkyv files with a manifest, a mutation
history and a compaction baseline, written by a worker. With E1's store there is no history and
no revision, so there is one file. Observed records are not kept: they are what a node sees
now, and a node that has just started sees nothing yet. When to save is node logic's (E3).
