# C35: One wire revision checked at hello, an additive level, and no silent answers

**Status:** done

**Group:** C. Comm and node logic

## Build

Before this, nothing checked that the two sides of a session speak the same wire:

- the frame version byte is checked but has never changed;
- `INTERFACE_REVISION` crossed in `Hello` and `Welcome`, and the server kept the lower of the
  two where nothing read it;
- a comm core dropped a kind it did not serve without a word, so a newer request to an older
  node ended in the caller's timeout;
- an appended field an older side ignores could silently change what a call meant
  (`on_subscribe = Latest` became from-now).

The coordinator's ruling:

- one wire revision, refused at hello on a mismatch with both numbers, as a typed error, on every
  carrier;
- an unknown kind refused at once;
- every addition whose meaning an older side would change gated per call, with a typed error that
  names the feature and both levels;
- R2's revision stays 1.

## Built

- **Wire.**
  - `INTERFACE_REVISION` (1) is the wire revision, bumped only for a change an older side would
    misread.
  - New `INTERFACE_LEVEL` (1).
  - `Hello` and `Welcome` gain an appended `level` (absent is 0).
  - `RejectReason::RevisionMismatch` (5), and `Reject` gains appended `node_revision` and
    `peer_revision`.
  - `session_revision` is gone.
  - Vectors: `HELLO` and `WELCOME` gain `01`; `REJECT` is `050102`.
- **Server.**
  - A `Hello` of another revision is turned away with both numbers. The check is in
    `Server::hello`, so it covers every carrier and recovery.
  - A kind no service takes is refused as `unsupported`.
  - `Welcome` names `Limits::level`. This is not a setting: it defaults to this build's level, and
    a test lowers it to stand in for an older node.
  - `SessionInfo::level` replaces the unread `revision`.
- **Client.**
  - `ClientError::Revision { node, client }`, from a `Reject` or from a `Welcome` of another
    revision.
  - `ClientError::Level { feature, needs, node }`.
  - `Feature` and its level table (`level.rs`).
  - `Welcomed::level`, plus `needs(feature)` on `Welcomed`, `Session` and `Client`.
  - Gated:
    - `Topics::declare` with `Latest`;
    - `shell`;
    - `Actions::run` with `detached`;
    - a signed link: an unanswered `LinkSignHello` is followed by a plain hello to read the
      level, which is then let go.
  - The facade re-exports `Feature`, `Session`, `LinkRead` and `LinkWrite`.
  - C maps both errors to `ORION_E_REFUSED`, with the words.
- **Node.** `action-forward` asks a node below `RunOnBehalf`'s level for no run. The caller gets
  `unsupported`, and the log has both levels. A node of another revision is also `unsupported`.
- **The comm core's own clients.** Topic peers, the device gateway and enrollment send the level
  and refuse a `Welcome` of another revision, in words.
- **Devices.** The device core takes a `Welcome` of another revision as `Rejected(RevisionMismatch)`
  and says hello again later.
- **The web client.** It refuses another revision, from a `Welcome` or a `Reject`, with both
  numbers in the error.
- **Tests.** New `orion_stubs::older::OlderNode`, a link with a node from before the level on it:
  it welcomes with no level and drops what it does not know, as such a node does.

## Proved by

- `orion-server`:
  - a `Hello` one revision above and one below is turned away with both numbers;
  - `Welcome` names the level;
  - unknown kinds are refused under their `seq`.
- Per carrier, a `Hello` of another revision is told both numbers:
  - the Unix socket;
  - TCP (signed);
  - a serial port (pty);
  - a USB link handed over;
  - a WebSocket;
  - recovery's socket, which also names the level.
  The device core, as the device end of a link, turns away a `Welcome` of another revision.
- `orion-connect` `older`:
  - another revision, from a `Welcome` and from a `Reject`, is `Revision` with both numbers;
  - a node naming no level is at 0, and this build's board at `INTERFACE_LEVEL`;
  - a signed link to a board from before them is `Level { SignedLink, 1, 0 }`, and the only
    frame dropped is the signed hello.
- `orion` `older`: against the older node, `Latest`, `shell` and a detached run each fail with
  `Level`, naming the feature, and send nothing. A from-now declare and a run that is not
  detached do reach it.
- `orion-node-app` `forward`: a run for a caller on the left is refused `unsupported` by a
  level-0 right node, and its program never sees it.
- Not vacuous: 12 mutations, each caught:
  - the server's revision check and its unknown-kind refusal;
  - the client's two revision checks and the probe;
  - each of the three call gates and the forward gate;
  - `Limits::level` ignored;
  - the device core's check;
  - the level comparison off by one.

## Different from the brief

- **One number for the level, not named capabilities.** Every feature so far comes from one
  repository and arrives in order. A node at level N knows everything at or below N, in recovery
  as well, since the same build serves both. Whether a node *serves* a thing is a different
  question, and the unknown-kind refusal and the service's own refusals answer it: recovery
  without a shell says `unsupported`. Names would cost bytes in every hello and string matches on
  every gated call. They would buy independence the code does not have. If two lines of
  development ever diverge, named facts can be added to the hello beside the number.
- **`RunOnBehalf` refuses the forwarded run outright.** It does not send the run without the
  field. An older far node would take every caller behind the link as one and never hear one end,
  which is the gap C34 closed.
- **The signed-link probe** costs a second wait when the board does not answer at all. The
  signed hello goes before any session, so there is no `Welcome` to read the level from first.
- **R2's level.** `dbd5fc0` sends no level, so it reads as level 0 although it knows every
  level-1 feature. The Orion rev that boards take must be this one or later.
- Not run against a real `455a956e` comm core. `OlderNode` stands in for one, modelled
  on that rev's server code: `dispatch` drops unknown kinds, `hello` decodes only `HELLO`. Whether
  an old serial carrier takes the plain hello after the dropped signed one is not shown.
