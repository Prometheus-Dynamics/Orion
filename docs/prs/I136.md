# I136: The browser tests declare what they read outside the crates

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I135

Read `AGENTS.md` and `docs/design.md` first.

## Why

orion-web-tests is the largest consumer of the tests lane on a change it can't see. On a
comment in orion-types, it is 20.9 CPU-s of test processes and the lane's slowest test (video,
21.8 s). It ran on every such change.

The cause: its sources name paths outside the crates (`../../../web`), so `reaches_outside`
gave it every file outside the crates in its key, and never a key by its binaries. Reaching
was all-or-nothing: no package could say what it reads.

## Changes

- **orion-web-tests declares `test-reads = ["web"]`.** Its keys hold every file of `web/` by
  content: the source key as for any test-reads, and the binary key through
  test_binary_inputs.
- **A path inside a directory the package declares no longer counts as reaching outside the
  crates (`declared`).** The path is taken from the package's directory (where cargo runs its
  tests and CARGO_MANIFEST_DIR points) or from the root.
- **`Path::new(env!("CARGO_MANIFEST_DIR")).join("<a declared path>")` no longer refuses a key by
  its binaries (`DECLARED_JOIN`, `Keys.names_own_sources`).** Any other mention of
  CARGO_MANIFEST_DIR still does. The plan self-test's packages that mention it come from the
  same method.
- **A test that a path holds no `..` (`.contains("..")`) is no path (`DOTDOT_CHECK`).** The
  page server in browser.rs makes one.
- **Anything else outside the crates still makes the package whole-tree:** every file outside
  the crates in its key, and no key by its binaries.

Only orion-web-tests changes, of the 95 packages: before, it reached outside and had no binary
key; now it reaches nothing undeclared and is keyed by its binaries. The other 94 have the same
`reaches_outside` and `binary_keyable` as before.

## Proved by

Self-test plants (scripts/lane-reuse.py):

- **A file in `web/` changed:** orion-web-tests' source key moves, and its binary key moves.
- **A file outside the crates it doesn't declare changed** (examples/mcu-template): its source
  key stays.
- **An undeclared outside read planted in its tests** (`std::fs::read("../../../scripts/gate.sh")`):
  - with that read in place, a file outside the crates changed moves its source key
    (whole-tree);
  - and it is not keyed by its binaries.
- **CARGO_MANIFEST_DIR joined to an undeclared path** (`tests/client.rs`, its own source): not
  keyed by its binaries.
- **orion-ctl reading a file in `web/`,** which another package declares: not keyed by its
  binaries.
- **orion-ctl checking a path for `..`:** still keyed by its binaries.
- **orion-web-tests as it stands:** keyed by its binaries.

Mutations, each failing the self-test 3 runs of 3:

| Mutant | Fails on |
|---|---|
| No declared check | a file outside the crates that a package does not declare: the key moved |
| A path always declared | an undeclared outside read: the key did not move |
| No `..` check | a file outside the crates that a package does not declare: the key moved |
| No declared join | by its binaries, a file in a declared directory: the key did not move |

I135 came first, because web-tests' tests/client.rs holds a raw string with quotes in it,
which would have hidden an undeclared path after it.
