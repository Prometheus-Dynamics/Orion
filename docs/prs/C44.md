## Build

`Finished` gets an appended, typed `code`: the callee's status code (a service's pending-trial
`BUSY`, say), next to the outcome, output and detail. A caller then branches on a code, not on
the detail text. Older nodes leave it out. Define how a service sets it, and keep the words in
`detail`.

## Built

- **Wire.** `ActionResult` gains an appended `code: u32`, where zero means none. An older
  sender gives none and an older reader ignores it. The recorded vector line for
  `ACTION_RESULT` is extended (the sample gives 11), keeping the old bytes as its prefix, as
  `Run.on_behalf` was in C34.
- **Setting it.** `Registration::finish_with_code(call, outcome, code, output, detail)` sets
  it. `finish` is `finish_with_code` with zero. What a code means is the action's to define and
  document, and the words go in `detail` as before.
- **Reading it.** `orion_actions::Finished.code`.
- **Passed on as given.**
  - Node logic gives the program's code to the caller.
  - It keeps the code with a detached run's end, so the code comes back on attach.
  - A forwarded run carries it back across nodes (`link::Event::Result.code`).
  - The stubs' router passes it too.
  - Orion's own ends give zero: a deadline, a program that went, node logic stopping, a node
    that went, and a program too busy to take the run.
- **Not set:** the microcontroller library (`orion-device-actions::finish`) and the C library
  send none, so the code arrives as zero. The web client does not read it yet. `lock.md` says
  so.

## Proved by

- `action-list/tests/list.rs`, `whoever_started_a_detached_run_comes_back_to_its_progress`:
  code 11 reaches the caller and comes back again on attach.
- `actions/tests/actions.rs`: a program finishes with code 11 and the caller's `Finished` has it,
  with the words still in `detail`.
- `node-app/tests/forward.rs`: code 7 from a program on the right node reaches a caller on the
  left, through both nodes' logic and the forward link.
- `wire-vectors`: the extended line holds.
- Mutations, 6 of 6 caught: the list passing it on, keeping it on attach, the client reading it,
  the provider sending it, the link keeping it, forwarding passing it on.
- The gate passed.

## Different from the brief

- The brief said `Finished`. On the wire the message is `ActionResult`, and `Finished` is the
  client's view of it; both carry `code`.
