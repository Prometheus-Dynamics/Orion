# C37: Why a session ended is said, and a program on the board is not dropped for being quiet

**Status:** done

**Group:** C. Comm and node logic

**Wave:** 18

Read `AGENTS.md` and `docs/design.md` first.

## Changes

`crates/comm/server`, `crates/comm/unix`, `crates/comm/relay`, `crates/comm/self-status`,
`crates/client/connect`, `docs/comm.md`, `docs/client.md`

## Build

Three things made a lost session hard to explain:

- the comm core ended sessions without a word in its log. `stats.dropped` went up by one, for a
  missed hello, a quiet session and a stalled write alike;
- a client pinged once a heartbeat against an idle time that could be set as low as two
  heartbeats, so one late ping ended a healthy session;
- a program on the board that stopped pumping its session for three heartbeats was dropped,
  with its topics, actions and leases, though its socket was open and it was alive.

## Built

- **Every session the comm core ends is logged at `warn`**: its name, who it was, and why, as
  `orion_server::Dropped` with the numbers:
  - `NoHello { limit_ms }`, `Quiet { quiet_ms, limit_ms }`, `ReadFailed(kind)`, `Damaged`,
    `OutOfTurn { kind }`, `Rejected(reason)`,
    `OutboxFull { kind, frame, waiting, limit }`, `WriteStalled { limit_ms }`, `Panicked`,
    and `Ended(why)` for a service's own reason;
  - the first reason given is the one kept;
  - a session its own program closed is not a drop and is not logged;
  - the last 16 are kept and read with `Comm::drops()`;
  - `Sessions::close_because(session, why)` is how a service says why. The relay uses it when
    a second node logic attaches.
- **A local session is not ended for being quiet.** `Connection::local()` says the other end
  is a program on this board over a socket that reports a hang-up; the Unix carrier answers
  yes, every other carrier no. Past the idle time such a session is logged once as quiet, has
  `SessionInfo::quiet_since` set (and is counted in the new `quiet` field of `orion.comm`),
  and is logged at `info` when it is heard again. It still ends on a hang-up, at the write
  deadline, on a damaged frame, and at the hello deadline if it never says hello.
- **The idle floor.** `comm.idle_ms`, when set, must be at least three heartbeats and at least
  1000 ms, or the settings are refused at load with the number it must reach. With none set
  and heartbeats under a third of a second, it is 1000 ms.
- **The client pings twice a heartbeat** (`heartbeat / 2`), from the first one on.
- **The client keeps a silent comm core on the board's own socket**, for the same reason the
  comm core keeps a quiet program there. Over a network or a link it gives up at the idle time
  as before.
- The docs say that a session lives only while its program pumps it, and that it ends when
  every process holding its socket has closed it.

## Proved by

- `server/tests/drops.rs` (the server tests' harness moved to `tests/common`, to keep `server.rs` under 800 lines):
  - each reason, in order, with its numbers, the name and who it was, and the words;
  - a session that does not read: `OutboxFull` with the kind and sizes;
  - a local session an hour quiet is kept, seen as quiet since it was last heard, counted as
    no drop, answered when it speaks, seen again when quiet again, gone at once on hang-up,
    and still dropped if it never says hello.
- `unix/tests/unix.rs`: the same over a real Unix socket in real time.
- `relay/tests/relay.rs`: the first node logic's drop says a second attached.
- `server` unit test for the floor, from settings text.
- `connect/tests/alive.rs`, against a stand-in comm core: ten pings in five heartbeats and none
  when the program does not pump; a silent comm core on a link is lost at the idle time; a
  silent one on the board's socket is kept for ten heartbeats; one that closes the socket is
  lost at once.
- 21 mutations, 21 caught (c37-mut.py). One was caught by a hang, which the run counts as caught after 150 s.
- The node-app suite was run 6 times.

## Different from the brief

- The brief named "node sessions/status" as where the quiet state shows. There is no listing
  of sessions in any tool today. The state is on `SessionInfo`, in the log, and as a count on
  `orion.comm`; a listing is not built here.
- The floor applies to limits read from settings. Limits a test builds itself are taken as
  written, because the suites run real links at 50 ms heartbeats.
- `stats.dropped` no longer counts a local session that went quiet, since it is not dropped.
