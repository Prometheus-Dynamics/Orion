# I132: A board away keeps its port from the boards that choose one meanwhile

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I131

Read `AGENTS.md` and `docs/design.md` first.

## Why

A tests step went red on
`orion-node-app::all sync::records_reach_the_other_node_both_ways_and_after_it_was_away`: the
board starting again on its port failed with `listen: AddrInUse`
(`crates/testing/stubs/src/lib.rs:420`), and then `the board starts: RecvError`.

Since I23 and I35, every stub board chooses its port below the ephemeral range, where only a
socket that names a port gets it. But every other test's board chooses its port in that range
too. While a board is stopped, waiting to start again on its port, another test's board can
choose the same port.

## Changes

- **Each port a board chooses is held for the life of its test process,** by a socket in the
  abstract namespace named for that port (`orion-stubs-board-port-N`).
  - No other process can make that socket while it is held.
  - It goes when the process ends, and leaves no file behind.
- **Every board that chooses a port skips one that is held,** whether in this process or any
  other.
- **A board started again on its own port binds it directly, as before.**
- **`another_board_chooses_its_port_from`** is a test-only hook (`#[doc(hidden)]`): another
  board choosing its port with a given port as its first choice.

Every harness with this pattern chooses its port through
`orion_stubs::listen_outside_the_ephemeral_range`, so all of them are covered. The tests that
start a board or node again on a fixed port:

- `orion-node-app` `sync.rs` (the red one) and `forward.rs`;
- `orion` `facade.rs` (three tests);
- `orion-connect` `connect.rs`, through its own harness in `tests/common`;
- `orion-topic-peers` `across.rs`, through its own node harness;
- `orion-stubs` `port.rs`.

## Proved by

- A new test, `a_board_away_keeps_its_port_from_the_boards_that_choose_one_meanwhile`: a board
  stops, another board chooses a port with that board's port as its first choice, and the first
  board starts again on its port.
  - Red without the fix: the other board was handed the port.
  - With the other board's port left unchecked, the red's own signature appears:
    `listen: Os { code: 98, kind: AddrInUse }`, then `the board starts: RecvError`.
- Mutants, 3 runs each, both red:
  - the hold dropped as soon as the port is bound;
  - a held port taken anyway, under another name's hold.
