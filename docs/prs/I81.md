## Why

The second part of the clock row. The board has no battery on its clock. After power-up its
clock is not set, and that is the normal good state until a source answers. Nothing refuses for
want of time, but the board should say where it is, before and after a tool connects.

The hardware clock survives a warm restart, so it is a floor. And the kernel copies the system
clock to the hardware clock (`RTC_SYSTOHC`) only while the clock is marked synchronized. So the
kernel must hear "synchronized" only when a source vouches for the clock.

## Built

- **Saying it.** These say nothing when `time.sync = off`.
  - The hello fact `clock` is `synced` or `unset`, asked of the time sync each time the
    document is made. A client reads it with `Node::clock`. The broker reserves `hello.clock`.
  - The announcement's `clock=` key carries the same word. The responder asks for the word each
    time it looks at the interfaces (every 2 s, `orion_mdns::Retell`). When it has changed, the
    record is announced again on every interface (RFC 6762 §8.4). The record stays layout 2,
    and is at most 478 bytes (was 465).
  - `orion/state` gains a line: `clock: synced from <source>`, or `clock: not set (sources
    tried: ...; last: ...)`. When the board only reports, `time.sync = report;` comes first.
  - `orion-ctl node time` adds a line when the board says `unset`, naming `node offer-time`.
- **The hardware clock as a floor** (`time.rtc`, default `/sys/class/rtc/rtc0/since_epoch`,
  `off` for none).
  - It is read once at start beside the saved time, and a clock behind the later of the two is
    stepped forward to it.
  - A reading before this build existed is no floor: that is 1970, after power-up with no
    battery.
  - The saved time stays the anchor for peers.
- **What the kernel is told.** Slews and steps already cleared `STA_UNSYNC`. New, while
  disciplining, it is set (`orion_measure::clock::unsync`, `Clock::unsync`):
  - at start, after any floor step, so neither a floor nor a run before this one vouches for
    the clock;
  - after 8 polls in a row with no answer once synchronized (NTP's reach register). The status,
    the time-synced file and what is served say unsynchronized too, and the rule against
    backward steps stays;
  - when the time sync stops.

  Reporting never touches the kernel.

## Needs a board look

This is read-only, and I will ask before doing it. On a board, `zcat /proc/config.gz | grep
RTC_` should show `RTC_HCTOSYS=y`, `RTC_SYSTOHC=y` (both on rtc0) and `RTC_DRV_RPI=y`. With
Orion synced, `since_epoch` should follow the system clock after the 11-minute write. None of
the code here depends on what that shows.

Thirteen mutants each failed 3 of 3 runs:
- in orion-time: the loss rule never firing, no unsync at start, the hardware clock ignored, a
  lost clock still served as synced, no unsync on stop;
- the hello fact left out;
- the responder not announcing a change, and the run loop not asking;
- the comm core not wiring the hello or the state line, and the word left out of the TXT
  strings;
- the client reading the wrong fact.

**One mutant survives, and is the same in effect:** the first record built without the word.
The responder's next look, 2 s later, finds the word differs from what was said and announces
it, before the test's browse. That is the re-announce path working on a real comm core. So no
single test fails if only that path breaks, or only the first record: either one covers for the
other. A change of word on a running board (unset to synced) is not driven end to end: a
disciplining sync reaching synced needs `CAP_SYS_TIME`, which tests do not have. The pieces are
each tested: the word, the responder's re-announce on real sockets, and the TXT strings.

## Size

The first gate was red at size: `orion` for a board was 5,517,760 bytes, over its limit of
5,510,000, and 22,496 over I80's 5,495,264.

**Cut first:** the re-announce was a task of its own fed by two watch channels (one in the time
sync, one to the responder). The responder already wakes every 2 s to look at the interfaces, so
it asks for the word then, with no task and no channel. That took 8,600 bytes off: 5,509,160,
which is 13,896 over I80 and 840 under the limit. The limit is not raised here.
