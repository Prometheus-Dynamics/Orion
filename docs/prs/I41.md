## Why

I39's check failed on CI, though it passed locally. CI sets `CARGO_TERM_COLOR=always`, so
`cargo tree` colours the ` (*)` it puts after a package already shown. The script strips
` (*)` before splitting a line into package and features. A coloured one is not stripped,
and a repeated package is then read as having the features `(*)` wrapped in escape codes.
Every package the group shows twice then seemed to differ: 46 on CI.

## How

`cargo tree` is run with `--color never`. The answer no longer depends on the terminal or
the environment. The stamp key covers the script, so stamps from before are not used.

## Proof

Before, with `CARGO_TERM_COLOR=always`, the `orion-types,orion-check,orion-supervise` group
on `riscv32imac-unknown-none-elf` fails with the two differences CI showed, every time.
After, with the same setting, both targets and both groups give "the same features together
as alone".
