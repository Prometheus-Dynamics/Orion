## Build

What the lock revision promises, made true before it is declared: a refusal reaches a program with
the node's words; a tool can learn the key of the node it reached; a ring of another layout is
refused by name; the node's own hello facts cannot be published by a program; `updating` is gone;
an unknown USB link name says which names there are; and only a lease's holder frees it.

## Built

**Refusals carry the node's words.** `ClientError::Refused { error, detail }`. `detail` is what
the node sent, verbatim, or the error's own name when it sent none, so it is never empty
(`ClientError::refused(error, detail)` builds one). `Client::refusal(seq)` now gives the whole
`ClientError::Refused`, kept with its words. Display is `refused: <error>: <detail>`, or
`refused: <error>` when the words are only the name. `ClientError::refusal()` gives the code.

**The node's key.** `Welcomed` gains two fields:

- `signed: bool`: whether the session's frames are signed;
- `node_key: Option<[u8; 32]>`: the key the node proved. Set at connect on a signed handshake (TCP
  and signed serial/USB links, from the handshake's `server_key`, which was checked against a pin
  and dropped before).

On a plain session `node_key` is `None` until asked. `Session::node_key()`, `Client::node_key()`
and `Orion::node_key()` ask once (`Identify` with a fresh 32-byte nonce), check the signed answer
with `hello::verify`, and keep the key in `Welcomed`. A bad signature is `ClientError::Denied`.
`Client::node_key` takes the answer before the handlers, so frames meanwhile still reach them.
`Orion::node()` (`crates/client/orion/src/node.rs`) already proves the key, so it keeps it too.

**Layout (21).** `Error::Layout = 21`, "shared memory is of another layout", level 2
(`LAYOUT_LEVEL`). A session below it hears `malformed`. The broker adopts an offered ring before
giving it to the topic (`topics::adopt`). `RingError::Layout` is refused 21 with "this ring is
layout 1; this build reads layout 2: rebuild the publisher at or after the device library's
ad5bf930" (`orion_broker::REBUILD`). Any other ring that does not read is `malformed`, as before.

**The node's own hello facts.** `orion_broker::NODE_FACTS = ["hello.state",
"hello.recovery_why"]`. Declaring either topic is refused `denied` with "hello.state is the node's
own hello fact: a program cannot publish it". Hello's test checks the list is
`FACT_PREFIX + STATE_FACT` and `FACT_PREFIX + RECOVERY_WHY_FACT`.

**`BoardState::Updating` removed.** The states are `running`, `recovery` and `flasher`.

**USB.** A handle offered for a link name the board does not have is logged at warn, with the name
offered and the names known. It is refused `not found` with "no USB link named usb9 here; known:
usb0" (or "known: none").

**Who frees a lease.** Deleting a lease record is allowed to:

- the session that wrote it;
- a caller whose principal (as the audit log names it: `local:1000`, `operator:<key>`, ...)
  equals the lease's holder;
- root.

Anyone else is `denied`, with "<resource> is held by <holder>: only its holder or root frees it".
A lease that has ended, or is not there, holds nothing, and anyone may clear it.
`orion_resources::Caller { session, principal, root }` is what `Resources::check` takes now.

**Security off, hello signed.** A test pins it: with security off, a nonce on the board's socket
and a connection off the board with no nonce both get an answer signed by the board's key.

**`shm-ring-latest`** is no longer a workspace dependency. No crate used it.

## Break list (for the lock declaration)

- `ClientError::Refused(Error)` is now `ClientError::Refused { error, detail }`, and `ClientError`
  is `#[non_exhaustive]`.

  ```rust
  // before
  Err(ClientError::Refused(Error::Busy)) => wait(),
  // after
  Err(ClientError::Refused { error: Error::Busy, detail }) => { log(&detail); wait() }
  Err(ClientError::Refused { error, .. }) => fail(error),
  _ => ...,   // needed outside orion-connect
  ```

- `Client::refusal(seq)` returns `Option<ClientError>` (a `Refused` with words), not
  `Option<Error>`. `.and_then(|refused| refused.refusal())` gives the code.
- `Welcomed` has `signed` and `node_key`, and is `#[non_exhaustive]`: it is not built outside
  `orion-connect`.
- `Error::Layout = 21` (level 2). Older sessions hear `malformed`.
- `BoardState::Updating` is gone. The hello `state` values are `running`, `recovery` and `flasher`.
- A program that declares `hello.state` or `hello.recovery_why` is refused `denied`.
- Freeing a lease another holds is `denied`, unless by its holder or root.
- `orion_resources::Resources::check` takes a `Caller`, not a session number.

## Lock notes

- Every publisher that offers its ring to the broker is built against the device library at or
  after `ad5bf930`. An older one is refused 21 and told to rebuild.
- Orion holds no copy of the shared-memory crates. They are pinned by revision in `Cargo.toml`.
- A tool that connects signed with no pin reads `Welcomed::node_key`. On a plain session it calls
  `node_key()`. This is the call for a tool's pin flow.
- Security off, the hello answer is still signed when a nonce is given, or when the asker is off
  the board.
- Builds:
  - Windows and macOS: the gate runs clippy, tests included, for the client crates on
    `x86_64-pc-windows-msvc`, `x86_64-pc-windows-gnu`, `x86_64-apple-darwin` and
    `aarch64-apple-darwin`, as before. J9 adds nothing platform-specific: `welcomed.rs` is
    portable, and the broker, hello and USB changes are in Linux-only crates.
  - Without the device library: there is no such build today. Every client build takes
    `shm-sample-time` from it (`orion-connect` alone, and `orion` with no features). With its
    default features `orion` also takes `shm-ring`, `shm-ring-doorbell` and `shm-ring-time`
    (on Windows too).

## Different from the brief

- Display of a refusal names the code as well as the words (`refused: busy: cam.front is held
  ...`). The brief had `refused: <detail>`. The code's name in front says what kind of refusal
  it is.
- The holder of a lease is text the writer chooses. Anyone may write a lease with the same holder
  text, which renews it and makes that session its writer, and then free it. The rule stops a
  stray free, not a program that sets out to take a lease. The node cannot tie a holder name
  like `workload:detector` to a principal. Closing that needs holders to be principals, which is
  not in this brief.
- A holder whose session has ended, or that node logic forgot in a restart, is not the writer
  any more. It frees by writing the lease again first. Before, anyone could free it.
