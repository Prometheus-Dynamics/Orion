## Build

After I11, each slow step was faster, but the steps still ran one after another. Most of them
build in a target directory of their own, so nothing stops them from running beside clippy and
the tests.

## Built

- **Lanes.** After the lockfile and format checks, these start in lanes:
  - the feature matrix;
  - the no_std checks and the client's clippy on other systems, in
    `$CARGO_TARGET_DIR/other-systems`;
  - the size gate;
  - the device size, mcu template and packaging checks, one after another. The device size has
    `$CARGO_TARGET_DIR/device-lane`.

  Clippy, the tests and the compiled-out check run in front. Then `the steps beside` waits for
  every lane, prints what each said with its time, and fails if one failed.
- **What fails still fails.** In a lane, each step runs plainly under `set -e`. A function run
  as `command || ...` has `-e` ignored inside it, so a failing step in the middle of
  `other_systems` would not have stopped it.
  - The lane stops at its first failure, and its exit trap names the step.
  - Each lane is a process group of its own. If the gate stops first, its exit trap ends every
    lane by its group's id.
- **Fuzz alone, last.** A fuzz target's budget is time, so with the lanes beside it a target
  tried less: 114,054 runs of `frame` in its 3 s, against 888,604 alone. It runs after the
  lanes, as I11 left it.
- **Cheap checks first.** Boundaries and links build nothing, and now run before anything that
  does.

  - This gate took 110 s, with three new target directories filled for the first time. In

    device size (cold), 80 s for other systems (cold) and 38 s for the matrix.

- **A lane's failure fails the gate.**
  - **No_std:** `extern crate std` for `target_os = "none"` in `orion-check`, the first of the
    no_std checks, with every later one passing. The gate exits 1 with `FAILED: orion-check on
    thumbv7em-none-eabihf`, and the device size lane fails on it too.
  - **The lane machinery alone:** a function whose middle step fails and whose last passes fails
    its lane, and the gate. A gate that stops while a lane runs ends the lane with it: no lane
    process is left.
