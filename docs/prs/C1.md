## Build

- `Carrier` and `Service` traits as in the design.
- One async thread. Per-session bounded queues and deadlines.
- A service can only be reached with a `Checked<T>`.
- One bad session cannot stall another.

Built with one change: a service call is a plain function that returns at once, not an `async fn`.
Nothing a service does can then wait on a session, which is what makes the last line checkable, and
it needs no allocation per request. A service with slow work does it in its own task and answers
through `Comm::with`. See `docs/comm.md`.

## Proof

A misbehaving session test. 0 allocations per request in steady state.
