# I112: A microcontroller's size builds run beside the others'

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I111

Read `AGENTS.md` and `docs/design.md` first.

## Why

The one-minute rule (2026-11-24). After I111, a change to a leaf crate (`orion-device-probe`)
took a 145 s gate at load 134 to 150. The devices lane was the last to end, and the main part
waited 66 s for it. In that lane, `scripts/device-size.sh` took 78 s on 17.5 CPU-s: twenty
small builds of the probe, four targets of five variants each, one after another. Each is a
single-threaded fat-LTO link, and each waited.

## Changes

- **`scripts/device-size.sh` builds each target beside the others**, and beside the firmware's
  builds, each in a target directory of its own: cargo holds a target directory for one build
  at a time. Each target prints to a file of its own, and the files are read back in order. A
  target whose builds fail is a failure, named.
- **`scripts/work-area.sh`** says how an empty subvolume is removed: `rmdir`, by its owner. That
  is how one was removed here; `btrfs subvolume delete` was refused.

## Proved by

The same leaf change (a comment added to the probe, then taken out), the script before and
after, 3 rounds, order alternated, load 84 to 120:

| Script | Wall | Median | CPU-s |
|---|---|---|---|
| before | 29.6, 38.2, 27.5 s | 29.6 s | 14.5 to 14.8 |
| after | 12.2, 17.4, 9.2 s | 12.2 s | 14.8 to 15.2 |

All 24 measurements were the same, byte for byte, before and after. The first run after the
change builds each target's directory once: 93 CPU-s.

## Measured

Filled in at landing: the leaf and core changes' gates, with the load each ran under.
