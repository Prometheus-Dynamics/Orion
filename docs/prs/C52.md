## Build

The comm core runs as root only so that it can start logins as other accounts. Move that into
a login helper, the one process that becomes other users. The comm core then runs non-root
with only `CAP_SYS_TIME` and `CAP_NET_BIND_SERVICE`, and the helper's bounding set is
`CAP_SETUID`, `CAP_SETGID`, `CAP_CHOWN` and `CAP_KILL`.

- The helper starts each SSH connection's child too, always as its own `ssh.sandbox_user`. A
  client never names that account.
- The helper is a separate socket-activated unit (`orion-login.socket`) and exits when idle.
- It decides each login again, in parity with the comm core under each state of the security
  switch: Off, On, Damaged and not told. There is a test for each.
- Recovery goes through the helper too, with the test "broken settings + recovery key logs in
  through the helper".
- Size: measure with the helper in, find cuts elsewhere first, and bring the numbers before
  any limit moves.

## Built

### The helper

`orion login-helper` (docs/comm.md, "The login helper") listens on `login.helper`. When the
system starts it, the listening socket comes in as its input (`StandardInput=socket`).

- **Who may ask.** It answers the uid in `login.comm_user` and no other, by `SO_PEERCRED`.
- **Deciding again.** Each question is decided again with what is read at that moment: the
  switch, by `SecurityView::read` (the comm core's own reader), and the trust store, by the
  new `Keys::read_only` (it parses the trust file, makes no seed and writes nothing).
  - An SSH login runs `Keeper::login` with the key the client proved.
  - A shell over a session runs the check with `orion_ssh::SHELL` (root, local, operator,
    which is what `orion-shell` used), then `Keeper::admit`.
  - Only after that does it start the session, through `Keeper::start_here`, the code that
    started sessions in the comm core before.
- **Sandbox children.** A child is started as `ssh.sandbox_user` from the helper's own
  settings, becoming that account between fork and exec. A sandbox user that is root is
  refused.
- **Idle exit.** Running sessions and children are counted: each status socket is relayed
  through a socket pair, and the count drops when the code has crossed. The helper exits once
  none is running and nothing has been asked for `login.idle_ms` (10 s).
- **Recovery.** The comm core says it is in recovery, and the helper then decides with the
  recovery keys file, read the way recovery reads it.
  - When the helper's own settings cannot be read, it does what recovery does: it uses the
    last good start's record, or nothing.
  - In that case it answers recovery questions only.

### The comm core

The `Keeper` takes the helper with `with_helper(path)`.

- With a helper, `start` forwards what was admitted: the account, plus the key or the
  principal. `login` and `admit` no longer require root ("can become").
- Without a helper, it behaves as before.
- `admit` now takes the principal, so the helper can be told who asked.
- `ssh-sandbox` starts its children through the helper (`Child::Helper`) and no longer drops
  ids itself.
- In recovery, a comm core that cannot read its settings and is not root uses the usual socket
  (`/run/orion-login/login.sock`) if it is there.

### Packaging

- **`orion-comm.service`:**
  - `User=orion-comm` (new sysusers entry, 902, in `orion` and `dialout`);
  - capabilities `CAP_SYS_TIME CAP_NET_BIND_SERVICE` (ambient and bounding) and
    `NoNewPrivileges=yes`;
  - `ORION_LOGIN_HELPER=/run/orion-login/login.sock`;
  - with sessions gone from the unit, it adds `ProtectKernelTunables`, `ProtectHostname`,
    `RestrictNamespaces` and `RestrictSUIDSGID`.
  - systemd re-owns `StateDirectory=orion` to the new user on the first start of an existing
    board.
- **`orion-login.socket`:** mode 0600, owned by `orion-comm`.
- **`orion-login.service`:** root, group `orion`, bounding set `CAP_SETUID CAP_SETGID
  CAP_CHOWN CAP_KILL`, `Restart=no`.
- **`packaging-check.sh`:** now loads the two new units and scores the comm core:
  - before this PR the comm core was left unscored because it was root;
  - it now scores 4.7, against a limit of 5.0;
  - before the four new lines it scored 5.7.
- **BusyBox boards:** no change. The comm core there stays root and starts logins itself.

The helper adds 41.6 KiB of `.text`:

- `orion_ssh` +25.7, almost all of it `login::serve` (17.6 KiB), which inlines the login
  check, `Keeper::login` and `start_here`;
- `orion_comm_app` +4, `orion_bin` +3.2, `Keys::parse` +2, postcard and `shm_fdpass` +1.2.

Folding the two branches of `answer` into one `start_here` call saved 0.5 KiB.

The cut elsewhere is one codegen unit for `profile.service`, which `profile.device` already
had. It costs a single-threaded final link: an `orion` build took ~6.5 min against ~6 before.

No limit moved. Tightening them to the new numbers comes in its own commit after this one,
from the gate's board numbers.

## Proved by

- `orion-ssh` `tests/login.rs`:
  - the helper decides as the comm core does under not told, Off, On and Damaged: who
    starts, who is refused, and root when it is not allowed;
  - only the comm core's user may ask;
  - a sandbox user that is root is refused;
  - it exits when idle, but not while a session runs;
  - in recovery the recovery keys decide.
- `orion-shell`: a shell over a session is started by the helper (`id -u`, a terminal, the
  exit code), and no shell starts once the helper has gone.
- `orion-ssh-sandbox`: the children and the sessions are started by the helper. A key
  revoked on disk is refused by the helper while the comm core's copy, read once, still
  lets it in.
- `orion-comm-app` `tests/recovery.rs`: with broken settings, a recovery key logs in with
  OpenSSH through the login helper, and once the helper has exited idle, nothing starts.
- **Mutations, each killed:**
  - the uid check removed;
  - the root sandbox user allowed;
  - the idle exit ignoring running sessions;
  - the switch read as Off;
  - the SSH and shell recovery branches using the ordinary trust store;
  - the comm core ignoring its helper (killed by the shell, sandbox and recovery tests; the
    sandbox test needed the revoked-key step to kill it).
- `scripts/packaging-check.sh`: the units load, and the comm core scores 4.7 (limit 5.0).
- The board run comes next: the helper under capsh and the comm core under setpriv, the
  helper's RSS with a session open, and the capabilities in `/proc`.

## Different from the brief

- `login.helper` is set in `orion-comm.service` (`ORION_LOGIN_HELPER`), not in the shared
  `orion.conf`. A BusyBox board reading the same file has no helper and would let nobody in.
- The comm core's unit gained four hardening lines and an exposure limit. They were possible
  once no session runs in it.
- The size was met by a profile cut, not by trimming the helper. The helper itself is 41.6
  KiB.
