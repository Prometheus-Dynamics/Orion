# E21: Forgiving a stale peer

**Status:** done

**Group:** E. Node logic

**Wave:** 14

**Needs:** E19

**Runs:** cloud

Read `AGENTS.md` and `docs/design.md` first.

## Changes

`crates/core/wire`, `crates/core/msg-peers`, `crates/comm/relay`, `crates/node/sync`,
`crates/node/node-app`, `crates/client/orion`, `crates/client/ctl`

## Build

- A request that says where sync is with each peer, and one that forgives a stale peer, so a
  node away longer than deletes are remembered can sync again when someone accepts it.

## Proof

Two nodes stale to each other do not sync; once both forgive, they do.

## Built

- Kinds `PEER_STATUS` (0x6A), `PEER_FORGIVE` (0x6B) and `PEER_STATES` (0x6C). Bodies
  `PeerStatus`, `PeerForgive { node }`, and `PeerStates { request_seq, peers }` of
  `PeerState { node, state, agreed_ms }`, with `SyncState` Down, Syncing, InSync, Stale.
  Wire vectors recorded.
- `orion-relay` `SYNC_ASKED`: both from programs on the board and operators with the grant;
  status reads records, forgiving writes them.
- `orion-sync` `Sync::peers()`: each peer's status and when it was last agreed with.
- Node logic answers both with `PeerStates`. Forgiving a node sync does not know is `not
  found`; otherwise sync forgives it, `sync-agreed` is rewritten without it, and it is in the
  audit log as `forgive node:NAME`.
- `Orion::sync_peers()` and `Orion::forgive(peer)`; `orion node sync` and `orion node forgive
  PEER`.

## Proved by

- `cargo test -p orion-node-app --test sync`: two real nodes whose `sync-agreed` says they
  last agreed in 1970 come up `Stale` to each other, as the client and `orion node sync` both
  say. A record put on one does not reach the other, nor after one side forgives. Forgiving a
  node that is not a peer is refused `not found`. Once the other side forgives too, through
  `orion node forgive`, the record arrives and the two are `InSync`. The forgiving is in the
  audit log and the old agreement is gone from `sync-agreed`. With the forgive call left out,
  the test fails. The node-app suite passed 40 runs in a row.

## Different from the brief

- No brief was written before this PR; E19 left `forgive` without a request.
- Forgiving is per node: each side refuses the other, so both have to forgive. A cluster-wide
  forgive would be a record, and would sync to nodes that never saw the peer go stale.
