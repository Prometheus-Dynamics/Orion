## Build

A worker took much longer from spawn to push than the gate takes. It ran the whole gate before
pushing its working branch, the lander then ran it again on the merged tree, and several workers
ran it at once on one machine, which slowed every run and made timing tests fail and rerun.
`scripts/push.sh` required a gate stamp on every branch, so a worker could not push `pr/<id>`
without running the full gate first.

## Built

- `scripts/push.sh` pushes a working branch `pr/<id>` without stamps. Every other branch, `next`
  among them, still needs a stamp on each new commit's tree, so nothing lands without a passing
  gate on exactly that tree.
- The push guard's self-test, run by the gate, pushes an unstamped commit to `pr/X1`, and then
  checks that pushing the same commit to `next` is still refused.
- `AGENTS.md` has a "Workers and landing" section with the seven rules:
  - the landing gate is the proof, and a worker runs the scoped check and its fail-before proof;
  - repeat runs are set by risk;
  - a red gate is given a named cause before anything reruns;
  - heavy jobs are capped to their cores;
  - a worker starts warm;
  - a brief names its base commit and files;
  - board runs go one runner per board.

## Proof

Each mutation turns the push guard's self-test red, and the restored script passes:

| Mutation | Self-test |
| --- | --- |
| Working-branch case removed | `self-test FAILED: a working branch was refused` |
| Every branch skips the stamps | `self-test FAILED: an unstamped commit was pushed` |
| None (restored) | `push guard self-test passed` |
