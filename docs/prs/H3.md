Round trip against a simulated host.

## Built

- `crates/device/actions` (`orion-device-actions`), `no_std`, no alloc. `ActionSpec` constants
  (name, a node or resource target, the policy, a description) are registered with
  `ActionRegister` through `Requests`, once a session and again until answered. `handle` reads
  `ActionRegistered`, a `Refusal` of a registration, `ActionClaim` for a registered action of
  this device (name and target both match) and `ActionCancel`. `progress` and `finish` send
  `ActionProgress` and `ActionResult`.
- `Policy::to_bits` in `orion-check`: the policy's byte, for a writer without serde.
- The size probe's `actions` variant and its budgets.

## Proved by

`crates/device/actions/tests/actions.rs`, against the simulated host: registrations decode as
the host reads them, policy included; a run is handed over with its arguments and deadline and
its progress and result reach the host; a claim for another action, another target, or a
target of the other kind with the same name is not this device's; no run before registration;
a cancel is passed on; a result the link has no room for is refused and sent on a later pass;
registration is said again until answered, a refusal is kept for the session, and a new
session registers again; answering runs allocates nothing.

## Different from the brief

- No table of runs on the device. The host already holds each run with its deadline, so a
  device that forgets a run (a reset) costs a timeout, not a leak, and RAM stays flat.
