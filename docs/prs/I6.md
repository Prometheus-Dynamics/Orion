## Built

- `scripts/size-gate.sh`: each form built on its own, profile `service`, and held to a
  number of bytes: `orion-recovery` and `orion` for this machine and, where the target and a
  C compiler for it are installed, static for `aarch64-unknown-linux-musl`; `liborion_c.so`
  for this machine. Built together, cargo gave each the features of all, and the recovery
  form carried what `orion` has. A step of the gate.
- `scripts/memory-report.sh`: from `/proc/PID/smaps` on a board, each process's Pss split into
  code, rings and data, the code touched since the reference bits were cleared, and a total.
- `testing/board-runs/I6-setup.sh`: the full setup on a board, then the report.
- `testing/board-runs/I6.md`: the run.

## Proved by

On the test board with the full setup (`testing/board-runs/I6.md`), the comm core and node logic
together: data 1.66 MB, rings 42 KiB, code in use 1.35 MB, three threads.

## Different from the brief

- Code is within 2 MB only as the code in use. Mapped, it is 2.87 MB: nearly all of the 3.06 MB
  of text, because the kernel maps 64 KiB around each fault. Bringing that under 2 MB means
  less text (the standard library is a fifth of it, TLS and SSH another fifth) or text laid out
  so that what runs sits together; neither is done here.
- No memory gate in CI: memory is measured on the board, by hand, with the scripts above.
