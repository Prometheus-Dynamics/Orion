# I141: CI builds with the pinned toolchain only, and the carrier's close is asserted in the log

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I140

Read `AGENTS.md` and `docs/design.md` first.

## Why

rust-toolchain.toml pins 1.99.0, and every build in the checkout uses it. But each CI job first
ran `dtolnay/rust-toolchain@stable`, which installed the current stable and made it the default,
next to the stable the runner's image already has. No build used them. rust-cache's key, however,
hashes every installed rustc. So each stable release, or each image update, moved the key and
left every job with a cold cache, though nothing in the repo had changed.

I140 left one thing unasserted: the log line saying a connection closed inside a frame.

## Changes

- **Each CI job installs the pin and nothing else** (the gate parts on Ubuntu, and the client on
  Windows and macOS). One bash step does it, before rust-cache:
  - it reads the pin from rust-toolchain.toml;
  - it runs `rustup toolchain install` with no name and the minimal profile, which installs the
    file's toolchain with its components and targets;
  - it makes the pin the default;
  - it uninstalls every toolchain not named `<pin>-*`.
- **A check step stops the job** unless:
  - `rustc -vV` says the pin both in the checkout and at `/`;
  - and `rustup toolchain list` shows no other toolchain.
- **The size gate's self-test takes "another toolchain" offline.** The old case ran rustc under
  `RUSTUP_TOOLCHAIN=stable`. With no stable installed, rustup would install one from the network
  inside the size lane.
  - Now a planted `rustc` comes first on PATH. It runs the pin's rustc, but its `rustc -vV` adds a
    line.
  - PATH is not among the variables the key reads. So the case now proves that the key sees
    `rustc -vV` itself, where the old case already passed on the variable alone.
  - The script's change moves every size key: CI measures each of them again.
- **The carrier test asserts the warn line.** `a_peer_that_hangs_up_inside_a_frame_has_closed`
  sets a tracing subscriber of its own that records each event's level and message. It requires
  `WARN a connection closed inside a frame: the part of it sent is dropped`. orion-unix gains
  tracing as a dev-dependency.

Nothing on the wire changes, and nothing a program calls.

## Proved by

- **Locally:** rustc 1.99.0 compiles the tree today. The check step's script, run here, stops on
  the other toolchains this machine holds. The install and uninstall steps are not run here: the
  machine's rustup is shared.
- **CI on the commit:** rust-cache's "Rust Versions" lists only 1.99.0.
- **Size gate self-test:** passes, with the new case.
  - Mutation: without `rustc -vV` in the key, the toolchain case fails 3 of 3 ("the toolchain left
    the key of r as it was", and the same for o and c).
- **Carrier test:** passes 3 of 3.
  - Mutation: without the `warn!`, it fails 3 of 3.

## Not covered

- No seed step. A cold run is seeded only if one comes near a bound.
