## Fault

A fetch bounded each wait for the next chunk by the session's reply rule. With the default
(`Reply::Timeout`, 5 s, which `orionctl` uses), a program that was there but quiet for 5 s,
busy reading a slow source say, ended the fetch with a timed-out error. Nothing said the
program was quiet before that. The fetch gave up by default.

## Built

- **A fetch never gives up on a program that is there.** It ends when:
  - the program gives it all, refuses or aborts it;
  - the comm core says the program went;
  - the session is lost: a comm core silent past its idle time over a network or a link, or
    its socket closed.
- **The quiet is said.** After `NO_PROGRESS` (5 s) without a chunk, a step says
  `Step::Stalled { received, size, quiet }`, then again each time as long passes. The fetch keeps
  waiting. `Fetching::stalled_after(quiet)` sets another interval. `Step` is the push's too; a
  push never says it.
- **A limit only when asked.** `Fetching::give_up_after(quiet)` is off by default. That much quiet
  at a stretch ends the fetch `Rejected` with "gave up: no progress for <quiet>, the limit set
  for this fetch", and the program is told the same words.
- **orionctl.** `file fetch` prints `NAME: no progress for N s, R of S bytes here; still
  waiting` at each stall, and `--give-up MS` sets the limit (unset by default). A fetch it gave
  up on prints `NAME was not fetched: gave up: ...` and exits 1.
- **orionctl's tests.** They moved into one binary, `tests/all.rs`, with `verbs.rs` and a new
  `fetch.rs`, as the other crates' tests did in I25. This keeps `verbs.rs` under 800 lines
  without another link.

## Proof

- `crates/comm/file-offers/tests/quiet.rs`, with a real comm core. The client session's answers
  are bounded at 300 ms, and the fetch says stalled after 100 ms.
  - A program quiet for 900 ms mid-gift: three or more `Stalled`, each with what is here, the
    size, and a quiet of 100 ms or more. The program then goes on, and the fetch commits whole.
  - With `give_up_after(400 ms)`: `Stalled`, then `Rejected` with the words, within 3 s. The
    program's gift ends not taken, with the same words.
- `crates/client/ctl/tests/fetch.rs`, `orionctl` against a board:
  - `--give-up 300` on a program quiet for 1.5 s exits 1 with the gave-up line.
  - Without the flag, a program quiet for 5.6 s gives one stall line ("no progress for 5 s, R of
    4194304 bytes here; still waiting"), then the file is in place and the exit is 0.
- Each fault planted alone fails its tests:

  | Fault planted | Tests that fail |
  |---|---|
  | The old wait, bounded by the session's timeout | all three |
  | The limit is not kept | the give-up test and the orionctl test |
  | A stall is never said | all three |
  | orionctl drops `--give-up` | the orionctl test |

- `quiet::`, `abort::` and `fetch::` ran 10 of 10 green.

Found and left alone: a program giving a file counts its own pause as the client's silence.
A gift stepped again after more than the session's timeout, with the window full, ends timed
out though the client is there. The orionctl test gives its program a 30 s timeout so that
only the fetch is tested. Reported, not fixed here.
