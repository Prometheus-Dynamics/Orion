# I126: A package with no test executable is keyed over none

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I125

Read `AGENTS.md` and `docs/design.md` first.

## Why

In the comment and unused-fn rows on 6f16cece, 10 of the 36 packages that ran had no test
executable at all. They are libraries with no tests of their own (for example
`orion-device-probe`, which has `test = false`, and `orion-msg-topics`). `binary-plan` keyed
only a package with executables, so these ran every time their source key moved, and ran zero
tests.

## Changes

- **`binary-plan` keys a package the build made something of, executables or not.** With none,
  its binary key is over no binaries and everything else the key holds: the files it builds
  that are not Rust, its declared test reads, the programs and the environment. It is reused
  while those stay the same.
- **A package the build made nothing of is still not keyed by binaries, and runs.**
- **Doctests are unchanged.** They are chosen by the source key before the build, as before.

## Proved by

- A new case in the plan self-test: a package with no test executable, passed before, is
  reused. Red on 6f16cece: it ran.
- A second case: a package with no artifact in the build is not keyed by binaries, and runs.
- Mutants, 3 runs each, both red:
  - keyed only with executables (as before);
  - a package the build made nothing of, keyed over none.
