# I133: The feature matrix builds each feature set once

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I132

Read `AGENTS.md` and `docs/design.md` first.

## Why

The feature matrix had 110 items but only 108 distinct builds. `orion-shell` and
`orion-recovery` each have one feature (`login-helper`) and no `default` key, so
`--no-default-features --features login-helper` and `--all-features` are the same build, run
twice.

## Changes

- **`scripts/workspace.py matrix` leaves out the single-feature item when a crate has one
  feature and no `default` key.** Its `--all-features` item is the same build.
- **A crate with `default = []` keeps both items.** An empty default still builds with
  `feature="default"`, so it is another rustc invocation. Five crates are like this
  (`orion-connect`, `orion-discovery`, `orion-link-can`, `orion-link-serial`,
  `orion-link-usb`), and their graphs were compared to make sure.

The matrix goes from 110 items to 108. No coverage is lost.

## Proved by

Every item's unit graph, from `cargo -Z unstable-options check --unit-graph --locked` (read-only,
nothing built), was hashed over its roots. Each root was hashed with its full dependency closure:
package, target, mode, features, profile and platform.

- **Before:** 110 items, 108 distinct graphs.
- **After:** 108 items, 108 distinct graphs.
- **The two sets of graphs are equal.** Every kept item has the same graph as before.
- **Each dropped item's graph is its crate's `--all-features` graph:**
  - `orion-recovery`: `f16e6b7604b74f45`;
  - `orion-shell`: `9d61ec2b8fc05f05`.
- **The first rule tried, "one feature and an empty default", dropped 7 items.** The 5 extra
  differed from `--all-features` only by `feature="default"` on the crate's own unit, so that
  rule was rejected.
