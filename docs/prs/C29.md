# C29: A subscriber across the network can start from the newest values

**Status:** done

**Group:** C. Comm core

**Wave:** 18

Read `AGENTS.md` and `docs/design.md` first.

## Changes

`crates/core/msg-topics`, `crates/client/topics`, `crates/client/orion`, `crates/comm/outbound`,
`crates/comm/broker`, every `TopicDecl` and `Declare` literal, `docs/client.md`, `docs/comm.md`

## Build

A subscriber that is sent samples as messages starts with nothing: a value that changes rarely
stays unknown to it until it next changes. A subscriber that reads the ring has `latest(field)`.

1. `Declare` gains an appended `on_subscribe`: 0 from now (as before, and what a body without
   the byte reads as), 1 the newest of each field first.
2. With 1, outbound sends `latest(field)` for every field that has a sample within `expiry_ms`
   (zero: always) when it starts carrying a subscription. The samples keep their own times.
   Then it goes on as before.

## Built

- `OnSubscribe`, an open enum, appended to `Declare`. `TopicDecl.on_subscribe` carries it,
  re-exported as `orion::topics::OnSubscribe`.
- Outbound's `carry`:
  - on a new subscription, sends the newest of each field, checked against `expiry_ms` on
    `SampleTime::now()`, under the same byte limit and counters;
  - a subscriber already carried, carried again because the publisher came back, is not sent
    them again.
  - The `Subscribed` answer and the ring handover go out before the subscription is told, so
    these samples follow the answer.
- The comm core's own topics declare `FromNow`. The C API declares `FromNow`.
- Peer links pass the declaration's bytes on as they are, so a mirrored topic keeps its
  `on_subscribe`.
- Wire vector `TOPIC_DECLARE` gains its last byte (`01`).

## Proved by

- `orion-outbound` network test
  `a_subscriber_across_the_network_is_given_the_newest_of_each_field_when_the_topic_asks`. Three
  fields, one published twice, one long expired. A network subscriber to the `Latest` topic gets
  the newer of the first and the second field's only sample, then nothing more. One to the
  `FromNow` twin gets nothing. Both then get what is published next.
- Not vacuous:
  - with the newest never sent, the test times out waiting for them;
  - with expiry not checked, the expired field arrives and the test fails.

## Different from the plan

- Not covered by a test: a subscription carried again because the publisher came back is not
  replayed.
