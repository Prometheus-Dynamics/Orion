## Changes

## Build

What the first program to build on C16 found:

1. **Who rings Orion's subscribers.** `wake` does, after each publish; `poll` gives the program
   no doorbell events. Said in `docs/client.md`, with the cost: one eventfd write per Orion
   subscriber that is asleep, none for one that is awake.
2. **A subscriber could not reach the pool**, only a frame's buffers through its `held`.
   `BufferSubscriber::pool()` gives the pool as it was offered (`PoolView`: each buffer's
   descriptor and where in it the buffer is). `BufferDesc` and `PoolView` are re-exported.
3. **A silent wrong result.** The same declaration again with another ring was taken for the
   publisher carrying on, and the new ring was ignored. The broker now carries on only when the
   ring offered is the same memory; another ring is checked against the declaration like any,
   and one of another shape is refused, `malformed`.

## Proof

`crates/client/buffers/tests/adopt.rs`: the same declaration with a ring of another shape is
refused `malformed`, and the same ring again is accepted; an Orion subscriber's `pool()` has
every buffer the publisher offered, as offered.

## Proved by

The two tests in `adopt.rs`. With the broker taking any ring under the same declaration for the
one it has, the first fails (`Ok` where `malformed` was expected).
