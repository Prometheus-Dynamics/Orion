# C52b: A root login is all of root again; a connection's child holds nothing

- **Status:** built, gate pending; board check pending (a test board, after the PC rehearsal)
- **Group:** C (comm)
- **Wave:** 18
- **Needs:** C52

## Changes

- `orion-login.service` sets no `CapabilityBoundingSet=`. A login keeps the helper's bounding set, so since C52 a root login over SSH held only SETUID, SETGID, CHOWN and KILL. Recovery, slot work and bring-up need all of root. The comm core stays non-root with its two capabilities.
- A connection's child is started by the helper as root, with `--become uid:gid` naming the account. Before it reads a byte, it empties its bounding set, becomes the account and sets no-new-privileges. Before this change it was switched between fork and exec and kept the helper's bounding set.
- `scripts/packaging-check.sh` fails if the helper's unit bounds capabilities. It also fails if the comm core's `User=` is not a sysusers account or its unit has no `RuntimeDirectory=`.
- Docs: `docs/comm.md` (what each session holds; bounding root logins with the security switch on is decided with that design), `packaging/README.md` (what an image must carry).

## Proved by

- `orion-ssh-sandbox` test `each_kind_of_session_holds_what_it_should_and_no_more`. It runs itself again in a user namespace (`unshare --map-auto --map-root-user`) and reads `/proc/*/status`:
  - a root login: CapPrm, CapEff and CapBnd all full;
  - a login as another account: CapPrm and CapEff 0;
  - the connection's child: uid of `ssh.sandbox_user`, CapPrm, CapEff and CapBnd 0, NoNewPrivs 1.
  Where user namespaces are not allowed, the test says so and passes.
- Mutations, each failing the test with the child's CapBnd at `000001ffffffffff`:
  - without the bounding-set drop;
  - with the old fork-and-exec switch.
- Packaging check mutation: adding a bounding set to the unit fails it.

## Different from the brief

- The drop is done in the child (the crate forbids `unsafe`, so there is no `pre_exec`): the helper names the account in the child's arguments, never the comm core.
