## Fault

Found reading the device library's contract note for Orion. Node logic ended a run by
assumption in two places:

- **A deadline.** It told the program to stop and ended the run `TimedOut` at once.
- **Stopping.** It told every program to stop and ended each run `Cancelled` at once.

A program may have finished the run a moment before: an install that completed was reported to
its caller as timed out or cancelled, and what the program said after was ignored. A cancel the
caller asks for already waits for the program's word; these two did not.

## Built

- `Outcome::Indeterminate = 6`: node logic told the run to stop, and its program did not say
  how it ended in time. Not `Unknown`: `open_enum!` already makes `Unknown(n)`, and an older peer
  reads 6 as `Unknown(6)`, which is not a success either. The web client has it too. The C
  library has no actions.
- `Cancel`'s doc names it.
- `orion-action-list` (`src/stop.rs`):
  - At a deadline, and for every run when node logic stops, the program is told to stop as
    before. The run stays open for its word, up to a bound: `CONFIRM_MS`, 10 s, or the node's
    `actions.confirm_ms`. 10 s is longer than a device daemon's own 5 s wait, so its answer
    comes first, and well inside a service's 30 s to stop.
  - The program's word ends the run as it says. One mapping: a run its program reports
    `Cancelled` after a deadline cancel ends `TimedOut` with code 110 (`DEADLINE_CODE`), as callers
    got before. It was stopped because it ran out of time.
  - No word by the bound: the run ends `Indeterminate`, code 0, with words that say what was
    asked and that how it ended is not known.
  - While stopping, a new run is refused, `unavailable`. A detached run that ends then is not
    kept for its starter, as before.
- `orion-node-app`: when told to stop, node logic tells the programs, then keeps serving until
  every run has ended. Each run's bound caps that. A comm core lost meanwhile ends it.
- `orionctl`: a run that ends `Indeterminate` prints its line, then `it is not known whether it
  was done: look at what the action changes`, and exits 3. 0 is done, 1 not done, 2 not
  understood.

## Proof

Each new test fails with the old behaviour planted back, and passes with the fix:

- `orion-action-list` (`tests/stopped.rs`, 4 tests): the program finished as the deadline passed
  ends `Succeeded`; a silent program ends `Indeterminate` at the bound and not one millisecond
  before; the node's bound is used; stopping refuses new runs, waits for each program, and ends
  the silent one `Indeterminate` at the bound. With the old endings planted in `stop.rs`, all 4
  fail.
- `orion-node-app` (`tests/stops.rs`, 4 tests, a real caller and a provider process, bound
  300 ms):
  - a job that finishes as it is told to stop, at its deadline: `Succeeded`, `finished first`;
  - a program that never answers: `Indeterminate`, after its deadline plus the bound and well
    inside 3 s;
  - stopping node logic with three jobs under way (one answers `Cancelled`, one had finished,
    one never answers): the stop takes the bound and no more; they end `Cancelled`,
    `Succeeded`, `Indeterminate`;
  - `orionctl` on the silent one: exit 3 and the line that says it is not known.
  - With the old endings planted: the first three fail. With node logic returning as soon as it
    is told to stop: the stopping test fails, and the two deadline tests pass, as they should.
    With orionctl's branch taken out: its test fails.
  - Run 10 times: 10 of 10 passed.
- Updated tests: a deadline now needs the program's word (`Cancelled` gives `TimedOut`, 110),
  and the node logic restart test hears the program's own `stopped`.
