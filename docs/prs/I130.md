# I130: GATE_LANE_SCHEDULE, to measure how the lanes share the machine

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I129

Read `AGENTS.md` and `docs/design.md` first.

## Why

On the comment row, the tests step's build took 15 to 20 s alone at load 136 to 151, but 48 s to
1 m 41 s inside the gate. There, the clippy, shipped, matrix, other-systems and devices lanes
all build at the same time, each with its own `-j13`, on 26 processors. To find out whether
another schedule shortens the critical path, each one has to be measured as a gate on the same
records. `gate.sh` is in the records' hash, so it cannot be edited for each variant: the
variants need a switch that is off by default.

## Changes

- **`GATE_LANE_SCHEDULE`**:
  - `parallel` (the default, and when unset): as before. Every lane starts at once, with the
    same command lines.
  - `matrix-after-tests`: the feature matrix starts when the tests step ends, passed or failed.
    If the tests step failed, every lane still runs to its end and what each said is printed,
    so a red matrix is never hidden behind red tests.
  - `shared-jobs`: every cargo and rustc of the gate takes jobs from one jobserver, a FIFO
    passed in `CARGO_MAKEFLAGS`, with one token fewer than the processors the gate has. Each
    lane still runs all of its work.
- **`GATE_TRACE_LANES=FILE`** writes each lane's command line, and when it started, to FILE.
- **The wrapper self-test** takes the new functions (`lane_start`, `start_deferred`,
  `tests_step`) from `gate.sh`, as it takes the rest.

## Proved by

- New wrapper self-test cases:
  - a lane held for after a red tests step, red itself: both reds printed;
  - the same after a green tests step;
  - a green held lane.
- Mutants, 3 runs each, all red:
  - no join after a red tests step;
  - the held lane never started;
  - the held lane started only after a green step.
- A full gate with `matrix-after-tests` and two planted reds: a failing test, and a
  `compile_error!` that only the matrix's no-default-features builds reach. The tests step
  failed, the matrix started after it and ran, and both "FAILED: feature matrix" and the
  test's failure are in the gate's output.
- cargo with a FIFO jobserver of 1 token ran at most 2 rustc at once, under its own `-j 13`.
- The commit's gate ran with the switch unset and `GATE_TRACE_LANES` set: its lane lines are
  the default's.
