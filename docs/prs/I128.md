# I128: A module by #[path] from a crate is not a read outside the crates

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I127

Read `AGENTS.md` and `docs/design.md` first.

## Why

The check for reads outside the crates (`reaches_outside`) is broad on purpose. A package it
flags is not keyed by its binaries, and every file outside the crates goes into its source key.
It flagged `#[path = "../../broker/tests/common/mod.rs"]` as a read outside, for example in
`orion-time` and `orion-self-status`. That path names a module, which is compiled in and read
by nothing at run time.

## Changes

- **A `#[path = "..."]` that names a file in the crates is left out of the check.** The rule is
  sound for two reasons:
  - the module is compiled in, so it is in the test binaries;
  - the dep-info check (`depinfo`) fails a test binary built from a crate its key does not hold.
- **The path must be in the crates from both places it can be taken from:** the source's
  directory, and the directory named for the source (a module inside a file module).
- **A path that leaves the crates is judged as before.** The dep-info check does not look
  outside the crates, so nothing else would hold that file.

## Proved by

- A planted case: `orion-ctl` with a module by `#[path]` from a crate stays keyed by its
  binaries. Red on 0f330162: it was not keyed.
- Two planted cases that must stay broad, and do:
  - a module by `#[path]` from outside the crates;
  - the same in-crates path read at run time with `std::fs::read`.
- Mutants, 3 runs each, both red:
  - every `#[path]` left out;
  - the path taken from the directory named for the source only.
- 71 of the 95 packages are now keyed by their binaries, from 68.
