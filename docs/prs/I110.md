# I110: Only what changed is tested; no lane runs in full for being behind

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I109

Read `AGENTS.md` and `docs/design.md` first.

## Why

The one-minute rule (2026-11-24): every gate, check and test run ends in under a minute at
any load, the slowest one in twenty included. A run over a minute is a defect.

- **The tests were the gate.** After I109 the tests step took 238 s of a 339 s gate at load
  122–185. A warm run, nothing to build, is 155 CPU-s; at load 100+ the gate gets about five
  processors. Every package's tests ran again whatever had changed.
- **Lanes ran in full for being behind** (some commits or a day since their last full run),
  and the size gate measured everything once a day. A run made long on purpose cannot end
  within a minute.
- **A browser test left Firefox running** and I104's CI run failed on it: its content
  processes outlived a kill of the main one (`docs/flakes.md`).

## Changes

- **The tests, clippy, the shipped builds and the short fuzz run are keyed lanes**
  (`scripts/lane-reuse.py`: `tests`, `clippy`, `shipped`, `fuzz`). A package whose tests
  passed before on exactly the same inputs is not run again. Its key holds:
  - every crate its tests build, and their entries in `Cargo.lock`;
  - the toolchain, the cargo configuration, the build's environment and the gate's scripts;
  - one digest of every file outside the crates but the notes;
  - the crates it says its tests read (`[package.metadata.orion] test-reads`);
  - the programs on the machine a test may start, and the kernel release;
  - the environment its tests read (`TEST_ENV`: `ORION_*`, `NAMESPACE_TESTS`, ...).

  `Gate-Lanes:` says `tests=passed(N-of-M-reused)` when some were reused.
- **What the keys hold is checked, not trusted.**
  - `lane-reuse.py reads`, a gate step, fails when a crate names a file of a crate its key
    does not hold, or reads a variable no key holds.
  - `lane-reuse.py depinfo` holds each test binary that ran to its `.d` file: what the
    compiler read must be in the key.
  - `lane-reuse.py --self-test`, a gate step that runs again only when the key scripts
    change, changes each class of input in a copy of the tree and checks the key moves; a
    note and a crate not built leave it alone.
- **A fuzz run that could not run is not `passed`.** Without cargo-fuzz or a nightly
  toolchain, `Gate-Lanes:` says `fuzz=not-run(...)`, and a release refuses it.
- **The filters are checked against every test.** Each run's test list is kept by its key,
  so `check-test-filters.py` sees the reused packages' tests without building them.
- **Doctests run only for the crates that have one** (`scripts/workspace.py doctested`):
  seven of them. A rustdoc pass of a crate with none tests nothing.
- **No lane runs in full for being behind**, and the size gate no longer measures everything
  once a day. CI runs every lane in full on every push, and `scripts/release-check.sh` wants
  each `passed` with nothing reused.
- **`scripts/workspace.py`** answers what the scripts asked of `cargo metadata` in inline
  `python3 -c`: the members, the feature matrix, the crates a change affects, the doctested
  crates. A listing that comes back empty fails, saying so, never as nothing to check.
- **A browser is started in a process group of its own and ended whole**: `kill -KILL` to the
  group, then the test waits up to 10 s for the group to empty and fails if it does not.

## Proved by

- **The keys' self-test**, each input class taken out of the key in turn: the files outside
  the crates, the programs, the crates a package's tests read and the environment the tests
  read. Each time 3 of 3 failed, naming the class.
- **The browser group kill.** Firefox here did not leave a content process behind: the code
  before the fix passed 3 of 3 with a real browser, so a real browser cannot prove it. A new
  test starts a stand-in that leaves a process of its own, as Firefox's content processes
  did on CI. With the code before the fix (the main process killed, nothing waited for), it
  failed 3 of 3, naming the process still running. With the fix, it passed 3 of 3, in 0.2 s.
- **The environment the tests read** (`TEST_ENV`): with `ORION_` taken out of it, `reads`
  failed 3 of 3, naming the 23 places that read one.
