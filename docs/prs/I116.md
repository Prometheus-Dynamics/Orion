# I116: A red command fails its step and its lane, wherever the gate calls it

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I115

Read `AGENTS.md` and `docs/design.md` first.

## Why

A gate that passes on a red command is worse than a slow one. Each of the gate's wrappers
(`step`, `timed`, `once`, a lane's steps, `lane_item`) ran its command and then printed its
time, and left the command's status to `set -e`. Bash ignores `-e` in a function called from
`||`, `&&` (but not its last command), `if` or `!`, and inside every function called from
there. So called there:

- a lane whose first step failed ran its next one, and passed with the last step's status;
- a step, or a timed part, passed with the status of the time it printed;
- a lane item failed, and its pass was recorded all the same.

`once` ran its command as `"$@" || return`, so a function given to it had `-e` ignored even
at top level: one whose first command failed and whose last passed was stamped as passed.

No call in the gate is in such a place, so no gate on this branch passed this way. Every gate
log since I109 was checked by its positive markers:

- every passed gate (I109, and I110 through I115) ends `gate passed` with exit 0 and a
  `Gate-Lanes` line of lanes all passed;
- each step's `==>` line is followed by its time line, printed only once it ends;
- no line says FAILED, error, or a failed test.

Every failed gate (I109's first three, I110's first, I113's first) ended red.

## Changes

- **Every wrapper keeps its command's status by hand** (`scripts/gate.sh`): run plainly, then
  `status=$?`, then the time, then `return "$status"`. A lane's red step ends the lane with its
  status (`exit`), so no later step runs. A lane item is recorded, and a `once` command
  stamped, only after a pass.
- **`timed` and `once` run a function in a shell of its own** with `set -euo pipefail`, as
  `bounded` already did, so its first red command ends it wherever it is called.
  `join_lanes` waits for this shell's children, so it times itself instead.
- **`scripts/feature-matrix.sh`** counts a shard that ended red as failed, not just one that
  said so.
- **`scripts/gate-self-test.sh`**, a gate step (run through `once`). It takes the wrappers
  from `scripts/gate.sh` as they are, runs planted red and green commands through them in the
  gate's shell, and checks both the status and the lines printed. It runs each case at top
  level, as the gate does, and again inside `f || exit`.

  The cases:
  - a lane whose first, last or only step is red, its steps split on `--`, also started after
    `&&`;
  - a step, a function step whose first command is red and last green, a timed part, a timed
    function;
  - a red lane item, which must write no record;
  - a red `once` command, which must write no stamp;
  - green lanes and steps, every step run and timed.

  Records and stamps go to a git directory of its own.

## Proved by

- **On the gate before this change,** the self-test failed 3 of 3, with 20 cases red,
  among them `once` at top level.
- **On this change,** it passed 3 of 3, in about 2 s and 2 CPU-s.
- **Each fix taken out alone** (`step`, `timed`, `once`, a lane's steps, `lane_item`)
  failed it 3 of 3, each naming its own case.
