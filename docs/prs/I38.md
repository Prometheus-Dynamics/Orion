## Why

The gate's tests step ran `cargo nextest run`, then `cargo test --doc`, one after the other.
The doctests take about 15 s warm, more under load, though there are only 13 of them, in 7 of
91 crates. Most of that time is a rustdoc pass over each crate, which rustdoc does every time.
The crates are on edition 2024 already, so the doctests are already merged into one binary
per crate.

nextest's run is set by its slowest test, the browser video test (22-25 s). The doctests
fit inside it.

## Built

`tests` starts `cargo test --doc` in the background, runs nextest, waits for the doctests,
and prints their output after nextest's. It fails if either failed, and says when the
doctests did. The two do not wait on each other: with doctests running, a nextest run took
only the package cache's lock, for a moment. The same tests run as before.

## Proof

- **A failing doctest still fails the step.** A failing `assert!` was planted in
  `orion_values`' doctest. All 900 nextest tests passed; the step failed, saying "the doctests
  failed". Restored after.
- **Timing.** The tests step alone, warm, under `bounded.py`, as a niced user unit, interleaved
  A B A B (A: before, B: this), load 88-157:

  | Pair | A wall | B wall | A CPU-s | B CPU-s |
  |---|---|---|---|---|
  | 1 | 68.2 s | 33.7 s | 112.1 | 101.2 |
  | 2 | 59.9 s | 32.2 s | 100.5 | 104.5 |
  | 3 | 62.8 s | 49.5 s | 112.4 | 135.0 |
  | **Median** | **62.8 s** | **33.7 s** | **112.1** | **104.5** |

  29 s off the gate's critical path, with the same CPU-s.
