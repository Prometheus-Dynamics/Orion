## Build

- Fetch a URL into a file, with resume where the server allows.
- Feature-gated, and rustls only for this.

## Proof

Pull from a local test server.

## Built

- `crates/node/files-pull` (`orion-files-pull`): `Pulls` (`start`, `poll`, `active`,
  `fetching`), `Fetch`, `Report`, `fetchable`. It uses `ureq` 3 with rustls behind its
  feature `https`.
- `orion-file-store`: `reserve`, `fetched`, `commit_fetched`, `received`, so a fetch uses the
  part file, the check and the rename of a pushed file.
- `orion-node-app`: feature `pull`, on by default, answers `FilePull`.
- `orion-relay` routes `FilePull`.
- `scripts/check-boundaries.sh`: the one place network crates may be used is now
  `crates/node/files-pull` (it named `crates/node/files`, which was never made: E13 is
  `crates/node/file-store`).

## Proved by

- `crates/node/node-app/tests/pull.rs`, through the `orion` client against a real comm core
  and a local HTTP server:
  - The server hangs up after 300 KiB of a 900 KiB file. The pull is answered `Rejected`
    with 300 000 bytes received and nothing is in place. Asked again with the same number,
    the node asks the server for `bytes=300000-`, and the file is committed and is byte for
    byte the server's.
  - A server with another file of the same size: `Rejected`, "the digest does not match",
    nothing in place. A `file://` URL: rejected. No server: rejected, "the server was not
    reached".
- `crates/node/files-pull/tests/pull.rs`, 7 tests against a local server: whole; resumed
  where the server takes ranges; started over where it does not; a part that is already
  whole or too long; 404, too many bytes, too few, no server; progress and four at once;
  which URLs are fetched.

## Different from dev

Dev had no pull: blobs were pushed. HTTPS is not tested here: there is no server with a
certificate a test can trust without adding one to the build.
