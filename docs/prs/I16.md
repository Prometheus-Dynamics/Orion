## Build

Load robustness: the gate five times, each with a second gate beside it, in a worktree of its
own with a seeded target directory, at load 97–169. Nine of the ten gates passed. The fifth gate
in front failed one test:

`orion-recovery` `recovery.rs` `on_one_interface_recovery_is_open_there_and_nowhere_else`:
`assertion failed: std::net::TcpStream::connect(("127.0.0.1", port)).is_err()`.

The test found a free port by binding port 0 and letting it go. It then checked, 500 ms later,
that recovery on an interface not there yet listens nowhere: nothing answers on that port. A
port found free is not kept. Another test, here or in the gate beside, can be given it and
listen there, and the check takes that listener for recovery's.

Two more tests check the same thing the same way, and are fixed with it:
- `orion-ssh` `interface.rs` `an_interface_that_is_not_there_is_waited_for_not_given_up_on`;
- `orion-ssh` `forward.rs`, the port nothing listens on, to which a forward must fail.

## Built

- **The port is held** while the check runs: a socket bound to it and not listening.
  - The kernel gives a held port to no other bind to port 0.
  - Where the code under test may listen there, the hold sets `SO_REUSEADDR`, as recovery's and
    SSH's listeners do. A recovery that wrongly listened on the address alone would still
    listen, and the check would still catch it.

Parked, same cause, not seen failing: `forward.rs`'s `-L` port and the drills' `free_port` hand a
port found free to something that binds it later. They fail only if it is taken in between.

## Proved by

- **The check still catches the fault.** With `orion_ssh::listen` ignoring a failed
  `bind_device` (listening on the address alone when the interface is absent), both the
  recovery test and the SSH interface test fail at their checks. The same mutation in
  `orion-tcp`'s listener does not reach recovery, which listens through `orion_ssh::listen`.
- **A held port is not handed out.** With a port held as above, 3,000 sockets bound to port 0
  with `SO_REUSEADDR` and listening never got it. A port found free and let go was listened on
  by another socket at once.
- `orion-ssh`: 19 tests pass; `orion-recovery`'s test passes.
