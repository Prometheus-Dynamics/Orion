# I35: Every test removes the files it made, passed or panicked

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I34

Read `AGENTS.md` and `docs/design.md` first.

## Changes

`crates/testing/scratch` (new: `orion-scratch`), `crates/testing/stubs` (`Board::start`),
`crates/testing/test-board`, `orion_stubs::listen_outside_the_ephemeral_range` (now public), the tests of every crate that made a directory or file under the
temporary directory, the browser launchers in `crates/testing/web-tests` and
`crates/comm/ws`, `Cargo.lock`, `AGENTS.md`, `docs/flakes.md`, `docs/lock.md`, `TODO.md`.

## Fault

One gate run, its TMPDIR fresh, left 176 entries there, 139 MB. Tests made
`orion-<name>-<pid>` directories with `std::env::temp_dir()`, cleared any left from before,
and most never removed them: 93 sites in about 80 files, no guard anywhere. The largest:
- boards from `orion_stubs::Board::start`: 28 directories, up to 28 MB each;
- a node's sink test: 98 MB;
- one Firefox add-on (`tmp-*.xpi`, 4.3 MB). Firefox unpacks its built-in new-tab add-on into
  `TMPDIR` for every fresh profile.

A shared TMPDIR grows this way, run after run, until the tmpfs is full and unrelated steps fail
with errors that say nothing of it. That happened in another repository on this machine.
Without this change, the next PR, a gate step that fails on anything left in its own TMPDIR,
would go red at once.

## Built

- **`orion_scratch::Scratch`.** `Scratch::new(name)` makes `$TMPDIR/orion-<name>-<pid>-<n>`, where `n`
  counts the directories this process has made. Two tests in one process that give one name get
  two directories.
  - It is made with `create_dir`: one already there is never shared, and the test panics, saying
    so.
  - Dropped, it removes itself and everything in it. That covers a test that passes and one
    that panics.
  - It dereferences to its `Path`.
  - No dependencies. `tempfile` would have brought four crates into the lockfile and into the
    size-key closure of every crate that tests with it, and our directories need short, fixed
    names: a socket in them must fit in 107 bytes.
- **Every site is on it.** Each helper returns or holds its `Scratch` for as long as anything
  uses the directory. A struct holds it as its last field, so its threads and servers are
  ended first. Manual removes at the ends of tests are gone.
- **Boards.**
  - `orion_stubs::Board::start` holds the directory it made and removes it when dropped.
  - A board started in a caller's directory (`start_in`) leaves that directory alone.
  - Tests that stop a board and start another in the same directory now own the directory
    themselves.
- **A shared file.** The comm core's security record, one `orion-comm-security-<pid>` file
  shared by three test files, is written inside each test's directory.
- **Browsers.** The browser gets its `TMPDIR` inside the test's scratch, Firefox and Chromium
  alike.

## Proof

- **Before:** one full nextest run with a fresh TMPDIR left 176 entries, 139 MB.
- **After:** the same run, all 900 tests passed, left 0.
- `orion-scratch`'s own tests:
  - a scratch is empty when made and gone when dropped;
  - one dropped by a panic is gone;
  - two of one name in one process are two directories;
  - making one where one is already there panics.
- The next PR's gate fails any step that leaves anything in its TMPDIR. Its fail-before puts one
  of these sites back.

## A flake in I23's fix, found by this gate

The first landing gate of this change failed in `orion-connect`'s
`connect::there_is_one_way_back_and_it_never_gives_up`, at load ~118-132. The failure was
`AddrInUse` as the board started again on its port.

I23 moved `orion_stubs::Board` below the ephemeral range for this reason. Two test helpers
of their own were missed, and still listened on port 0:
- the connect tests' board;
- the topic-peers tests' node.

Both stop and start again on the same port. Both now listen through
`orion_stubs::listen_outside_the_ephemeral_range`. The kernel never hands out a port there by
itself, so only a socket that names the port can take it, and the gap is closed by
construction, as I23's was. Recorded in `docs/flakes.md`.
