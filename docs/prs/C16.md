# C16: Adopting a publisher's own ring and pool

**Status:** done

**Group:** C. Comm core

**Wave:** 18

**Needs:** J2

**Runs:** cloud

Read `AGENTS.md` and `docs/design.md` first.

## Changes

`crates/core/msg-topics`, `crates/comm/broker-buffers`, `crates/client/topics`,
`crates/client/buffers`, `crates/client/orion`

## Build

- A program that makes its own ring, pool and hold table with the `shm-*` crates, so it can
  serve readers with no Orion running, makes that same ring an Orion topic when Orion is on.
  One ring: Orion adds reach, never a second path.

## Proof

Orion's subscribers read frames a program writes with its own writer, in its own ring and pool,
from reader slots it left for Orion.

## Built

- `Topics::adopt(decl, ring)` and `Orion::adopt`: the declaration goes with the ring's write
  end, which the broker checks and uses (it already did so for a publisher coming back after a
  restart). The client makes no second writer; the program publishes with its own and calls
  `Publisher::wake`. `Topics::restore` hands the same ring back to a comm core that restarts.
- `Buffers::adopt(name, history, max_meta, ring, pool, reader_slots)` and
  `Orion::adopt_buffers`, giving `AdoptedBuffers`: `poll(pool, table)` offers the pool (again
  when it or the comm core is new) and puts Orion's subscribers' marks in the program's own
  `HoldTable`; `readmit(table)` puts them in a new table; `wake`, `subscribers`,
  `with_request`. `orion-buffers` re-exports `HoldTable`, and `orion::topics` `Ring` and
  `Spec`.
- `BufferOffer.reader_slots` (appended): the slots Orion may give subscribers, a bit each, zero
  for all. The broker gives slots only from those and moves a subscriber out of one the offer
  keeps back: the publisher is told the old slot is gone and given the marks under the new one.
- Wire vectors recorded again: the offer's bytes gained the field at the end.

## Proved by

- `cargo test -p orion-buffers --test adopt`, with a real broker:
  - A program makes a ring, a pool and a hold table with one reader of its own in slot 0, and
    lets Orion use every other slot. A ring of another shape than the declaration is refused
    `malformed`. An Orion subscriber reads 20 frames the program wrote with its own writer, in
    order, with the bytes the program put in its buffers; the program's table holds both
    readers; the subscriber's request reached the program.
  - A value topic: an Orion subscriber reads samples the program wrote with its own writer.
- `cargo test -p orion-broker-buffers`: a subscriber in slot 0 is moved to slot 2 when the
  camera offers again keeping 0 and 1 back, and frames reach it; a second gets slot 3, and a
  third, with no slot left, has the ring but no pool.
- With the broker ignoring `reader_slots`, both tests fail.

## Different from the brief

- No brief was written before this PR; it was asked for by the camera service, which makes its
  ring itself.
- Subscribers' doorbells stay Orion's: `wake` rings them. A program that wants them in its own
  bell set can call `wake` from the same place it rings its own readers.
- The gate turned up a race in the provider drill, fixed here: it killed node logic as soon as
  `resource show` said `Ready`, which can be inside the 10 ms before the record is saved, and
  the record was then rightly gone after the restart. It waits past the save first.
