## Fault

`orion_measure::sched::without_system_calls` runs a body in a forked child under a seccomp filter
that kills it on any system call. `a_system_call_is_caught` makes one on purpose, so the child is
killed by SIGSYS, which dumps core by default. On a desktop whose core pattern pipes to a crash
handler, each test run started a crash-handler unit and stored a dump: 14 in one day's log, from
the gate and test runs.

## Built

The child sets its core-file limit to 1 before it installs the filter. A limit of exactly 1 has
the kernel skip the dump to a pipe as well as to a file. A limit of 0 does not stop a pipe, and
neither does a process made not dumpable, where `fs.suid_dumpable` is 2, as on the machine this
was found on. The parent still reads the SIGSYS, so `SystemCalls::Made` is unchanged.

## Proof

`cargo test -p orion-measure --all-features --test harness sched::` (4 tests, all passing either
way), with the host's `coredumpctl list` counted for this binary before and after:

| Code | Dumps before | Dumps after |
|---|---|---|
| Before this change | 328 | 329 |
| This change | 328 | 328 |

No test checks this automatically, because it would read the host's crash handler, which tests
here leave alone.
