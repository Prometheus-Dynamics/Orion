## Build

A gadget function's bulk endpoints fail the call in flight with `ESHUTDOWN` when the host goes
away (unplugged, reset, unconfigured, the function disabled), and every call after with `EAGAIN`
until it is back; the descriptors stay good. The link took any error as its end: an unplugged
cable left it dead until the gadget's owner offered the endpoints again, which it does only after
taking the gadget down and up. And a holder that keeps copies of the endpoints stops their owner
from taking the function down or mounting it again (`EBUSY`), with no way to ask for them back.

1. `ESHUTDOWN` and `EAGAIN` are the host away: keep the descriptors, read again 100 ms later,
   doubling to 1 s while it stays away; bytes written then are lost, not the link.
2. Any other error, or the end of a file, is the end, as before. The rule is one function.
3. A `LinkOffer` of endpoints may carry a third descriptor, the end: readable or hung up, the
   link lets go of all three and waits for the next offer. No body change: the count says it.

## Built

As above. `blocking.rs` reads and writes through `verdict`; the reading thread sleeps out the
host's absence on the condition variable it already had, so letting go of the link wakes it.
The end descriptor is watched by a task of the link's stream (`AsyncFd`), aborted with it.
`Blocking` takes any reader and writer, which the tests use.

## Proved by

- `blocking::tests`:
  - `the_host_away_is_kept_through_and_anything_else_is_the_end`: the rule, code by code.
  - `reading_goes_on_through_the_host_going_away_and_ends_on_anything_else`: a scripted
    endpoint gives bytes, `ESHUTDOWN`, `EAGAIN` twice, bytes, `EBADMSG`; every byte arrives,
    then the end, and each endpoint is closed (the read one at its end, the written one when
    the link is let go).
  - `bytes_written_while_the_host_is_away_are_lost_not_the_link`: writes through `ESHUTDOWN`
    and `EAGAIN` succeed and are lost; the next is written; `EBADMSG` ends writing and closes
    the endpoint.
- `tests/usb.rs`, `an_end_descriptor_takes_the_endpoints_back_and_all_three_are_closed`: over
  pipes, a device's session runs; the holder writes to the end (then, the second time, closes
  it); the session ends, the board's write end is closed, its read end is closed once its call
  returns; each offer is taken and let go, and the link takes the next.
  Not vacuous: with the end descriptor's watch doing nothing, it fails (the write end is never
  closed).
- The other USB link tests, unchanged.

Not on a board: the test board is reached through its gadget, so its function is not taken
down from here.
