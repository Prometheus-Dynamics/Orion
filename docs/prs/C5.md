## Build

- Takes a publisher's buffers once, hands them to each subscriber once.
- Forwards the subscribe request to the publisher without reading it.
- Handles a replaced pool.

One kind was added at the end of the topics range, `TOPIC_HOLDS`: it carries a subscriber's page of
hold marks to the publisher, the publisher's answer that it is honouring them, and the reader slot
back to the subscriber. A subscriber is handed the pool only after that answer, so it never reads a
frame the publisher is not yet protecting.

Left for D3 (client buffer topics): after a comm core restart a subscriber can be given a different
reader slot, and the publisher then has that subscriber's page under the old slot too. Nothing
breaks (both read the same marks), but the old slot is only cleared by the publisher's client.

## Proof

Late subscriber gets the current pool. Comm core restart does not interrupt frames.
