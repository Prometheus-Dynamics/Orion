## Built

- `orion-ctl` (`crates/client/ctl`): `run(args, out, err) -> exit code`, the whole tool as a
  function, so the one binary can make it a mode. Fourteen verbs under the six concepts:
  `node show|peers|time`, `resource list|show`, `topic read|watch|publish`,
  `action run|attach`, `workload put|remove`, `file push|pull`. `--address` takes any address
  the client does.
- A command is understood before any board is asked: a mistake costs no connection and exits
  2 with the usage. Done is 0; not done (refused, failed, timed out) is 1.
- Values are shown by their field's declared type and unit, so the tool prints a topic it has
  never heard of.
- The facade gained `Orion::node` (the hello document, checked against its signature) and
  `Orion::clock` (a clock comparison). The hello document's check moved from `orion-hello` to
  `orion-identity`, so a client can check it without the comm crates.

## Proved by

`tests/verbs.rs` calls `run` for every verb against the comm core in `orion-stubs`, with a
provider and an executor running beside it where a verb needs one, and checks the text and the
exit code. `node show` is also run across the network. Ran clean eight times.

## Different from dev, and left for E

- No `clap`: the tool has fourteen verbs and is to be a mode of a small binary. Its arguments
  are taken apart by sixty lines of its own.
- Dev's `get`, `describe`, `apply`, `delete`, `maintenance`, `peers`, `operators` and `update`
  spoke dev's records and its HTTP API. They are not carried. Enrolling peers and operators
  from the command line is not here yet: the keys service takes those requests, and the verbs
  are an addition.
- There is no `workload show`. The wire has no way to ask where a workload is, only to be told
  after asking for it to exist or to go. E decides whether that is a request or a topic.
