## Build

Two flakes from the gate-timing runs, under load. Both were the code's.

### A sealed leftover on a link


`a_tool_with_a_key_signs_its_session_on_a_link` failed with `the board does not take a signed
session on a link` where the board refused a revoked key.

A link is a stream that outlives its sessions. The board's pong to the last session's heartbeat
can arrive after that session stopped reading, and stays in the link. The signed hello already
skipped a plain ping or pong left there, but a signed session's pong is sealed: a
`LINK_SEALED` frame. The next signed hello read it as the board's reply, a kind it did not
expect, and took the board for one from before signed links. Under load the last heartbeat's
pong comes late more often, so the failure showed only then.

### A command killed as it exits

`a_running_comm_core_serves_the_files_its_settings_name` failed with `sys/echo: /usr/bin/echo
signal: 9 (SIGKILL)` where `made by echo` was due.

A file the settings make by a command is the command's output. When the output ended, the
runner killed the command and then waited for it. coreutils closes its output on the way out,
before it exits. Killed in that gap, the command was reported killed, and the file refused. A
loaded machine widens the gap.

## Built

- **Sealed leftovers skipped.** While a signed hello waits for the board's challenge or answer,
  a `LINK_SEALED` frame is skipped like a stray ping or pong: nothing is sealed before the
  handshake ends, so it can only be a frame of a session that is over.

- **Waited for, not killed.** A command whose output ends is waited for until its deadline
  (`timeout`), through a pidfd, and only then ended. One that closes its output and runs past its
  deadline is refused `did not finish in N ms`, as one still writing is. A command that reached
  its bound, or failed, is ended as before.

## Proved by

- **`tests/link_stale.rs`.** The board's side puts a stale frame on the link before its answer;
  the tool must be told the answer.
  - `the_last_sessions_heartbeat_left_in_a_link_does_not_answer_the_next_signed_hello`: a plain
    pong (as before, now through a shared helper).
  - New `the_last_signed_sessions_sealed_heartbeat_does_not_answer_the_next_signed_hello`: a
    sealed pong. This makes the order that failed under load happen every run.
- **Mutation.** Without `kind::LINK_SEALED` in the skip, the new test fails and the old one
  passes.
- **`crates/comm/comm-app/tests/configured.rs`.** A new file, `sys/closes`, is made by `sh`,
  which writes `closed`, closes its output and sleeps 0.2 s before exiting 0.
  `a_running_comm_core_serves_the_files_its_settings_name` takes it as `closed`. This makes the
  order that failed happen every run.
- **Mutation.** With the kill back before the wait, the test fails 3 of 3 with `sys/closes:
  /usr/bin/sh signal: 9 (SIGKILL)`.
