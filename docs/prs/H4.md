## Build

- Receive through the same file kinds, into a two-slot sink.

## Proof

Interrupted transfer resumes. A bad image never boots.

## Built

- `crates/device/firmware` (`orion-device-firmware`), `no_std`, no alloc:
  - `Firmware<F>`: asks for its prefix with `FileSink` through `Requests`, and answers
    `FileBegin`, `FileChunk` and `FileCommit` under it with `FileStatus`. Only the newest status
    is owed: each says everything.
  - `Slots<F>`: begin (resume when the transfer, size and digest match; refused while a trial
    is pending), write (only the next bytes; anything else is answered with where to go on
    from), commit (read back, SHA-256 against the sender's digest, then on trial), confirm.
  - `BootRecord`, kept in two CRC-checked copies with a sequence number, written to the older.
  - `boot` and `boot_select`: a trial runs once; unconfirmed it goes back (not confirmed, or a
    boot failure after a fault); a slot runs only if its stored bytes match the CRC recorded
    at commit; the slot the board left the factory with runs unchecked.
  - `SlotFlash`: the port's flash.
  - A small SHA-256 (one round in a loop), tested against `sha2`.
- The size probe's `firmware` variant, over flash at fixed addresses, with the bootloader's
  entry point, and its budgets.

## Proved by

`crates/device/firmware/tests/firmware.rs`, against the simulated host and a flash in memory
that refuses writes over unerased bytes and can tear a record write: an image arrives, runs on
trial and stays once confirmed; a transfer cut off by a lost session goes on where it stopped;
a chunk that is not next is not written; an image with the wrong digest never starts; an image
that changed in flash after commit is given up before it starts; a trial not confirmed goes back,
for both reasons; a new image waits until the trial is settled and then goes to the other slot;
a record torn by a power cut leaves the one before; a file for another prefix is not this
layer's; receiving allocates nothing. `sha256` is held to `sha2` at every length around a block.

## Different from the brief

- Dev's transfer had Activate and Confirm on the wire. Here a commit that checks out is the
  activation, and confirming is the application's own call: the file kinds stay the file
  kinds, and only the device knows when it is healthy.
- Progress is kept in RAM: a transfer resumes across a lost session, not across a reset of the
  device, which starts the image over.
- `sha2` unrolls its rounds and cost 7 KB of flash, with panic paths; the device's SHA-256 is
  written small.
