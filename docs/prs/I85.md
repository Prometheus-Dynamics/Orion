## Changes

`crates/comm/hello/tests/hello.rs`, `docs/flakes.md`, `docs/lock.md`, `TODO.md`.

## Why

`cargo test -p orion-hello --test hello` failed 3 of 3 runs. The gate uses nextest, which gives
each test a process of its own, so the gate never saw it. Run in one process,
`a_fact_of_up_to_the_limit_is_carried_and_a_longer_one_is_left_out_and_logged_once` read the
process's log window and found another test's line there: `hello.long: 1025 bytes ... left out
of the hello`, from `facts_other_programs_publish_are_in_the_document_and_go_when_they_go`.

## Built

The test counts only the "left out" lines that name its own facts (`hello.at_limit`,
`hello.over`, `hello.offers`). It still requires exactly one line, for `hello.over`, after two
questions.

## Other tests that read the log window

Two other test files read the log, and neither needs a change:

- `comm-app` `interfaces.rs` counts only lines naming its own interface (`onever`), and runs in
  a process of its own, in a network namespace.
- `comm-app` `own_files.rs` bounds the size of `orion/log` and looks for its own numbered lines
  in a window large enough that other tests' lines cannot push them out. Its comments say so.

## Tests

In one process (`cargo test -p orion-hello --test hello`): failed 3 of 3 before, 8 passed 3 of 3
after. Under nextest it passed before and passes after.
