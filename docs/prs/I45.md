# I45: A build lane item that passed on exactly these inputs is not run again

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I44

Read `AGENTS.md` and `docs/design.md` first.

## Changes

- New: `scripts/lane-reuse.py`, `scripts/lanes-behind.sh`, `scripts/release-check.sh`.
- `scripts/gate.sh`: `--drop`, the lanes' state, `other_systems`, `device_size`, `lane_item`, the
  `Gate-Lanes:` line, and the step "nothing built reads the gate's own variables".
- `scripts/feature-matrix.sh`, `scripts/push.sh`, `AGENTS.md`, `docs/lock.md`, `TODO.md`.

## Why

A gate after a change that touches nothing a lane builds still ran that lane in full:
- the feature matrix's 108 `cargo check` calls (29 CPU-s warm);
- the no_std and other-system checks;
- the device sizes.

A lane whose result is a function of its inputs need not run again on the same inputs. This is
the shape of the LANE-SELECT ruling (per item, a content key, records, a line saying what each
lane did, a limit on how long a lane may go without a full run, a full run before a release),
and I24's size key's inputs.

## Built

- **Which lanes reuse.** Only lanes that check or build:
  - each feature-matrix build;
  - each no_std group per target, and the client's lint per other system;
  - the device sizes.

  Main's tests, the size gate (which has I24's key of its own), the MCU template and packaging
  (they run tests and system tools) run every time.
- **The key** (`scripts/lane-reuse.py`), per item, covers:
  - every file of each workspace crate the item builds (normal and build dependencies on every
    platform; for the client's lint, which takes its tests, the crates' dev-dependencies too);
  - the lockfile's entry of each package it builds: a dependency's change reruns only what
    builds it;
  - the root manifest, the toolchain file, cargo's configs, `rustc -vV`, `cargo -V`, clippy's
    version for a lint, the C compiler, and the environment a build reads;
  - the item's command line, and the scripts that run and judge it: `gate.sh`, `lane-reuse.py`,
    `size-key.py` and the lane's own (`feature-matrix.sh`, `same-features.py`,
    `device-size.sh`);
  - for the device sizes, the stm32g4 example's files, the pinned nightly that measures its
    stack, `rust-lld` and `llvm-size`.

  The worktree's path is not in it.
- **Records** are in the repository's common git directory (`orion-lane-records/LANE/KEY`),
  shared by its worktrees.
  - Only the gate writes them, for an item that passed.
  - Each holds the hash of the scripts above: a record without it, or with another (an older
    format, or one made by hand), is not a pass.
- **What each lane did** goes in the stamp and is printed:
  `Gate-Lanes: main=passed matrix=passed(K-of-N-reused) ... devices=passed`.
  - `scripts/push.sh` refuses a commit whose stamp holds that line if the commit does not carry
    it.
  - `scripts/gate.sh --drop LANE:WHY` leaves a lane out, `not-run(WHY)`.
- **Behind.** A lane runs in full, every item, in any of these cases:
  - its last full run here is 10 or more commits behind, or 3 days old;
  - it has never run in full here;
  - on CI, which keeps no records;
  - with `GATE_LANE_REUSE=0`.

  A lane behind cannot be dropped. `scripts/lanes-behind.sh` prints each lane's last full run.
- **Release.** `scripts/release-check.sh COMMIT` refuses unless that commit's `Gate-Lanes:` line
  says `passed`, in full, for every lane.

## Proof

- **Reproducible.** The device sizes from two cold builds in two different target
  directories: all 22 binaries byte-identical (20 probe ELFs, 4 targets by 5 variants, and the
  stm32g4 firmware's two builds), and the same report.
- **A second gate on the same tree reuses everything**, through `scripts/gate.sh` itself, run
  as the landing gate is (a user service, its own environment): `Gate-Lanes: main=passed
  matrix=passed(108-of-108-reused) other-systems=passed(10-of-10-reused) size=passed
  devices=passed(1-of-1-reused)`, each lane saying `0 of N items had no key or were not reused`.
  The gate before it ran every item and recorded each.
- **Plants.** After that full gate, each item's plan was checked against what it must be:
  rerun exactly when its build's closure holds the change. 40 checks, every one as it must be.

  | Plant | Matrix (108) | Other systems (10) | Devices (1) |
  |---|---|---|---|
  | Nothing changed | 0 | 0 | 0 |
  | One file of `orion-msg-peers` | 72 | 6 | 0 |
  | `cobs`'s entry in `Cargo.lock` | 93 | 8 | 1 |
  | `feature-matrix.sh` | 108 | 0 | 0 |
  | `same-features.py` | 0 | 10 | 0 |
  | `device-size.sh` | 0 | 0 | 1 |
  | Last full run 9 commits back | 0 | | |
  | Last full run 10 commits back | 108 | | |
  | Last full run 3 days ago | 108 | | |
  | One record made by hand | 1 | | |
  | `CARGO_INCREMENTAL=0` set | 108 | 10 | 1 |
  | `GATE_STEP_BOUND_SCALE`, `SIZE_GATE_MEASURE`, `GATE_LANE_STATE_DIR` set | 0 | 0 | 0 |
  | `orion-msg-peers` broken (`compile_error!`) | 72 | 6 | 0 |
  | That file put back (old content, new time) | 0 | 0 | 0 |
  | All restored | 0 | 0 | 0 |

  - **A variable naming a file.** The same variable and value, the file's content changed: the
    key changed. The content put back: the key the same again.
  - **An earlier tree put back.** `cargo check -p orion-msg-peers` passed, failed on the broken
    file, and passed again once it was put back: cargo built it again, nothing stale was taken.
  - **No key.** An item naming a crate not in the workspace was named (`no key: ...`), counted
    (`1 of 2 items had no key or were not reused`) and planned to run. Before, it stopped the
    plan.
- **The gate's own variables.** `own-vars` passes on the tree. A test naming
  `GATE_LANE_STATE_DIR` failed it, naming the line.
- **Time.** Three interleaved pairs of whole gates, A with every lane in full
  (`GATE_LANE_REUSE=0`), B reusing, on a warm target:

  | | Wall (s) | CPU (user+sys, s) |
  |---|---|---|
  | A | 53.0, 58.6, 145.1 (median 58.6) | 270.3, 239.6, 213.2 (median 239.6) |
  | B | 53.8, 62.2, 87.2 (median 62.2) | 181.9, 152.2, 177.9 (median 177.9) |

  62 CPU-s less a gate (26%). Wall time is flat: on a warm target the lanes already end before
  main's tests do, so what they save is CPU beside them, not time to the end.
- **Drop.** `--drop matrix:...` with the matrix 10 commits behind was refused, naming why.
  An unknown lane was refused.
- **Push.** The push guard's self-test refuses a commit that lacks its stamp's `Gate-Lanes:`
  line, and passes it once the commit carries the line.
