# I134: The tests run on the very binaries their keys were taken from

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I133

Read `AGENTS.md` and `docs/design.md` first.

## Why

The tests lane builds the packages whose sources changed (`cargo test -p ... --no-run`). It
keys each package by those test binaries (scripts/lane-reuse.py binary-plan), and then runs
the rest (`cargo nextest run -p ...`), naming only the packages to run.

Cargo unifies features over the packages a command names. Naming fewer resolves other features
for shared dependencies: rustix without `default` and `mm`, linux-raw-sys without `std`, slab
without `default`, orion-measure without `sched`, and every hash above them. So:

- **The run built again.** On a comment in orion-types (87 built, 20 to run), the run
  recompiled 31 units before its first test: 25 CPU-s and about 7 s. A real gate log shows
  the same, with 13 crates and `Finished in 7.06s`. The doctests, naming the 7 packages that
  have some, built 46 libraries again (5.4 CPU-s).
- **The tests passed on binaries other than the ones keyed.** A package that ran was recorded
  under the key of the binary the build made, but its tests passed on another binary, built
  with other features.

## Changes

- **The run names the same packages as the build** and chooses those to run with a filter,
  `-E 'package(=NAME) | ...'`. It builds nothing, and runs the binaries the keys were taken
  from. nextest skips the binaries of packages the filter leaves out without listing them.
- **The build's packages are kept in `$state.built`.** test_filters lists with them and the
  same filter, so the list it checks (and depinfo's binaries) are the binaries that ran.
- **The doctests run with the build's packages named, too.** It is the same 14 doctests, on the
  libraries the build made. Without nextest, `cargo test -p ...` still names only the packages
  to run.

## Proved by

The gate's own `tests` function was taken from scripts/gate.sh by name and run with the gate's
environment. A bash function recorded nextest's arguments and output, and no environment
changed, so no key moved.

The change made was a comment in orion-types and a new test in orion-outbound, which is keyed
by its binaries, so that it runs. Then the proof compared, by sha256, the ELF its key was taken
from (the build's artifacts) with the ELF nextest ran (`nextest list` with the run's own
arguments).

- **Before:** keyed `all-0e9e3f78ab187050` (`e81da187…`), ran `all-ae063b6d6ff1c387`
  (`830740b6…`), so **different**. nextest compiled 23 crates before its first test
  (`Finished in 3.96s`).
- **After** (87 built, 46 run): keyed and ran were both `all-0e9e3f78ab187050` (`67f0e8ce…`),
  so **the same**. nextest compiled nothing (`Finished in 1.66s`, a fingerprint check), and 41
  binaries were skipped by the filter.
- **The first run after this change doesn't count as the proof.** A new gate.sh outdates every
  record, so all 95 packages ran, and the build and the run named the same set.

**Doctests,** after the build, on a new comment in orion-types each time, interleaved A B ×3
(load 40–108, nice 10):

| | The 7 packages with doctests | The build's 87 |
|---|---|---|
| CPU-s | 10.8, 13.6, 12.9 (median 12.9) | 8.3, 10.0, 7.7 (median 8.3) |
| Wall | 4.9, 14.4, 14.0 s | 9.0, 21.7, 15.8 s |
| Compiled | 46 | 0 |
| Doctests | 14 | the same 14 (same names) |

They run beside nextest, which takes longer, so the CPU-s is what the gate pays.
