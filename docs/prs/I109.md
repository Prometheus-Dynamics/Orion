# I109: Nothing known runs again; clippy and the shipped builds beside the tests; the gate's tools in git

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I104

Read `AGENTS.md` and `docs/design.md` first.

## Why

The one-minute rule (2026-11-24): every gate, check and test run ends in under a minute at
any load, the slowest one in twenty included. A run over a minute is a defect. 117 gates before
this one took a median 138 s and 499 s for the slowest in twenty.

- **The wall time is the main part.** The lanes beside it finished first in nearly every
  gate: the main part waited 0 s for them. Its steps ran one after another: clippy, the tests,
  then the shipped builds' tests (median 32 s, mostly build).
- **Nothing tested changes when only notes change**, but a commit of notes cost a whole gate.
- **The gate's wrapper and the board's SSH settings lived outside the repository** and were
  lost with the folder they were in.

## Changes

- **`scripts/code-key.sh`.** The code key of a tree is a hash of every file but the notes, the
  paths CI's push trigger ignores: `*.md`, `docs/`, and `LICENSE-*` at the root. `--check`
  fails if a Rust source names a note, and the gate runs it.
- **The gate runs nothing whose result is known.**
  - It stamps both keys: the code key, holding the `Gate-Lanes:` line, and the whole tree.
  - On a code key that passed before, it runs only what reads notes: boundaries, links, the PR
    list and the check above. That takes seconds; then it stamps the tree.
  - On a tree that passed whole, it runs nothing.
- **`scripts/push.sh` compares code keys.** Every commit pushed must have a stamped code key,
  and the tip's whole tree must be stamped, so the notes at the tip were checked. A commit of
  notes alone needs no `Gate-Lanes:` line; a commit that changes code does.
- **Clippy and the shipped builds' tests are lanes** (`clippy`, `shipped`), each in a target
  directory of its own, beside the tests. They are new `--part`s, CI runs each on a runner of
  its own, and `scripts/release-check.sh` wants both passed.
- **The ctl test that asked a socket nobody serves** waits 200 ms, not the default 5 s. What
  it checks, that the tool says it is not done and why, does not depend on the wait.
- **The tests that start first** (`.config/nextest.toml`) are taken again from the medians of
  117 gates.
  - In: the two test-board pushes, mDNS on its interface, and the board's announcement.
  - Out: `workload_put_and_remove`, which now takes 0.3 s.
- **`scripts/run-gate.sh`** runs the whole gate and records the load before and after and the
  wall and CPU time. `GATE_CPUS` and `GATE_JOBS` keep it to a share of the machine. It does not
  wait for a quiet machine: by the one-minute rule, a wait that makes a gate longer than a
  minute fails it.
- **`scripts/board-ssh.sh`** writes the SSH settings for the reference boards from the
  machine's own addresses, with a `known_hosts` of its own, and holds each board's host key to
  the one pinned in the script before any command runs.
- **`scripts/bounded.py`:**
  - Its self-test holds each case to its time less the longest any of its processes waited
    ready to run, from `/proc/PID/schedstat`.
  - It holds its own alarm and stop signals while its two threads start.

  `docs/flakes.md` has both causes.

## Proved by

- **The push guard's self-test**, with three new cases:
  - a commit of notes alone, its tip unchecked, is refused; once checked, it goes;
  - a code change beside notes is refused without a gate of its own.

  Each of the guard's checks was taken out in turn: the self-test failed 3 of 3 each time,
  naming it.
- **The step bounds' self-test**, its unit held to 10% of a processor: before, 3 of 3 failed;
  after, 3 of 3 passed.
- **The thread-start crash** was reproduced by delaying the end of a thread's start past a 1 s
  bound: before, 3 of 3 died with a `KeyError` and left their step running; after, 3 of 3 ended
  `TIMED OUT` with nothing left.
