## Build

The hello document carries the node's security mode, from the one record:

- `on` or `off` with the generation;
- `damaged` when the record is malformed, which reads as on.

It is appended, so an older node simply lacks it, and the client reports "not told". A consumer
needs it for its security line and scorecard. `Welcomed::signed` cannot stand in, because tool
sessions always sign.

## Built

- **Two node facts, not a new field of `Identity`.** `Identity` keeps its signature as its last
  field so that the signature can be cut off and the rest checked. A field appended after it
  would break that, and one before it would not be appended. So the mode goes where `state`
  already is: Orion's own text facts, in name order and signed with the rest.
  - `security` is `on`, `off` or `damaged`.
  - `security_generation` is the record's generation in decimal, sent only when the record was
    read. No record means `off` with no generation.
  - An older node sends neither.
- `orion_hello::Hello::with_security(&SecurityView)`. Both the comm core and recovery call it
  with the view they act on. A hello service built without it says nothing of security. The
  hello service skips a program's fact under either name, and the broker refuses to let a
  program declare `hello.security` or `hello.security_generation`, as it does for
  `hello.state`.
- `RecoveryComm::start` takes the record as read, not just its switch.
- Client: `orion::node::Node::security()` returns `orion::node::Security`, which is
  `#[non_exhaustive]`: `NotTold`, `On { generation }`, `Off { generation }` or `Damaged`.
  `NotTold` also covers a word this build does not know.

## Proved by

- `hello/tests/hello.rs`, `the_document_says_the_boards_security_switch_as_its_record_has_it`:
  records on/7, off/2, none and damaged give exactly the expected facts, signed. The reserved
  names test lists all four of the node's own facts.
- `comm-app/tests/recovery.rs`: a good start on a record that says on/1 reads
  `Security::On { generation: Some(1) }` through the client, and so does recovery after the
  settings break.
- `orion` unit test `the_security_switch_is_read_from_the_boards_facts`, including `NotTold`
  for an older board and for an unknown word.
- Mutations:
  - caught: the comm core's call, recovery's call, the damaged word, the generation fact, the
    client's `on` and its generation;
  - removing a reserved name fails to compile, because the hello test compares the full array.
- The gate passed.

## Different from the brief

- The brief asked for an appended field. The mode is two of the node's own facts instead, for
  the reason above: it keeps the signature last and is just as absent from an older node.
