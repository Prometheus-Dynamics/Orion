## Ruling

armv7 and riscv64 have never run on a board. Their size builds come out of the every-change
gate and run on the release path only. The x86_64 and aarch64 size checks stay on every change.
One command runs all four on demand.

## Built

- `scripts/size-gate.sh`: each board has a column saying when it is gated: aarch64 on `every`
  change, armv7 and riscv64 before a `release`. Without `--release`, the two print `before a
  release only (scripts/size-gate.sh --release)`.
- `scripts/size-gate.sh --release` builds and measures every target: x86_64 (three files),
  aarch64, armv7 and riscv64 (two each). Nothing is reused, and it fails on any file over its
  budget. A target this machine cannot build fails the run instead of being skipped.
- `docs/release.md` (new): the release checklist. There was no release workflow and no
  checklist. A release passes the gate and `scripts/size-gate.sh --release`; the checklist
  lists the Rust targets and C compiler that needs.
- `scripts/gate.sh`: the size gate's slowest green time is now 610 s, from CI. CI never built a
  board target (its runner has no musl targets), so this ruling does not change what CI
  measures. The earlier 1,341 s was a cold run on this machine before I24, with all nine builds.
  Its bound is 1,830 s.

## Proof

- After a core change, the size gate builds 5 files, not 9, and names the two left for a
  release.
- `--release`: exit 0, 9 files measured.
- `--release` with armv7's budget planted at 2,000,000 and riscv64 renamed to a target nobody
  has: exit 1. The rename fails with `cannot be built here, and a release measures it`, and
  armv7 `is 2682016 bytes, over its limit of 2000000`. The every-change gate passes with the same
  plant, as it should now.
- Cold, in a fresh target directory, the new set: 5 files, 203 s wall, 1,558 CPU-s.
