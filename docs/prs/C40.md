## Build

The WebSocket, SSH and NT4 ways in are the same class as `peer.listen`: an address that is taken,
or not on the board yet, is not a comm core that cannot start. Give them the same capped retry
(5 s, then 10 s, one warning, a line when it opens, the rest of the comm core running). Errors
that waiting does not clear still mean recovery. Update the lock page's known limits and add
codes 18 and 19 to it.

With it, three follow-ups to J11: a fixture that hands the client rings it cannot read, a clock
test that holds on a loaded machine, and a resource listing that tells an empty description
from a broken one.

## Built

- **`orion-server`:** `Retry` (5 s, then 10 s), `open_retrying(way, at, retry, open)` (one
  warning when it cannot open, an info line when it does), and `may_clear(&io::Error)`. These
  errors may clear by themselves: address in use, address not available, permission denied (a
  port that needs a capability), and `ENODEV` (an interface not there yet). Anything else is
  settings that cannot work. `orion_tcp::Retry` is the same type, and the network way in uses
  the helper.
- **`orion_ws::WsListener::opening(addr, options, retry)`:** a listener whose socket opens when it
  runs. Its subprotocols are said and its carrier made at once, as on one that is open, so NT4
  on the WebSocket is wired the same either way.
- **The comm core** (`ways.rs`): `now_or_later` starts a way in once. If it cannot open yet, the
  start goes on, and a task tries again and keeps what it opens for as long as the comm core
  runs. For SSH (sandboxed or not; the sandbox's own fallback is kept) and NT4. The WebSocket way
  in uses `opening` and is announced at the address it was given. The network way in now retries
  only errors that may clear, as the others do.
- **The NT4 gateway** passes the socket's own error up (it was `io::Error::other`), so a taken
  port can be told from a mapping that cannot work.
- `CommSettings::peer_retry` is `listen_retry`, for every way in.
- `docs/comm.md`: the recovery list, the network carrier and the start's errors.
- `docs/lock.md`:
  - codes 18 and 19, reachable only through level-1 `DetachedRun`;
  - the known limit about the ways in, removed;
  - a "Since the lock revision" section with J11 and C40, both additive.

### J11's follow-ups

- **Rings the client cannot read, in the tree.**
  - `topics/tests/old_rings.rs`: a comm core of one stub service hands out rings made by this
    build with word 1 (the layout) set to 1, as a comm core built before `ad5bf930` does. A
    declaration gets `Layout("a publisher's ring", 1, 2)` and a subscription
    `Layout("a subscriber's ring", 1, 2)`. A subscription with no ring shared and a declaration
    no ring can have gets `Memory("a subscriber's ring of its own", ..)` with the ring's words.
  - `buffers/tests/old_pool.rs`: a pool page that is not a pool page of this build gets
    `Memory("a buffer pool", "not a ring: not a pool page")`. A pool page has no layout word in
    this device library (only a magic), so `Memory` is what that site can say.
- **The clock test** (`sample_times_arrive_in_this_boards_time`).
  - It no longer sleeps 300 ms and allows 20 ms. It publishes until a sample arrives moved,
    which shows the clocks were compared.
  - Then it asserts what the comparison guarantees: the offset is wrong by at most half its
    round trip, and that round trip fell between the test's start and that sample. So
    |moved − 5 s| ≤ (stamped − began) / 2: the bound grows with whatever a loaded machine did.
  - It also asserts that the bound is narrower than the 5 s being measured, so it still tells a
    compared clock from a wall clock.
- **The resource listing.**
  - `Found::broken` is `Some("description does not decode: <why>")` when a provider's
    description does not decode. It is `None` for no description and for one that reads.
  - `orion ctl resource list` and `resource show` print it.

## Proved by

- `ws/tests/opening.rs`: on a taken address the listener is refused at once
  (`AddrInUse`, `may_clear`). `opening` takes a carrier before it opens, is still trying after
  several waits, and once the holder goes a hello over it is welcomed.
- `comm-app/tests/ways.rs`.
  - With `ws.listen`, `ssh.listen` and `nt4.listen` all on taken addresses, the comm core starts,
    serves its socket, and announces the WebSocket address. Once the holders go, each address
    answers as its way in: an HTTP refusal of a non-upgrade, an SSH banner, NT4's HTTP answer.
  - An NT4 mapping onto `orion.host` still fails the start with `nt4.listen`.
- `recovery.rs`: the start that fails after the socket is served is now `nt4.listen = ws` with
  no `ws.listen`, and it still ends in recovery with the socket.
- `orion-server` unit test: what `may_clear` takes and refuses.
- The fixtures and provider test above. The clock test passes 12 at once on 4 cores.
- Mutations, 18 of 18 caught:
  - `may_clear`'s kinds and `ENODEV`;
  - the later guard, both ways;
  - the task keeping its server;
  - the WebSocket's fallback, its announced address and its bind;
  - the network way in's guard;
  - the NT4 error kind;
  - each of the four J11 sites;
  - the provider's words, and its empty case;
  - the clock offset off by 100 ms, and never compared.

## Different from the brief

- `CommCore::ssh_addr()` and `CommCore::nt4()` are `None` for a way in that did not open at start,
  even after it opens. The task holds it.
- The NT4-on-WebSocket handover is not tried again separately: the gateway in that mode does not
  listen, so it never waits.
- An SSH host key that cannot be read for want of permission is retried with a warning, as a
  port that needs a capability is, rather than meaning recovery.
