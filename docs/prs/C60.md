# C60: The stub and the node share the action list

- **Status:** done
- **Group:** C (client)
- **Wave:** 19
- **Needs:** C53b

## Why

The stub board answered action runs with a router of its own: a copy that kept to what the
briefs said of node logic. A copy drifts. It ran detached runs with no deadline, which the node
refuses. Its run handles could not show what the node does when a caller's numbers come round
again in a new session, or when node logic starts again. Tests that pass against a stand-in
and fail on a board are worse than none.

## Changes

- `orion_stubs::router::Router` is now an adapter. It builds node logic's `Asked` from each
  request, hands it to `orion_action_list::Actions`, and sends what the list says back through
  the comm core's sessions. It keeps no rules of its own. Its two jobs:
  - It holds the registrations still standing, so a restart can hand them over again, as the
    comm core does when node logic comes back.
  - It applies the run policy each registration asked for (`KNOWN` until one is registered, as
    the relay does).
- The router's deadlines tick every 10 ms on the board's thread, not only when a frame comes.
- `Board::restart_node_logic()` gives node logic a new start, with a new instance and nothing
  running. Standing registrations are handed over again. It returns the new instance.
  `Board::node_logic_instance()` reads the current one.
- The client's action tests use the stub router, not a copy of it in the test file.
- `actions.rs`: detached runs now give a deadline, as the node requires.
- The rule, in `docs/testing.md`: the stub and the node share the action list.

## Proved by

`crates/client/actions/tests/handles.rs`:

- `a_handle_from_a_lost_session_follows_its_own_run_never_the_new_one_under_its_number`:
  - A detached run starts in a session that is then lost.
  - The same caller starts a new run in a new session, under the same number.
  - Attaching by the old handle gets the old run's ending, and the new run is untouched.
- `a_handle_from_before_node_logic_started_again_is_told_the_run_is_gone`:
  - After `restart_node_logic`, the old handle is refused with `RunGone`.
  - The action stays listed.
  - A new run's handle carries the new instance.
- `a_cancel_by_a_handle_that_names_nothing_now_is_refused_and_the_newer_run_goes_on`:
  - The old run's kept ending is handed out once, by its own handle.
  - After that, an attach and a cancel by that handle are refused with `NotFound`.
  - A barrier run reaches the owner before any cancel could. The newer run under the same number
    finishes as it was told.

`crates/testing/stubs/tests/one_list.rs`, `nothing_answers_action_runs_but_node_logics_own_list`:

- Every `.rs` file under `crates/` and `examples/` is scanned. Only the relay and the stub's
  router may be a `Service` that names `ACTION_RUN`.
- The stub's router uses `orion_action_list::{Actions` and builds none of the list's messages
  itself.

Mutations, each killed:

- The restart keeps the old list: the restart test fails.
- The restart does not hand the registrations over again: the restart test fails.
- `attach_handle` sends the number alone: all three handle tests fail.
- A new file with a `Service` of its own that names `ACTION_RUN`: `one_list` fails.
- The router builds a `Claim` itself: `one_list` fails.
