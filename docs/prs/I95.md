Read `AGENTS.md` and `docs/design.md` first.

## Why

I94 showed there is no `unwrap` and no `expect` that a peer's input can reach in the comm core
or node logic. That leaves the other way a handler panics on input: `a[i]` and `a[i..j]` on
bytes or counts a peer chose. Nothing has been read for it.

A panic there is contained: the request's session is dropped, the rest go on, and
`orion/state` counts it (`panics contained`). So this is hardening, not a hole.
