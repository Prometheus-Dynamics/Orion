# I52: A fetch whose giver or comm core goes ends within a second, by test

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I50

Read `AGENTS.md` and `docs/design.md` first.

## Changes

`crates/comm/file-offers/tests/fetch.rs`, `docs/lock.md`, `TODO.md`. Tests only.

## Why

A program serving files through `Files::offer` asked what its clients get when the giving side
fails mid-gift, and when. Two of the four cases had tests with no time in them:

- the giving program dies (no drop runs): the fetch ends `Rejected`, "the program that offers it
  went";
- the comm core goes: the fetch's step fails with an error whose `is_lost()` is true.

Each must come at once, not at the client's silence limit (5 s by default).

## Built

- `a_fetch_whose_program_goes_is_rejected_to_its_client` now holds the end to under 1 s from the
  cut, checked as it waits.
- `a_fetch_whose_comm_core_goes_ends_as_a_lost_session_at_once` (new): a gift under way, the comm
  core stopped. The client's fetch fails, `is_lost()`, in under 1 s, and never ends as a transfer.
  Seen: about 0.6 ms, through whichever of three signals comes first (the socket's end, a reset
  read, a broken-pipe write).

## Proof

Each mutant fails its test, 3 runs of 3:

| Mutant | Test | Fails with |
|---|---|---|
| The comm core does not tell a client its program went | program goes | `not told after 1.0s` |
| The client hears none of the socket's end, a reset read or a broken-pipe write | comm core goes | `the fetch never saw its session go` (10 s) |
| A connection error is not counted as lost (`is_lost` only for `Lost`) | comm core goes | `Connection reset by peer`, or `Broken pipe`, not lost |

Hearing only one of the three signals is not enough to fail the second test: each of the other
two reports the loss in under a millisecond.
