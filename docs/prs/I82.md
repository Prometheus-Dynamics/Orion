## Why

The third part of the clock row. A board with no clock battery starts in 1970, or at its last
saved time, and gets the real time later: the clock steps forward by hours or years while the
board is running. Two things followed.

- **What node logic keeps on the wall clock went wrong at the step.** A lease that ends at a
  time ended at once. A peer last agreed with a moment ago looked days gone, and stale.
- **One wrong source could move a clock that was right.** After the first synchronization, two
  samples from the same source were enough to step the clock forward by any amount.

## Built

- **Seeing the step** (`node-app` `clock.rs`). Node logic compares the wall clock less the
  monotonic one with what it last saw. The kernel slews both alike, so only a step changes
  it. A change of 200 ms or more is a step; the time sync steps only what is over 400 ms.
  Smaller changes are kept against the same starting point, so they cannot add up unseen. It
  is looked at before every request and every turn, which is before anything reads the wall
  clock.
- **Leases.** Each lease with an end that this node wrote is written again with its end moved
  by the step (`orion_resources::shift_leases`). A lease another node wrote is left: that node
  moves it, and two nodes moving one lease would move it twice. A lease with no end has
  nothing to move.
- **Peer sync.** When a peer was last agreed with, when everything was last sent, and when it
  may be sent again all move by the step (`Sync::clock_stepped`).
- **A far step needs a second word** (`orion-time`). Once synchronized, a step forward of over
  an hour is made only when a second, different source agrees within 0.1 s, or the source is
  an operator's clock. The source that said it is left out of the next round, so the next in
  rank is heard; the round after asks them all again. With no other source agreeing, nothing
  is stepped, and `orion.time` says so: `<source> says the clock is over an hour behind, and no
  other source agrees (...): not stepped without a second source or an operator`.
- **The first step after start is free**, as before: two samples that agree, from any one
  source.

## Not as the design said

The design named a timer the kernel cancels when the clock is set (`TFD_TIMER_CANCEL_ON_SET`).
I compare the two clocks at the start of each request and turn instead. It gives the same
guarantee, that nothing is decided on a stepped clock with times not yet moved, because those
are the only places node logic reads the wall clock. It adds no descriptor to node logic's
loop and needs no new system call. What it does not do is wake node logic at the moment of the
step: an idle node logic moves its times at its next request or deadline, which is when it
would first use them.

## Size

No limit is raised here: I88 raised the board's `orion` limit for the whole clock row.

## Tests

- `orion-time`:
  - `once_synchronized_a_step_of_over_an_hour_needs_a_second_source_or_an_operator`: the rule
    itself, with the first step free, the same source twice moving nothing, a disagreeing
    second source moving nothing, an agreeing one stepping, an operator believed alone, and
    50 minutes needing one source.
  - `once_synchronized_a_far_step_waits_for_a_second_source_and_one_alone_never_steps`, on real
    sockets: one source alone never steps and the status says why; with two, the first is left
    out, the second is asked, and the clock steps on its word.
- `orion-resources`
  `when_the_clock_is_stepped_a_lease_this_node_wrote_lasts_as_long_as_it_was_given`: a
  ten-second lease taken in 1970 still has nine seconds after the clock steps to today, and
  would have had none; a lease with no end and one another node wrote are not moved.
- `orion-sync` `a_clock_stepped_by_days_makes_no_peer_stale`: stale without the move, not with
  it.
- `orion-node-app` `clock::a_step_is_seen_once_and_two_clocks_read_apart_are_not_one`.

Nine mutants each failed 3 of 3 runs: the same source counted as a second; the rule applied
before the first synchronization; an operator not believed alone; the lone source never left
out; the left-out source asked anyway; another node's lease moved; a lease's end not moved;
sync's times not moved; and every small change taken for a step.

**Not covered end to end:** node logic's own call (`Logic::clock_step`, which joins the three)
is not run by a test, because a test cannot step the machine's clock. Each piece it calls is
tested. It is for a board: take a lease with an end before the board has the time, give it the
time, and see the lease still held.
