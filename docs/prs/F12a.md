## Build

Tools that reach a board from a laptop run on Windows and macOS as well as Linux. The client was
Linux-only throughout. Agreed design:

- The session core builds on every system. TCP and a link in two halves work everywhere.
- Topics are messages-only off Linux, with a subscriber's own ring on the heap.
- The facade gates per feature, not as a whole.
- The gate runs check and clippy for Windows and macOS. A CI job on hosted Windows and macOS
  runners is the authority.
- Shutdown contract for a link in two halves: the session holds only the write half, and
  dropping it is the application's signal. The reading thread is detached, never joined. Late
  bytes are thrown away.

It waited on the shm crates' new rev, which makes the ring, the sample time and the time lookup build
off Linux.

## Built

- **Pins.** All eight `shm-*` crates are at the shm repository's `d1a8939a4f428575e20797e8c5eebee8de7a7942`.
  `shm/` there is identical to the P1s commit `315c9c8`, and it does not change again before L1.
  No local patch.
- **`orion-identity`:** the 0640 key file mode is set on unix only.
- **`orion-connect`:**
  - `fd.rs`: `BorrowedFd` and `OwnedFd` are std's on unix and uninhabited elsewhere, because
    no descriptor travels off Linux.
  - `piped.rs`: the `LinkRead` and `LinkWrite` traits, and the reading thread with its channel.
    On Linux the thread also rings a pipe, so `as_fd` still works. TCP off Linux goes the same
    way.
  - `Session::over(read, write, expect, name, options)` and `reconnect_over(read, write)`.
  - `as_fd`, `AsFd` and `next_async` are Linux-only. Off Linux, the board's socket and serial
    addresses fail with an I/O error of kind `Unsupported`.
  - `shm-fdpass` and `rustix` are Linux-only dependencies.
- **`orion-topics`:**
  - The crate builds everywhere. `adopt` and the doorbell are Linux-only, and `rustix` and
    `shm-ring-doorbell` move to Linux-only dependencies.
  - New `mirror.rs`: a subscriber's own ring is a memfd ring on Linux, as before, and an
    `Arc<Heap>` ring elsewhere, formatted with `format` and read and written with `over`.
  - `RingReader` names what a subscriber reads, on either system.
  - Off Linux, `wait` pumps the session, since samples arrive as messages.
  - Descriptor plumbing (marks, a ring handed back) goes through small `copy`, `lend` and
    `keep` helpers that cannot be reached off unix.
- **The `orion` facade:**
  - The crate-wide Linux gate is gone.
  - `buffers` is `all(feature = "buffers", target_os = "linux")`, and `adopt` and
    `topics::Ring` are Linux-only. `topics::RingReader` is exported.
  - The crate docs say what is Linux's.
- **`orion-ctl` and `orion-capi`:** both libraries build everywhere. Their crate-wide gates are
  gone.
- **Tests and dev-dependencies:** every client crate's dev-dependencies are Linux-only, and its
  integration tests (which start a comm core) are gated on Linux. Unit tests run everywhere.
  The `roles` example starts its own comm core on Linux, and does nothing elsewhere.
- **Gate:** clippy over the ten client crates, all features and all targets, for
  `x86_64-pc-windows-msvc`, `x86_64-pc-windows-gnu`, `x86_64-apple-darwin` and
  `aarch64-apple-darwin`. `rust-toolchain.toml` lists the four targets, so CI installs them.
- **CI:** a `client` job on `windows-latest` and `macos-latest` builds the ten client crates
  and runs their tests.
- **Docs:** `docs/client.md` covers `Session::over`, the shutdown contract, and what each system
  has.

## Proved by

- The gate's four cross-clippy steps, clean.
- `orion-connect`, `a_link_the_program_opened_in_two_halves_carries_the_same_calls`, over a pty
  link:
  - plain, the whole `exercise` (500 requests with no allocation, the frame limit, identity);
  - signed with the board's key expected, the same, in a frame 32 bytes shorter;
  - another key expected: `OtherKey` with both keys;
  - a key expected with none to sign with: `Denied`.
- `orion-topics`, `mirror::tests::a_ring_on_the_heap_is_read_as_it_was_written`: the
  heap ring, built on Linux too. Samples come back in order, `latest` and `at_or_before` work,
  and samples outside the shape are refused.
- On Linux: the client suites ran twice, clean, and the ring, buffer and adopt tests ran on the
  new rev three times, clean.
- Not vacuous:
  - with `expect` ignored in `Session::over`, the halves test fails;
  - with the heap reader on other memory, the mirror test fails;
  - with the mirror not written, the outbound network tests fail (`orion-topics`' own tests do
    not cover a network subscriber; `orion-outbound`'s do).
- Not yet run: the CI `client` job on the hosted runners. Its first run is on this push.

## Different from the plan

- `orion-ctl` and `orion-capi` were planned for later, but both libraries built portably once
  the facade did, so they are portable now. No standalone `orion` command-line binary is built
  off Linux yet: the one binary is the node's.
- `reconnect_over` has no test. A test would need a second set of halves on the same link, and
  the first reading thread, which the test cannot end without closing the link, would take its
  bytes. Its code is `over`'s plus the counters.
- B9 needs no board rerun. Between the two revs, publish and read are unchanged apart from types
  and cfgs. The doorbell wait reads the clock once more per poll, and a pool view matches once
  more on byte access. Neither is measurable against 18 µs a frame.
