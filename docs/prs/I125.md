# I125: Tests reused by their binaries keep their test listing

**Status:** done

**Group:** I. Finish

**Wave:** 19

**Needs:** I124

Read `AGENTS.md` and `docs/design.md` first.

## Why

On ecfd4354 the gate went red at "test filters" in three runs of `scripts/measure-change.sh`
(a comment, an unused function, and a used string in `orion-types`), all with:

    lane-reuse.py: orion-action-list was reused, but its tests were never listed: run with GATE_LANE_REUSE=0

The step's listing kept each package's tests under the key it ran with, and looked a reused
package up under its source key. I121 reuses a package by its binary key after the build. A
change that moves the source key and leaves the binaries the same is that case exactly: no
listing was ever kept under the new source key, nor under any binary key. The I124 gate and CI
never reused a package this way, so they did not reach it.

## Changes

- **Each listing is kept under both keys:** the package's source key and, when it has one, its
  binary key. The same binary bytes hold the same tests.
- **A reused package is looked up by its binary key first,** then by its source key.
- **A reused package with neither kept is listed now** (`cargo nextest list` of it). It is never
  skipped, and never filled from a listing of other binaries.

## Proved by

- A new case in the plan self-test: the same binaries reused after the source key moved must
  yield a listing. Red on ecfd4354 with the gate's own message.
- A second case: with no listing kept under either key, the package is listed now, and the
  listing is kept under its binary key.
- Mutants, 3 runs each, all red:
  - looked up by the source key only;
  - kept under the source key only;
  - a package with no listing skipped, not listed.
