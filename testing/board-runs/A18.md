# A18: What dev's orion-node memory actually is

All numbers are from a CM5 (Raze #2, image dev.993, 4 GB, the real services and
the real graph workload running). `dev` is at 7012e8d.

## How it was measured

- **Who asked for what:** `dev`'s `orion-node` with the `dhat` allocator profiler
  added, with the image's features (`peer-tcp`, `discovery-mdns`, `systemd-notify`,
  `time-sync`). It replaced the service for 180 s through a runtime-only drop-in,
  and the profile was taken while it was still running, so "live" means live at
  steady state. The patch was never committed. The real service was restored after.
- **Where the bytes sit:** `/proc/<pid>/smaps` of the real, unprofiled service,
  sampled once a minute from a restart.
- **What the big regions hold:** the bytes of the region, read from
  `/proc/<pid>/mem` and classified.

The profiled build is musl-linked, because requested sizes don't depend on the
allocator. Its own RSS (88 MB) is the profiler's bookkeeping and is not used.

## The plateau

Memory stops growing about 8 minutes after start, at the size the 12-hour-old
node had:

| | 10 s to 2 min | 8+ min | 12 h |
|---|---|---|---|
| Heap (kB) | 2260 | 3156 | 3360 |
| Other anonymous (kB) | about 900 | 1344 | 1348 |
| VmRSS (kB) | 7800 | 9132 | 9404 |

## The 1.35 MB of other anonymous memory

| What | kB | Evidence |
|---|---|---|
| Thread stacks, nine threads | 712 | Six Tokio workers touch about 70 kB each, the three helper threads 12 kB each. One region also holds an adjacent 252 kB block that wasn't separately identified. Main's stack is counted under static and stack. |
| Sample history rings | 408 | Six rings of 4096 samples at 16 bytes each. `VecDeque` doubles, so each one crosses `MALLOC_MMAP_THRESHOLD_` and gets its own mapping. Region bytes are exactly 4096 `(u64, f64)` pairs. |
| The graph, as JSON | 168 | Two copies of one 85,028-byte `daedalus.graph` string, 84 kB each. Found by content. |
| Small mappings | 56 | |

This is why the region grows after start: the rings only reach 4096 samples once
enough samples have arrived.

## The 3.4 MB of heap

At steady state the program has asked for 2,130,579 bytes in 5,502 blocks. Of
those, 595,196 are graph copies that live outside the heap, which leaves **1.5 MB
requested** inside a heap of 3.2 MB. Around **1.7 MB of the heap is not data**:
about 86 kB is allocator headers, the rest is free space held after short-lived
buffers. 60% of the heap's bytes are zero.

What the program had asked for at steady state:

| What | Bytes | Blocks | Why |
|---|---|---|---|
| Workload config, mostly the graph | 640,546 | 362 | Seven copies of the graph were alive at that moment: two kept, five in flight being cloned. |
| Control channel buffers | 558,272 | 22 | Each IPC connection has a Tokio channel of `ControlEnvelope`, allocated in blocks of 25,376 bytes (32 slots), mostly empty. |
| Async task state | 160,512 | 27 | Per-connection tasks: 9,088 and 2,560 bytes each. |
| State maps (B-tree nodes) | about 240,000 | about 150 | Records, status, resources. |
| Runtime, tracing, sample rings so far, other | about 530,000 | about 4,900 | |

Peak requested was 3,452,269 bytes, 1.3 MB above steady state. The difference is
config clones (767,191), rkyv serializer scratch (262,144) and encode buffers
(224,432).

## Churn

143,564,005 bytes in 247,504 allocations over the 180 s, startup included: about
1,375 allocations a second with nothing being asked of it.

| What | Bytes | Allocations |
|---|---|---|
| rkyv serializer scratch | 34,692,608 | 3,994 |
| Cloning the whole workload config tree (about twice a second) | 32,925,552 | 24,204 |
| Encoding control envelopes | 19,257,912 | 1,262 |
| Inventory archive buffers | 9,223,104 | 462 |
| Encoding observed cluster state | 8,275,232 | 66 |

Most allocations by count are small string and key copies:
48,648 `to_vec` on one host-action path, 32,571 cloning the resource tree.

## The targets, with reasons

| Target on `next` | Today | Where the difference comes from |
|---|---|---|
| Heap 1.4 MB | 3.2 MB | Encoding into a reused buffer ends the free space the transient buffers leave (1.7 MB). The graph is stored once. A client costs a small fixed slot, not 25 kB. |
| Other anonymous 0.3 MB | 1.34 MB | About four threads at about 70 kB each. The rings and the graph stop being anonymous allocations made on demand. |
| Static and stack 0.3 MB | about 0.3 MB | Already there. |
| Rings 0.5 MB | 0.41 MB inside "other" | Sample history is the same data, moved into fixed rings whose size comes from the declaration. No doubling. |
| Total 2.5 MB | 4.7 MB | |

The rules this gives the groups that follow:

1. **The graph exists once.** Nothing clones a workload's config to read a field.
2. **Nothing is cloned on a timer.** The reconcile and status paths read in place.
3. **A client costs a fixed slot.** No per-connection queue of the largest message.
4. **Encoding reuses a buffer.** Already true of the wire (A5, A12: no allocations).
5. **History rings are sized from the declaration**, at creation.
