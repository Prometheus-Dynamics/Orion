# H8: an STM32G4 on the CAN gateway

**Not run.** This file says why, and what a run needs, so it is not mistaken for a result.

## Why it was not run

There is no STM32G4 board on the bench: the run needs an STM32G431 board (a Nucleo-G431 or
any board with FDCAN1 on PA11/PA12), a CAN FD transceiver on it, a probe to flash it, and a
CAN FD interface on the board that runs the comm core.

## What a run is

1. Flash `examples/stm32g4-device` (`cargo build --release`, then `probe-rs run --chip
   STM32G431KBTx ...`), default features.
2. On the CM5, bring up the CAN interface at 500 kbit/s nominal and 2 Mbit/s data with FD on,
   and give the comm core the bus `can0=can0:0x100:0x180:1:fd`.
3. The device `can0.1` connects and declares `loop` and `stack`. Read `stack` with a client:
   one sample a second, `size` matching the build and `high_water` below it.
4. Subscribe to `loop`: samples every 100 ms while subscribed, none after the subscriber goes.
5. Pull the transceiver and put it back: the device reconnects in a new session and declares
   both topics again.
6. With `hw-crc`, repeat 3. Samples arriving at all is the proof the CRC unit agrees with the
   software CRC, since every frame carries it.

Record the board, the interface, `high_water` against the stack bound in `size-baseline.txt`,
and the loop count with and without a subscriber.
