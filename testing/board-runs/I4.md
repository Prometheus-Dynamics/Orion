# I4: The two services on the test board

Run on the test board (an aarch64 Cortex-A76 module, image dev.993), with the board lock held. `next` is at 8f427b1 plus this
PR.

The board's root filesystem is read-only and the board runs its own Orion service, which owns
`/run/orion`. So the units ran as runtime units under other names: `orion-i4-comm.service` and
`orion-i4-node.service` in `/run/systemd/system`, made from `packaging/systemd/*.service` by
changing only the names and paths (`/run/orion` to `/run/orion-i4`, `/var/lib/orion` to
`/var/lib/orion-i4`, the binary and settings file under `/run/orion-i4-bin`). Everything else
in the units ran as written. The settings were `orion.conf.example` with the socket and state
directory moved the same way. `orion` was built for `aarch64-unknown-linux-musl`, profile
`service`. The board already has the `orion` user, uid 901, in `dialout`.

## What was seen

- **Started when ready.** `systemctl start orion-i4-comm.service` returned after 40 to 50 ms,
  with the unit `active (running)` and its status line from the comm core: `serving
  /run/orion-i4/orion.sock (socket, topics, keys, ...)`. User root, group orion, watchdog 30 s.
- **The socket is the group's:** `srw-rw---- root orion /run/orion-i4/orion.sock`.
- **Node logic as `orion`.** `orion-i4-node.service` ran with uid 901, and the comm core let it
  in as node logic (`socket.node_uids = 901`): `orion node show` answered `node board`. Its
  state directory is `orion:orion 0750`, apart from the comm core's key (`root`, `0600`).
- **`kill -9` of the comm core.** systemd started it again (one restart). Node logic was not
  restarted (same pid, no restarts) and `orion node show` answered again within 200 ms.
- **A comm core that stops turning.** `kill -STOP` of the comm core: after 30 s systemd logged
  `Watchdog timeout (limit 30s)!`, killed it and started a new one (33 s from the stop to a new
  pid).
- **Memory:** comm core 3,844 kB resident, node logic 3,664 kB, idle.
- The board's own Orion service stayed active with no restarts. The runtime units, the binary
  and `/var/lib/orion-i4` were removed afterwards.

## Not run here

`systemd-analyze` is not on the board; the units were checked with it on the build machine
(`scripts/packaging-check.sh`). The preset and the sysusers file were not applied on the board:
its root is read-only and the user already exists.
