# I6: Memory under the full setup, on the test board

Run on the test board (an aarch64 Cortex-A76 module, image dev.993, kernel 7.2.9 with 16 KiB pages), with the board lock
held. `next` is at edeab78 plus this PR. `orion` and `orion-drill` were built for
`aarch64-unknown-linux-musl`, profile `service`, and run from `/run/orion-i6`; everything was
removed afterwards and the board's own Orion service was not touched.

## The setup

`testing/board-runs/I6-setup.sh`, run on the board:

- the comm core, with SSH, peers and the WebSocket listening, and node logic, each its own
  process of the one binary;
- around them, each its own process of `orion-drill`: the sample executor, a provider of
  three actions, a publisher counting at 1 kHz, two subscribers of it, a camera of 4 KiB
  frames at 100 a second and two viewers of them;
- five workloads running under the executor, eight more topics each held by a publisher, and
  one action run through the provider;
- then ten seconds of all of it running, with the reference bits of the comm core and node
  logic cleared at the start (`/proc/PID/clear_refs`), and `scripts/memory-report.sh`.

`scripts/memory-report.sh` splits each process's proportional set size (Pss) the way the
budget does: **code** (executable mappings of a file), **rings** (memfd shared memory: topic
rings, frame pools, marks) and **data** (everything else: heap, stacks, static data,
read-only data). Pss counts a page shared by two processes half in each, so the comm core and
node logic, which map the same file, are counted once together. **Used** is the part of code
touched in the ten seconds (`Referenced`, shared out the same way).

## What was measured

In KiB, the fourth run (the first three are below):

| | Code mapped | Code used | Rings | Data | Threads |
| --- | --- | --- | --- | --- | --- |
| Comm core | 1,513 | 988 | 32 | 1,035 | 1 |
| Node logic | 1,353 | 357 | 10 | 627 | 2 |
| **Both** | **2,866** | **1,345** | **42** | **1,662** | **3** |
| Budget | | 2,048 | | 2,560 | |

- **Data: 1.66 MB, within 2.5 MB.** Rings are 42 KiB more, shared with the programs that use
  them; in the budget's words that is data too, and the sum is 1.70 MB.
- **Code in use: 1.35 MB, within 2 MB.** The code that ran while the board did its work.
- **Code mapped: 2.87 MB, over 2 MB.** This is almost all of the binary's text (3.06 MB, of
  a 5.03 MB file): the kernel maps 64 KiB around each page fault
  (`/sys/kernel/debug/fault_around_bytes`), and with 16 KiB pages, so what one call touches
  brings its neighbours along. Those pages are page cache, shared with every other process
  of the file and given back under pressure; they are not the board's memory the way data
  is. Run 3 cleared nothing and saw `Referenced` equal to mapped: on this kernel a page
  mapped around a fault counts as referenced, so only clearing the bits shows what is used.

The design's table had 2.84 MB of code resident on dev: the same measure as code mapped here.

The programs around Orion, for scale (KiB, code mapped / data): executor 331 / 107, provider
255 / 238, publisher 94 / 102, each subscriber 103 / 106, camera 176 / 118, each viewer
191 / 114.

## The earlier runs

- **Run 1** counted the command line's processes (eight `orion` publishers holding topics)
  among those sharing `orion`'s text, which made the comm core and node logic's share of code
  look smaller: 1,408 KiB. It also left the comm core and node logic running when it ended
  (the script lost their process ids in a subshell); they were killed by id. Runs 2 to 4 use
  `orion-drill` for the command line and keep the ids.
- **Run 2**: code 2,866, rings 42, data 1,654.
- **Run 3** added the used column without clearing the reference bits: used equalled mapped.

## Binary size

`scripts/size-gate.sh`, in the gate, builds each form on its own, profile `service`:

| File | x86_64 gnu | aarch64 musl (static) |
| --- | --- | --- |
| `orion-recovery` | 2,973,432 | 2,634,312 |
| `orion` | 5,936,216 | 5,032,768 |
| `liborion_c.so` | 670,696 | |

Each limit is that and a tenth more. The aarch64 files are gated where the target and a C
compiler for it are installed, and checked to be static.

Where the board's text goes (`cargo bloat --crates`, aarch64): the standard library 602 KiB,
unattributed 301 KiB, rustls 197, russh 169, the NT4 crate 162, the comm core's app 146,
ssh-key 102, ring 92, node logic 88, tokio 85, ureq 84, then 160 crates below 60 KiB each.
