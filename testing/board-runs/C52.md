# C52 and C52b: who holds what, on the test board

Run on the test board (an aarch64 Cortex-A76 module, the image's BusyBox and systemd), holding
the board locks. The script was rehearsed end to end on a PC first, each time: the same binary
under qemu-user, only the board's BusyBox applets on `PATH`, and the same `systemd-run`
invocations as user units. It is `testing/board-runs/C52-run.sh`.

- Everything ran from `/run/c52`, in transient units (`c52-login`, `c52-comm`; `--collect`,
  `RuntimeMaxSec=600`), the way the shipped units run them.
- No service, module or slot of the board was touched, and the watchdog stayed armed.
- After each run, `/run/c52` and the units were gone. The running services, failed units and
  loaded modules were the same before and after.
- The image has no `orion-comm` account (902). systemd starts a unit only as an account it
  can find, so the comm core ran as `daemon` (1) and the children as `bin` (2): accounts
  that exist and run nothing.
- The board's clock was a week behind the host's.

## C52 (a13d4030), the bounded helper

Two earlier tries failed, and the script now preflights both:

- The first, as uid 902, was refused by systemd with `217/USER`.
- In the second, the comm core could not make its socket in a root-owned directory and went
  into recovery.

The third ran:

| Process | uid | CapEff | CapBnd | NoNewPrivs | RSS |
| --- | --- | --- | --- | --- | --- |
| Helper | 0 | `e1` | `e1` | 0 | 3.0 MB idle, 3.5 MB with a session |
| Comm core | 1 | `2000400` (and ambient) | `2000400` | 1 | 3.9 MB |
| Connection's child | 2 | 0 | `e1` | 1 | 3.8 MB |
| Root login | 0 | `e1` | `e1` | 0 | 1.7 MB |

`e1` is CHOWN, KILL, SETGID and SETUID: a root login held only those. That was a regression
from before C52, when a root login was all of root, and C52b fixes it.

## C52b (5213e0b)

The binary was 5,213,424 bytes. The run took 17 s on the board's clock.

| Process | uid | CapPrm, CapEff | CapBnd | NoNewPrivs | RSS |
| --- | --- | --- | --- | --- | --- |
| Helper | 0 | full | full | 0 | 3.1 MB idle, 3.6 MB with a session |
| Comm core | 1 | `2000400` (and ambient) | `2000400` | 1 | 4.0 MB |
| Connection's child (`ssh-connection --become 2:2`) | 2 | 0 | 0 | 1 | 4.0 MB |
| Root login | 0 | `1ffffffffff` | `1ffffffffff` | 0 | 1.6 MB |

A login as an account that is not root was not tried on the board: the image has no account
with a uid of 1000 or more and a shell. The PC test
`each_kind_of_session_holds_what_it_should_and_no_more` covers it: uid 1000, CapPrm and CapEff 0.
